## 术语与对象关系

| 术语 | 含义与边界 |
| --- | --- |
| 用户 | 私有资料和业务资源的所属账号；显示名称与登录用户名分开 |
| 尺寸记录 | 一次保存的完整尺寸历史；当前尺寸是可切换、可清空的引用 |
| 文件资产 | 图片内容及其存储、核验与清理信息；不同于照片库或衣橱记录 |
| 个人照片 | 用户主动保存到照片库的记录；临时上传可以不加入照片库 |
| 穿戴单品（dress） | 一件衣服、鞋、帽子、包或饰品；文中“衣物”泛指穿戴单品，每件至少一张图片，可包含正面、背面与细节，排序第一张为封面 |
| 设计任务 | 一次独立设计提交及其后台处理过程，保存当次输入快照 |
| 模型调用 | 任务中一次规划或生图的外部调用；外部结果与本地保存状态分开判断 |
| 设计方案 | 任务产出的文字方案和效果图；仅文字成功不属于完整设计成功 |
| 收藏 | 用户对自己完整成功方案的整理关系，可不属于任何收藏夹 |
| 收藏夹 | 用户命名的收藏分组；同一收藏可以属于多个收藏夹 |

用户拥有尺寸历史、照片、衣物、设计和收藏。任务通过独立文件引用保留图片，通过快照保留尺寸和衣物文字；源记录变化不追溯修改旧任务。重试创建新任务并关联来源，完整成功的方案才允许建立收藏。收藏归属与方案生命周期分别维护。

## 账号与个人资料

- 用户名和密码注册、登录；是否开放注册通过部署配置控制。用户名为 4～32 位英文字母、数字或下划线，忽略大小写且全局唯一；中文显示名称独立设置，不参与登录。
- 注册成功后进入登录页，不自动登录。注册只填写用户名、密码和确认密码，显示名称留到个人资料设置；密码为 8～64 个 Unicode 码点，允许空格，不强制字符组合，不裁剪首尾空格。
- 登录失败限制、IP 请求额度及页面行为见 [登录注册需求](../02-需求文档/2026-10-20-登录注册/01-需求说明.md#失败限制与会话体验已确认)，2026-10-20 已确认并实现。
- 用户只访问和管理自己的资料、照片、衣物、设计及收藏。
- 多设备修改资料或收藏夹名称时，过期版本不能覆盖新值；前端保留输入并提示刷新比较。
- 登录后可校验原密码并修改密码，新密码不能与原密码相同。修改成功后所有设备需重新登录：当前会话立即结束，其余旧会话在下次请求时失效。规则与验证见 [修改密码](../02-需求文档/2026-10-21-修改密码/01-需求说明.md)。
- 暂不提供手机号、第三方登录和找回密码。
- 允许多设备登录，退出仅结束当前会话；空闲 2 小时或登录满 7 天后重新认证。页面轮询可延长空闲期限，不能突破 7 天上限。首版不提供“记住我”和设备管理页面。
- 身体尺寸包含基础身高体重、颈胸腰腹臀围、肩背、手臂、前后腰节长、腿部、头围及左右脚长脚宽，共 27 项，全部选填。体重使用 kg，其余使用 cm；仅脚部区分左右。详细字段见 [数据库设计](04-数据库设计.md)。不增加实际测量时间、测量方式或测量备注。
- 每次保存尺寸新增一份完整记录，自动设为当前值；历史记录不原地修改，允许将历史记录重新设为当前值。允许删除尺寸记录，删除当前记录时清空当前值，不自动选择其他记录；旧任务中的尺寸快照保持不变，删除时提示。尺寸全部清空后保存时新增一份全空记录并设为当前值，表示当前不提供尺寸，新任务按无有效尺寸处理。
- 提交穿搭任务时默认使用当前尺寸，用户可以关闭；没有尺寸也能生成。任务保存实际使用的尺寸快照。

## 个人照片库

支持头像、全身照和其他参考图，可设置默认头像、默认全身照。发型设计预选默认头像，穿搭设计预选默认全身照，提交前允许更换。

图片存储于七牛云，客户端先向后端申请文件 ID 和上传授权，直接上传七牛，经后端核验后再保存或提交任务。支持 JPEG、PNG、WebP，单张最多 20 MB、2500 万像素；不接收 HEIC、SVG 或动图。后端校验真实图片内容、纠正方向并移除定位等元数据。用户可以临时上传，明确选择是否加入照片库。提交前展示本次使用的照片、衣物、尺寸和文字要求。

## 衣橱与分类

一条衣橱记录代表一件衣服、鞋、包或配饰，支持多张照片、名称、分类、颜色、季节和备注。DeepSeek 理解单品图片，识别款式、颜色和图案等特征，用户可以修改识别结果；首版不要求自动抠图。

采用系统固定的衣物类别，如上装、下装、连衣裙、外套、鞋、包、配饰；类别固定单选；季节支持春、夏、秋、冬多选，未选择表示不限季节；颜色使用自由文本。照片、名称和类别必填，颜色、季节和备注选填。首版不做多级分类或衣物自定义分组。

穿搭设计由系统从用户实际拥有的衣橱单品中自动挑选搭配，用户可指定必须使用的单品。未指定单品表示自动选衣，不表示自由生成衣橱之外的服饰。首版使用已有单品；仅未选用衣橱鞋子时允许效果图补充示意鞋，并明确标注非衣橱单品，其他服饰不补造。缺少合适单品时明确提示。衣物图片作为参考，款式细节的保留效果待实际模型验证，不承诺精确试穿。

## 设计与任务

形象设计采用统一入口，允许选择整体设计、只改发型或只改穿搭。整体设计在同一次任务中规划发型与穿搭，产出一份包含两部分说明的方案和一张整体效果图；单项模式只设计对应部分。该决定于 2026-10-20 确认，替代此前两类独立入口的组织方式。页面组织见 [页面与菜单布局](../02-需求文档/2026-10-20-前端页面与菜单布局/01-需求说明.md)。

整体设计涉及穿搭时沿用已有衣橱选衣、必穿单品及可选尺寸规则。整体设计的照片预选和清晰度要求、只改发型时对未修改部分的保留要求仍待细化；只改穿搭时保留发型，见下文效果图真实性规则。现有数据库与接口的两类模式定义尚待调整，不代表已支持整体设计。

每次独立提交，使用 1 张本人照片，生成一套结果：1 张效果图和说明。穿搭可额外选择多件衣物，衣物参考图数量上限结合中转站协议确定。不满意时修改原要求并创建新任务。

2026-10-21 确认：首版一次提交后自动完成选衣、文字方案与效果图，不增加选衣方案的中途用户确认。规划通过程序校验后继续生图；不满意时修改要求创建新任务。本规则不取消提交前的输入预览与明确限制冲突处理，也不改变规划失败停止、结果未知不自动重发及用户手动重试规则。待生成模块实施。

页面关闭后后台继续执行，再次打开可查看任务状态和结果。每个账号最多有一个排队中或运行中的任务，再次提交提示查看现有任务；重复提交不创建额外任务。全平台允许多个用户排队。排队、待处理上传及暂存空间设可配置容量限制，达到限制时明确拒绝新增工作，已接收任务保留。结果待确认的任务释放账号名额，允许提交新任务，同时提示先前外部调用仍可能完成，不自动重提原请求。幂等键规则待细化。

失败后用户手动重试，新任务关联原任务。语言方案成功但生图失败时保存文字方案，可复用它重试生图；不能将此视为完整设计成功。超时或服务重启后，如不能确认外部调用结果，则标记结果待确认；可查询时先核实，不自动重复提交。

活动任务每 3 秒查询，页面不可见时暂停，恢复可见后立即查询。结果待确认（UNKNOWN）时停止持续自动轮询，进入详情页或手动刷新时查询；后台仍按渠道能力核实，发现结果后更新任务。

任务进度展示真实阶段，不编造百分比。语言模型输出必须包含设计说明、设计要点及生图提示词，校验失败则该阶段失败，不进入生图或自动追加修复调用。

模型分工、配置切换与运行方式见 [架构设计](03-架构设计.md)。

## 收藏与删除

只收藏自己生成成功的完整设计方案；仅有文字而图片生成失败的方案可查看和复用，不允许收藏。支持用户创建收藏夹，一个方案可以加入多个收藏夹。历史记录保存生成结果，收藏用于整理。

收藏可以不加入收藏夹，立即出现在“全部收藏”。同一账号下收藏夹名称去除首尾空格后不能重复，英文大小写有区别，例如 Travel 和 travel 可以共存。取消收藏不删除方案，同时移除所有收藏夹归属；删除收藏夹不删除方案，也不取消收藏；删除方案前提示，同时移除所有收藏关系。

排队中和运行中的任务不能删除或取消。成功或确认失败的任务允许删除，并按引用关系清理图片。结果待确认的任务允许从用户列表隐藏，后台保留核实所需记录及图片引用，待状态确认或达到约定保留期限后再清理；隐藏不代表取消外部调用，从隐藏时起最多保留 7 天，期间确认结果后即按隐藏意图清理，不重新显示；到期仍未知则停止核实并清理任务数据和无其他引用的文件。本地清理不代表取消供应商调用。仍显示的任务不自动删除。

删除照片库记录或衣物不删除过去的设计方案。仍被设计记录引用的图片保留到相关设计记录也被删除后再清理，界面明确说明这一区别。未加入照片库、衣橱或任务的临时上传文件保留 24 小时。已保存文件在最后一个有效引用删除后进入清理队列，执行前再次检查引用；首版不提供回收站。

## 状态与可执行操作

以下是已确认的业务语义；英文存储编码及执行权字段见 [数据库设计](04-数据库设计.md)，仍属于技术草案。

| 当前阶段或结果 | 触发与前提 | 用户可观察结果与限制 |
| --- | --- | --- |
| 排队 | 提交已接受，等待后台执行 | 占用账号名额，可以查询，不能取消或删除 |
| 方案生成 | 后台开始规划 | 展示真实阶段；结构化输出无效则失败，不继续生图 |
| 图片生成 | 文字方案已保存且校验通过 | 使用本人照片及所选衣物参考图；不能删除或取消 |
| 结果保存 | 已取得生成结果，仍需可靠保存 | 尚未完整成功；保存失败只恢复保存，不重新生图 |
| 完整成功 | 文字与图片均已保存 | 可查看、收藏或删除 |
| 确认失败 | 已确定该阶段失败 | 可手动创建重试任务或删除；有效文字可在生图失败后复用 |
| 结果待确认 | 无法核实外部调用是否成功 | 释放账号名额，不自动重提；可隐藏，后台按渠道能力核实 |
| 隐藏 | 用户隐藏结果待确认任务 | 隐藏与执行结果分开记录；不表示取消外部请求，按既定期限清理 |

## 规则核对场景

以下场景用于后续验收，目前均未执行：

- 修改当前尺寸后查看旧任务：旧任务仍展示提交时的尺寸；删除尺寸记录也不改变快照。
- 删除衣橱单品后查看旧设计：设计继续保留原输入图片，直至相关引用也删除。
- 文字方案成功、生图确认失败：允许查看文字和手动复用重试，不允许收藏为成功设计。
- 隐藏结果待确认任务后收到迟到结果：按隐藏意图清理，不重新出现在用户列表；隐藏操作不取消供应商调用。
- 一个收藏同时属于两个收藏夹：删除其中一个夹仍保留收藏和另一个归属；取消收藏则解除全部归属。
- 两台设备修改同一资料：旧版本写入被拒绝，前端保留输入，不静默覆盖新值。

## 衣橱自动搭配（已确认）

2026-10-21 确认天气与季节规则：按整套搭配的使用环境判断，优先参考用户主动提供的温度、室内外及活动信息；季节标签作为辅助，不直接排除跨季单品，允许通过叠穿使用。只提供季节时不自行换算温度，未提供天气时不擅自推断冷热。天气与温度默认作为设计依据，不构成保暖、防水等性能保证；明确提出的“必须防水”“不能露腿”等仍按硬要求处理，属性依据不足时沿用信息不足规则。衣橱无法兼顾一般场合与天气目标时，在遵守硬要求的前提下尽力搭配并说明局限。同一套方案可说明室内外穿脱方式，不额外生成第二套；外套为必穿时主效果图须穿着，用户要求全程穿着时不得建议脱下。首版不新增必填天气表单、自动定位或天气查询。待生成模块实施。

2026-10-21 确认必穿的含义：必穿单品须实际参与最终穿搭，文字方案与效果图保持一致。衣服穿在身上，包可手提或背着，配饰按正常方式佩戴；把衣服拿在手中或放在旁边不算满足必穿。同类单品不直接判冲突，按款式和正常穿用方式判断是否能合理组合；无法同时满足时停止并提示调整，不自行舍弃必穿项或强行叠穿。允许正常遮挡，不要求每件单品完整露出；用户明确要求展示某个细节时，将该细节的可见性作为硬要求，不能通过移动图案或改变单品款式满足。此为规划与效果图验收要求，不表示已验证生图模型能稳定遵守，不增加自动图像审核或重生。待生成模块实施。

2026-10-21 确认信息不足的处理：信息缺失本身不阻止生成。缺少识别标签但图片足以判断款式的单品可以参与搭配；普通审美判断允许合理取舍，结果须说明影响使用的不确定性，不把推测写成事实。若缺失信息影响硬要求或基础穿着判断，先在本次候选中寻找有依据的可行组合；无法找到时停止并说明需补充的信息，不以附带提醒代替满足硬要求。未提供的材质成分、保暖能力等不得仅凭图片判为确定事实。必穿单品同样遵守此规则，不得静默移除。待生成模块实施。

2026-10-21 确认结果表达：沿用固定方案栏目，清楚说明选用的真实衣橱单品、具体穿法，以及结合当次要求的配色、比例和场合理由。明确呈现未满足的目标、模型采用的理解与取舍；影响使用的限制和示意鞋的非衣橱来源提示放在效果图附近，不仅放在长说明中。不展示缺乏依据的搭配分数，不以空泛夸赞代替解释。说明表达设计意图，不宣称已验证最终图片或真实合身程度。待生成与结果页面实施。

## 常用搭配（2026-10-22 已确认，待实施）

常用搭配是用户保存并可反复使用的衣橱单品组合及穿法，区别于设计任务及对成功设计的收藏。用户可以手动组合，也可以从已有 AI 设计保存；保存后可独立编辑，不回写原设计。资源归属沿用当前账号隔离规则。

- 支持自定义分组，一套搭配可属于多个分组。删除分组仅解除该组关联，不删除搭配或其他分组归属；无分组的搭配仍可在“全部”找到。
- 用户可以置顶或取消置顶，工作台优先展示置顶搭配；置顶不是自动推荐，也不是实际穿着记录。
- 手动组合不完整时仍允许保存和请求评价；生成上身效果图时再检查能否构成完整穿搭。本规则不放宽既有自动选衣设计的完整性要求。
- AI 评价和效果图以用户选定组合为准，不自行更换单品；改搭建议单独表达，用户采纳后再修改组合。既有示意鞋例外在此流程是否适用仍待明确。
- 文字评价可独立生成，无需强制提供本人照片。无照片时评价配色、单品组合和穿法，不判断实际上身效果；生成上身效果图需要本人照片。仅文字成功不因缺少效果图被判为失败；既有设计任务的成功与收藏规则不变。
- 衣橱单品删除后保留搭配、标记缺失并允许替换，不自动删除整套搭配。
- 搭配修改后保留旧评价和效果图，明确标注对应修改前的搭配；由用户主动重新生成，不把旧结果作为新组合的评价或效果图。

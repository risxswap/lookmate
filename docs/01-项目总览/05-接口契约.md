## 通用约定

- 沿用 [架构文档](03-架构设计.md) 中的 HTTP 状态与 JSON 响应格式。
- 资源 ID 以字符串传输，时间使用带时区的标准格式；列表统一分页，已确认分页参数见下文。
- 更新字段明确区分未传、null 和空值，逐接口定义清空语义。
- 后端从会话确定身份，校验资源归属，不信任客户端指定的 user_id。
- 图片二进制由浏览器直接上传七牛。后端的上传授权、完成核验和访问授权使用业务 JSON；七牛接口独立于项目 API。

## 上传与设计提交

1. 向后端申请文件 ID 和七牛上传凭证，再直接上传七牛；完成后通知后端核实对象及真实内容，完成方向纠正和元数据清理。未完成核验的文件不可引用。
2. 客户端提交照片库记录、衣物或设计任务时只引用文件 ID。
3. 后端在事务中校验文件归属、状态和有效期，建立对应引用。
4. 设计提交成功返回 202 和任务编号；重复提交遵循幂等规则，账号名额冲突返回 409。

未保存临时文件保留 24 小时。具体文件限制、预处理、并发、轮询和模型输出校验以 [架构文档](03-架构设计.md) 为准，不将其解释为中转站接口能力。

## 七牛授权约定（已确认）

上传凭证限定单个对象、大小和有效期，并禁止覆盖已有图片。后端永久密钥不下发客户端。完成通知触发后端异步核验，重复通知不重复处理；后台定期核查七牛对象，补偿浏览器关闭或通知遗漏。客户端查询核验状态，只有核验成功才允许业务引用，不能仅凭客户端声明将文件设为可用。

图片存放在私有空间，访问授权接口验证归属后返回短期签名地址及过期时间。浏览器直接访问七牛；签名有效期内持有该链接即可使用，不把地址当作永久资源标识保存。生成图片由后台保存至七牛，不依赖浏览器在线。

## 会话约定（已确认）

普通会话连续空闲 2 小时失效，从登录起最长 7 天。登录可传 rememberMe=true，使用持久 Cookie，从本次登录起最长 30 天（服务端可配置）；缺省 false。服务端独立校验绝对期限，页面轮询不会延长绝对期限。允许多设备会话，退出只结束当前会话，暂不提供设备管理页面。具体边界见 [记住登录](../02-需求文档/2026-10-24-记住登录/01-需求说明.md)。

会话失效返回 401，前端停止需要登录的轮询并进入登录流程；重新登录后从服务端恢复任务状态，不重新提交生成请求。生产 Cookie 使用 HttpOnly、Secure、SameSite=Lax；写操作保留 CSRF 防护。

## 逐接口设计（技术草案）

以下未明确确认的方法、字段名和默认值是已有草案，供对应需求设计参考，不要求集中补齐或一次性确认。所有私有资源操作均从会话确定账号，并在 Service 校验归属；资源不存在或属于其他账号返回 404。请求使用 camelCase，数据库使用 snake_case。

### 公共传输格式

2026-10-20 已确认页码分页：page 默认 1、pageSize 默认 20 且最大 100；响应 data 包含 items、page、pageSize、total，默认按 createdAt、id 倒序。首版接受并发新增或删除导致跨页位置变化，不引入游标分页。

```json
{"data":{"id":"123"},"requestId":"request-identifier"}
```

```json
{"code":"ACTIVE_TASK_EXISTS","message":"已有待完成的设计任务","requestId":"request-identifier"}
```

字段错误可增加 `fieldErrors` 数组，每项为 field 和 message。请求标识由后端生成或校验后接收，不承担幂等职责。分页请求 page 默认 1，pageSize 默认 20、最大 100；响应 data 包含 items、page、pageSize、total。列表按 createdAt、id 倒序，业务排序另行注明。时间统一返回 UTC ISO 8601，例如 `2026-10-19T06:00:00.000Z`，前端按用户时区展示。

新增资源返回 201，普通查询与更新返回 200，已接受后台操作返回 202。删除成功返回 200 和 data:null；删除已不存在的本人资源可按幂等成功处理，但不能通过响应泄露其他账号资源。未经认证返回 401；CSRF 不合法返回 403；内容过大返回 413；频率限制返回 429；维护或依赖不可用返回 503。

PATCH 中未传字段保持原值，显式 null 仅允许清空声明可空的字段；空字符串不是通用清空标记。已确认创建和修改请求拒绝未定义字段，包括未经契约允许的 userId、状态和时间字段。空数组逐业务定义：seasons 空数组表示不限季节，images 空数组拒绝；整组图片以完整有序列表替换，人工特征修订使用独立接口。ID 不转为 JavaScript number。

### 异常和并发契约

已确认 Service 通过运行时业务异常表达失败，统一异常处理映射为 HTTP 状态和既定错误格式；认证过滤器使用同一格式。前端按 code 判断行为，不解析 message。后台任务失败由查询结果的任务状态及安全错误字段表达，查询成功返回 200，不将 FAILED 映射为查询接口 HTTP 500。已确认设计提交返回 202 和任务编号，详情通过 status、errorCode、errorMessage 表达任务状态及失败原因。

账号请求过频或上传额度暂满返回 429；全局排队已满或暂存空间不足返回 503。幂等请求优先查找原任务，再检查新增容量。

版本字段范围草案：资料、图片人工修订、收藏夹查询返回 version；修改资料、图片人工修订、收藏夹名称、默认照片和当前尺寸时携带 version。新增尺寸自动切换当前值，因此携带资料版本；删除尺寸统一携带资料版本，避免并发切换后误清当前值。缺失版本返回 400，过期版本返回 409 VERSION_CONFLICT；成功响应返回新版本。前端保留输入并提示刷新比较，不自动覆盖重试。后台任务名额变化不递增资料编辑版本。

### 已确认文本长度

显示名称、收藏夹名称最多 64 个字符；衣物名称、颜色最多 100 个字符；衣物备注最多 1000 个字符。接口与表单同步校验，超限返回 400 字段错误，不静默截断；可空性与清空语义沿用各字段约定。本节确认不代表其余接口契约已整体确认。

### 尺寸单位与数值

尺寸字段不带单位后缀，数据库 snake_case 对应接口 camelCase。长度和围度统一为 cm，weight 为 kg；请求与响应采用 JSON 数值，最多两位小数，不采用整数毫米或克。后端使用十进制数值处理并在持久化前校验，超出两位小数返回 400，不依赖数据库静默舍入。可空表示未提供，非空值必须大于零。任务尺寸快照沿用此单位，模型输入附明确单位说明。尺寸接口不增加 measuredAt、measurementMethod 或 notes；仅保留尺寸值及通用记录信息。已确认共 27 项尺寸，脚部区分左右，其余部位记录一组值。

尺寸保存与查询字段如下，均可空；保存时按完整记录处理，未提供字段记为 null，不自动继承旧记录。

```text
height, weight, neck, chest, underbust, waist, abdomen, hip, shoulder, backWidth, armLength, upperArm, forearm, wrist, frontWaistLength, backWaistLength, inseam, outseam, thigh, knee, calf, ankle, head, leftFootLength, rightFootLength, leftFootWidth, rightFootWidth
```

| POST /api/designs/{id}/hide | UNKNOWN 状态 | 设置隐藏，不取消外部请求；重复操作不延长清理期限 |
| DELETE /api/designs/{id} | SUCCEEDED 或 FAILED | 删除任务与方案及收藏，按引用清理文件 |

发型和穿搭均要求本人照片。requiredDressIds 表示穿搭必须使用的本人衣橱单品，不传或空数组表示由系统自动选衣；该字段仅用于穿搭，发型提交非空衣物集合返回参数错误。useMeasurements=false 时不使用尺寸；true 且 measurementId 未传时在事务内读取当前尺寸，指定时验证历史记录归属；没有有效尺寸仍可提交。已确认首版每次使用 1 张本人照片，生成 1 张效果图；穿搭可额外选择多件衣物，衣物参考图数量上限结合中转站协议确定。

客户端一次明确提交生成一个幂等键并保留到得到确定响应。网络失败后先使用相同键查询或重发相同请求，不生成新键；关闭自动重试不等于禁止用户手动恢复未知提交。服务端先查同账号幂等记录，再检查账号名额；相同键不同请求返回 409 IDEMPOTENCY_CONFLICT，相同请求返回原任务。去重以规范化客户端请求摘要为准，不以可能变化的当前尺寸内容计算摘要；第一次创建时固定实际输入快照。

已确认 GET /api/designs/by-request/{clientRequestId} 用于在当前账号范围查找已成功入库的提交。查询不到不能证明外部生成未执行，但可使用原键重新提交，由创建事务保证去重。任务已删除后客户端不复用旧键。

重试 FULL 使用原任务输入快照及当前模型配置；修改输入属于新的普通设计提交。IMAGE_ONLY 仅限已有有效文字方案且图片已确认失败的任务，复制原文字方案及规划来源，再按当前生图配置创建新任务。UNKNOWN 不开放自动或一键原任务重试，用户可在知晓旧请求可能完成的前提下新建独立设计。

正常活动状态沿用 3 秒轮询；已确认 UNKNOWN 停止持续自动轮询，进入详情页或用户手动刷新时查询，后台独立按渠道能力核实，发现结果后更新任务。重试、删除、隐藏等可执行操作由后端根据状态返回 actions，前端不自行推断操作权限；actions 只是当前状态下的可执行操作，实际操作请求到达时后端必须再次校验状态和归属。

## 内部维护契约（接口细节草案）

运维控制只通过内网管理端口开放，不由公网入口 Nginx 转发，使用独立运维凭据。控制调用也带操作编号，重复请求查询同一操作状态。维护状态已确认保存到 server 持久化目录的标记文件，重启后保持维护；不建立 maintenance_control 表。具体接口路径和文件格式仍为待细化内容。

| 操作 | 行为 |
| --- | --- |
| 进入维护 | 将门禁设为 DRAINING，拒绝新业务写入与上传授权，停止领取工作，允许已有工作收尾 |
| 查询维护 | 返回门禁状态、运行任务、核验和保存工作数、阻塞原因 |
| 进入静止状态 | 在没有可能修改快照数据的执行器后转 QUIESCED；外部未知请求只能记录为待后续核实 |
| 退出维护 | 校验操作编号、依赖、数据库兼容性及无冲突维护操作，再转 OPEN |

已签发的上传凭证不能靠本地门禁撤回；新到七牛的对象仍需核验后才能成为可用业务文件。维护期间拒绝完成入库请求时返回 503，不将已上传对象误报为丢失，恢复后由后端补查。具体控制路径和请求签名方式随部署工具确定。




## 衣橱多图识别与选衣接口草案

POST /api/dresses 要求 name、categoryId、images。有序 images 中每项使用 fileId，至少一张，第一张为封面；创建成功返回 201，图片列表及独立识别任务 PENDING 状态。GET 单品组合返回 imageRevision、当前识别任务摘要和 images，每张图包含 imageId、fileId、sortOrder、AI 识别字段、manualFeatures、effectiveFeatures、recognitionId 和 version，不返回执行权或凭据。

PATCH /api/dresses/{id} 不传单品 version，单品数据按服务器最后成功保存为准；images 未传保持原组，传入则是完整有序集合，已有图使用 imageId，新图使用 fileId，二者互斥。省略旧图表示删除，替换使用新图记录；同一事务校验非空、归属、文件可用和去重后更新顺序，并在集合变化时只创建一个识别任务。整体排序、图片集合版本及当前识别状态由服务端管理，不允许客户端直接指定。

图片人工修订使用 PATCH /api/dresses/{id}/images/{imageId}，携带图片 version、manualFeatures 与可选 resetFeatureKeys。未传键保持不变，显式 null 表示未知，resetFeatureKeys 删除人工覆盖并恢复 AI 值，两者不能冲突。修改人工特征不触发识别，仅递增图片自身编辑版本。此接口不替换文件，换图走整组保存。

POST /api/dresses/{id}/recognition-retry 带目标 recognitionId，锁定单品后校验它仍是当前集合最新的可重试任务，再新建当前集合的识别任务，返回 202 及任务编号。PENDING/RUNNING 不重复入队；UNKNOWN 需 confirmUnknown=true 提示旧请求可能仍执行。移除 /manual-confirm，人工补齐直接保存即可，提交设计时校验基础资料和图片可用性，不要求额外确认版本。进度查询从最新 dress_recognition 组合，dress 不重复存识别状态。

设计提交 requiredDressIds 表示必须使用的单品，空数组从已有衣橱自动选衣。候选和结果图片均为列表，保存 sourceDressId、sourceDressImageId 及不可变文件引用。返回 selectedDressIds 与单品／多图快照。模型图片数量限制及具体错误码仍待验证；不得静默删除必穿单品或生成衣橱之外的服饰。

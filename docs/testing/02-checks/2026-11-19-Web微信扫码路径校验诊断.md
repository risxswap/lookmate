# 临时验证：Web 微信扫码路径校验诊断

- 日期：2026-11-19，Asia/Shanghai，约 15:04。
- 依据：[小程序接口与数据设计：Web 扫码](../../02-需求文档/2026-10-30-微信小程序/04-接口与数据设计.md#web-扫码)。预期取码返回 `id`、`expiresAt` 和 `imageDataUrl`。
- 环境：本机 Lookmate Web `127.0.0.1:5174`、本机后端 `127.0.0.1:8080`，以及微信官方小程序码 API；未探测项目公网入口。使用 curl 8.7.1，连接超时 6 秒、总超时 15 秒，不重试、不跟随重定向。

## 业务接口

两个入口分别创建独立诊断会话，先 GET `/api/auth/csrf`，再携带同一 Cookie 和 CSRF 头 POST `/api/auth/qr`（请求体 `{}`）。

| 入口 | CSRF | 取码 | requestId |
| --- | --- | --- | --- |
| Web `:5174` | 200 | 503 / `WECHAT_UNAVAILABLE` | `fc87b1df-7d69-41c0-9b70-dc5896e9f9cf` |
| 后端 `:8080` | 200 | 503 / `WECHAT_UNAVAILABLE` | `0c8fc92f-6442-45af-a345-815c7e95158e` |

两次均返回“微信登录码暂不可用”。诊断产生的短期登录请求按现有机制到期清理。

## 微信上游对照

`.env.dev` 的 AppID 与小程序项目配置一致，`/cgi-bin/token` 返回 HTTP 200 和有效访问令牌。直接请求 `/wxa/getwxacodeunlimit`，`env_version=develop`、`page=pages/scan/index`、`check_path=true`；首次诊断 scene `diag20261119a5c20448c5` 返回 HTTP 200、JSON `41030 invalid page`，微信 rid `6afe9f86-54a2a16d-10cebb14`。

再使用同一令牌和 scene `diag20261119c7bf9cff64`，只改变 `check_path`：

| `check_path` | 微信响应 |
| --- | --- |
| `true` | HTTP 200，JSON `41030 invalid page`，rid `6afe9fb7-3c4b57eb-22e51d84` |
| `false` | HTTP 200，`image/jpeg`，97,520 字节 |

本地 `src/app.json`、`dist/app.json` 均已登记该页面。未保存二维码、Cookie、CSRF、密钥或访问令牌；未扫码、确认或领取会话。对照仅证明微信可返回图片，不代表二维码打开及登录链路已经验证。

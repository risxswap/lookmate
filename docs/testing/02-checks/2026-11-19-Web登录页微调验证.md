## 实际结果

- 修改前，1280×900 下从扫码切换为账号密码，「欢迎回来」的纵向坐标由 185.6 变为 168.2 CSS px。第一次复验中标题和标签位置已固定，但常见密码错误仍使表单容器增长 2.8 px；调整共享内容区预留高度后复验通过。
- 最终在 1280、360、320 px 宽度下，扫码、账密、凭据错误、限流反馈的右侧面板、表单容器、标题和标签尺寸与位置不变，无横向滚动。扫码区无装饰框或白底、不改图像像素；键盘触发刷新后仅创建一个新码，刷新按钮保持焦点。
- 模拟取码失败后可重试；查询失败后执行「检查登录状态」复查原票据，不创建新码；过期、取消后可获取新码。原始接口错误未显示在界面。错误密码提示在表单内，用户名保留；限流显示等待秒数。注册页仍显示确认密码，不发起取码请求。未观察到未捕获的页面异常。
- `apps/web` 构建通过（Vite 提示包体积）；`node --test tests/*.test.mjs` 108 项通过（含扫码 10 项）。`apps/server` 在 Java 21 下运行 `./mvnw -o -Dtest=WechatClientTest test`，5 项通过，确认请求发送 `is_hyaline: true`、原有路径校验不变、PNG/JPEG 原样传递。

未调用真实微信取码接口、未使用真机扫码，也未部署或迁移。模拟图只能证明页面透明呈现，不能证明微信实码的透明度或可扫性。

# 衣橱单品交互优化开发验证

日期：2026-10-24。依据：[需求](../../02-需求文档/2026-10-24-衣橱单品交互优化/01-需求说明.md)与[实施计划](../../02-需求文档/2026-10-24-衣橱单品交互优化/02-实施计划.md)。

## 实现与复核

单品列表采用四列轻量图片网格，分类与添加入口集中在工具栏。封面点击打开本件图片的大图弹窗，可切换多图；名称打开详情，更多菜单提供查看、编辑与确认删除。识别失败和未知状态保留详情入口，单页隐藏分页。添加弹窗将图片放在前面，支持点选与拖拽、调整封面顺序、分类预选，保持一次保存一件单品。

主 agent 复核后修复了三处问题：编辑缓存新鲜时不发请求可能停在加载态，改为每次直接编辑强制取最新详情；全局样式覆盖图片高度，增强局部选择器后实测图片与容器均为 290px；原生文件 input 被样式显示，改为显式隐藏并保留一个上传入口。未修改后端、数据库和详情布局。

## 浏览器检查

使用 Playwright CLI 与真实 Chromium，在本地 Vite 127.0.0.1:5173 检查。身份、衣橱、文件授权及上传请求由浏览器隔离路由响应；23 件示例单品使用带 TEST ITEM 标记的示意图片，不读取或写入真实账号数据。

| 场景 | 实际结果 |
| --- | --- |
| 1440×1000 列表 | 四列网格，图片完整显示，长名称省略，正常图片无常驻刷新按钮 |
| 多图预览 | 首件两图可切换，仅请求本件 DISPLAY 图片；最后一张禁用下一张、允许上一张 |
| 图片失败 | DISPLAY 授权返回 503 后显示重试，恢复响应后重试显示图片 |
| 直接编辑与重复打开 | 连续两次从菜单打开编辑，均读取详情并显示表单，不停在缓存加载态 |
| 服务端分页 | 第二页请求 page=2&pageSize=20，显示剩余 3 件；筛选上装请求 page=1&pageSize=20&categoryId=1，显示 4 件 |
| 分类内添加 | 添加弹窗预选上装；空名称提交显示校验错误 |
| 两图保存 | 上传两图并交换顺序，提交同一件单品的 images 数组，首图 fileId=101、次图=100 |
| 保存失败恢复 | 首次 POST 模拟确定拒绝，名称与图片保留；重试成功关闭弹窗并更新列表；两次 POST 均包含同一组两图，上传授权总计两次 |
| 删除确认 | 取消确认未发 DELETE；确认后模拟 503，保留弹窗，重试成功移除单品 |
| 上传入口 | 原生 input 不可见；点选可打开文件选择器，模拟上传失败显示重试入口；恢复后完成登记，可移除草稿 |
| 空分类 | 空配饰分类显示添加引导，不显示分页 |
| 1000×900 桌面 | 三列布局，分类可换行，无横向溢出 |

验证脚本调整：路由限制为 `/api/` 前缀，避免拦截源码 `/src/api/client.ts`；表单必填标记及按钮加载图标会影响可访问名称，改为匹配实际名称；图片失败夹具保持失败直到点击重试，避免开发模式重挂载使瞬时失败被恢复请求覆盖。文件选择器由 CLI 接管，额外选择产生的测试草稿已移除。这些属于验证工具调整，未作为产品缺陷记录。

# Java 排版与格式检查

日期：2026-10-21。范围：服务端 Java 生产与测试源码、Maven 格式检查、java-backend 技能；不改变业务规则。

## 问题与修复

原规约只规定四空格缩进，未明确声明注解和方法体的排版，也未要求交付前执行格式检查。后端构建没有格式门禁，已有代码出现注解、声明及方法体压缩在一行的情况。

通用技能源码和项目已安装副本同步补充了声明注解独占一行、非空方法体展开、语句与成员分行、逻辑分段及交付前检查要求。规则明确属于本套补充，不扩大阿里规约的采纳声明。

服务端锁定 Spotless 3.0.0 和 google-java-format 1.28.0，使用 AOSP 四空格风格，在 Maven validate 阶段执行只读检查。覆盖 src/main/java 与 src/test/java；自动修复由 spotless:apply 单独执行。114 个 Java 文件中，95 个需要格式化，本次完成统一；后续局部任务只修正涉及文件。

## 验证证据

使用本机 Java 21.0.8 与项目 Maven Wrapper，在 apps/server 执行：

| 检查 | 结果 |
| --- | --- |
| 修复前 ./mvnw -B spotless:check | 失败，报告 95 个文件有格式差异，包含压缩方法和测试注解 |
| ./mvnw -B spotless:apply | 成功，处理 114 个文件，修改 95 个 |
| main、test 分别放入临时压缩注解与非空方法样例，运行 ./mvnw -B validate | 两处均失败并指出样例文件；文件内容未被检查命令修改 |
| 对临时样例定向执行 spotless:apply，再运行 validate | 两处均成功；注解与方法体展开；样例随后删除 |
| ./mvnw -B verify | BUILD SUCCESS；94 项测试中 43 项通过、51 项跳过，无失败或错误 |
| 技能脚本 validate_skills.py、quick_validate.py | 通过，链接与元数据有效 |
| git diff --check | 通过 |

核对了 Controller、Mapper、实体、Service 与测试的格式 diff；95 个文件在排除 import 顺序、注释、空白和文本块缩进后，词法内容无差异。格式器保留字符串内容，不重排业务成员。

本次未启用 LOOKMATE_INTEGRATION，依赖真实 MySQL/Redis 的集成测试按已有条件跳过；不将普通构建通过视为真实持久化行为已验证。运行中的开发服务使用独立目录下的 JAR，本次构建未重启该服务。

命令和单文件格式化用法见 [服务端说明](../../../apps/server/README.md#java-格式检查)。

## 更新技能后的补充复核

工作区已有上述格式迁移，本轮按更新后的技能复核发现：google-java-format 仍将部分测试字段注解与声明放在同一行，四个生产类中还保留了合并字段声明。先前格式检查通过没有覆盖这两项要求。

本轮拆开 FileDto、FileAssetRow、RecognitionWorkRow、FileUploadParam 中的合并字段，并在 Spotless 的 google-java-format 步骤之后增加声明注解换行规则。四个测试类中的字段注解随格式器展开。业务处理与字段顺序保持不变；合并字段声明仍由人工审阅核对。

Java 21 环境下重新验证：

- 增加规则后运行 `./mvnw -B spotless:check`，正确拒绝现有测试中的同行字段注解。
- 运行 `./mvnw -B spotless:apply test`，格式修复、validate 阶段只读格式检查、生产与测试编译通过；94 项测试中 43 项通过、51 项按环境条件跳过，无失败或错误。
- 审阅本轮字段拆分、注解排版与配置差异，检索未再发现上述同行声明和合并字段；`git diff --check` 通过。

本轮未启用外部服务集成测试，未重启开发服务。

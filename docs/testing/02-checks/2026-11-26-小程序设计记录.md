# 小程序设计记录验证

2026-11-26，从微信开发者工具的「我的 → 设计记录」进入。模拟器使用本次小程序构建和本地接口夹具。夹具含 29 条任务，包含已成图的设计、进行中与失败任务、文字评价、历史缺图记录和无法读取的缩图。[需求与验收范围](../../02-需求文档/2026-10-20-设计记录/01-需求说明.md#2026-11-26-小程序设计记录)

## 微信模拟器操作

| 操作 | 观察 |
| --- | --- |
| 在 390px 屏幕打开记录 | 改前首屏重复显示标题，日期为完整时间戳，摘要为空时显示了 null。新版首组显示「今天」，行内显示「18:08」。缩图占位与成图均为 66 × 88px，失败后仍能点整行查看详情。[改前](2026-11-26-小程序设计记录/01-改前列表.png) · [改后](2026-11-26-小程序设计记录/02-记录列表.png) |
| 设置任务范围和状态 | 取消后列表没有发起请求。应用筛选后按选定条件从第一页读取。顶部五个操作的点击区域均高 44px。[筛选面板](2026-11-26-小程序设计记录/03-记录筛选.png) |
| 翻页失败后重试 | 筛出 21 条已完成的穿搭任务，第二页失败后保留首批 20 条。重试时携带原筛选，页码依次为 1、2、2，每页 20 条。 |
| 进入详情，返回列表 | 搭配评价打开对应常用搭配；缩图读取失败的普通任务仍能打开设计详情。返回后保留「穿搭」「已完成」。 |
| 清除筛选或开始设计 | 零匹配时点「清除筛选」恢复 29 条记录。模拟账号没有任务时点「去做设计」进入设计页。 |

320px 模拟器也走通了上述流程。长标题最多显示两行，状态始终完整可读。首轮实测发现四列筛选会把「结果待确认」的最后一个字挤到下一行。窄屏改为三列后复测，所有状态都在一行，点击区高 44px，「应用筛选」高 48px。选择「仅普通设计」和「结果待确认」后返回唯一匹配的记录。[窄屏长标题](2026-11-26-小程序设计记录/04-窄屏长标题.png) · [窄屏筛选](2026-11-26-小程序设计记录/05-窄屏筛选.png)

在两个尺寸上各测量四对相邻的同日记录，卡片边框之间均有 8px 间距。

## 接口与构建

- 小程序 169 项测试全部通过。构建校验 19 条路由、组件依赖和本地资源。微信原生编译器通过 30 份 WXML/WXS 及 28 份 WXSS。
- 在独立的 MySQL 8.0.45 与 Redis 8.10.2 实例上，记录和工作台两组集成测试共 14 项通过。MockMvc 的记录响应保留了超出 JavaScript 安全整数范围的字符串文件 ID，排除了其他账号的图片引用。文字评价、失败任务和缺图任务的 `outputFileId` 均为 null。测试库通过 ops 应用已有 V1 至 V12 后启动，两个测试实例已关闭。
- Java 21 的 Maven 标准验证通过，191 项执行，170 项按环境条件跳过。上述 14 项另在隔离环境执行。线上后端、真实对象存储和真机显示仍待联调。

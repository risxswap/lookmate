# 全局反馈提示开发验证

## 范围与实现

2026-10-24 用户要求接口等操作反馈使用 Ant Design Message 和右上角 Notification，不占用页面内容区。本轮按局部交互调整实施，覆盖登录注册、工作台、资料、上传、衣橱、收藏、设计提交与搭配操作。

统一组件 `apps/web/src/components/Feedback.tsx` 使用 `App.useApp()`：简短反馈用 Message（错误 5 秒，其他 3 秒）；有详情或操作按钮的反馈用右上角 Notification，保留至关闭或对应状态结束。组件卸载清除自己的提示；同一次反馈更新沿用同一 key，新请求失败可重新提示。照片弹窗中的反馈仅在弹窗打开时显示。

表单字段校验、历史任务失败原因、生成结果限制与资料冲突对照属于字段或业务内容，保留在原位置。未修改接口与业务规则，未调整历史界面预览稿。

## 验证结果

- `npm run build --prefix apps/web`：通过类型检查与构建；保留大于 500 kB 的构建体积警告。执行环境 Node.js 24.14.0，低于 package.json 声明的 24.22.0 最低版本，本轮未更换运行时。
- `node --test apps/web/tests/*.test.mjs`：31 项通过。首次执行上传用例因隔离加载器未声明新增 Feedback 依赖失败；补齐该依赖替身后通过，原有业务断言保留。
- Playwright CLI 真实浏览器访问本地 Vite（127.0.0.1:5173），使用浏览器路由模拟登录失败和注册配置失败、恢复；未创建账号或写入业务数据。
- 登录错误：顶部 Message，页面无对应 Alert，自动消失，同文案再次提交失败仍显示一条提示。
- 注册配置读取失败：右上角 Notification，重试后失败提示仍可用；切换为成功响应后，重试恢复注册表单并移除通知。
- 重试验证初次定位遇到旧通知退出与新通知进入动画期间的双按钮；动画结束后只有一条通知，再次验证恢复通过。
- 已查看截图：仓库 `output/playwright/feedback-message.png`、`output/playwright/feedback-notification.png`。

浏览器仅验证上述代表路径；其余业务页面完成类型检查与代码核对，未逐一执行完整业务流程。真实供应商与生产环境不在本轮范围。

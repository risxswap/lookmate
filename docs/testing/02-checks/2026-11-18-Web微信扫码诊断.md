## 预期与实际尝试

各入口先 GET `/api/auth/csrf`，从响应提取 `headerName` 和 `token`，再携带同一 Cookie 会话及该头 POST `/api/auth/qr`，Content-Type 为 `application/json`，请求体 `{}`。GET 超时预算 25 秒，POST 同样为 25 秒。

按契约，配置及微信权限正常时取码应返回包含 id、expiresAt、imageDataUrl 的响应。实际如下，curl 均无传输错误：

| 入口 | CSRF | 取码 HTTP / 业务码 | 取码 requestId |
| --- | --- | --- | --- |
| `http://127.0.0.1:5173` | 200 | 503 / WECHAT_UNAVAILABLE | 3e891f4b-d68f-4b09-9a2a-be976735b265 |
| `http://127.0.0.1:8080` | 200 | 503 / WECHAT_UNAVAILABLE | 380f9cf2-9938-41fd-8754-7463ba599e89 |
| `https://lookmate.labno3.com` | 200 | 503 / WECHAT_UNAVAILABLE | 8e7eeff6-8eae-4f76-ae77-e31f1678e87e |

三个取码响应的 message 均为 `微信登录码暂不可用`，未进入状态查询或领取步骤。上游诊断结果及源码归因另见[问题说明](../../03-BUG修复/2026-11-18-Web微信扫码不可用/01-问题说明.md#根因证据)，不计作业务接口验收通过。

## 证据与清理

本文件及问题说明保存脱敏响应字段和关联标识，无独立原始响应文件。Cookie jar 存在临时目录，请求结束后已删除；上游令牌仅保留于诊断进程内存，进程已退出。未保存密钥、Cookie、CSRF 或 access_token。

取码接口会创建短期认证请求；本次使用独立诊断会话，未操作真实用户账号，未手动删除数据库记录，按既有过期清理机制处理。未验证微信扫码、登录确认、浏览器领取或真机，认证处理后待复验。

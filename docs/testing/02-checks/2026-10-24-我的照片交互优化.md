# 我的照片交互优化开发验证

日期：2026-10-24。依据：[确认范围](../../02-需求文档/2026-10-21-个人资料/01-需求说明.md#2026-10-24-我的照片优化确认与实施授权)。

## 实现与复核

照片页改为分段筛选、照片网格与更多菜单；照片完整显示，默认用途采用角标。去掉照片页顶部刷新与常驻图片刷新按钮，失败仍可重试。点击图片打开大图；设置／取消默认、删除进入菜单，删除保留确认。服务端分页沿用每页 12 张，单页和空结果隐藏分页。

添加弹窗选择类型后，点选或拖入即上传并自动入库，每张固定选择时的类型，显示处理状态。成功项不重复入库；确定拒绝可复用原 fileId 重试。后端 POST /photos 没有幂等去重，不确定结果只通过分页核对 fileId 和类型；查不到继续待核对，不盲目重发。图片入库不会自动设置默认照片。

主 agent 复核后修正了全局样式覆盖图片高度、隐藏弹窗错误提示、拖拽区使用 Ant Design Button、卸载清理原始 File 引用。衣橱和设计上传仍采用原流程。

## 浏览器验证

执行器：Playwright CLI，真实浏览器，1440×1000，本地 Vite 127.0.0.1:5173。身份、照片、文件授权及上传接口通过浏览器路由隔离响应；图片为带 TEST PHOTO 标记的示意素材，无真实账号或业务数据写入。

| 场景 | 实际结果 |
| --- | --- |
| 初始照片库 14 张 | 第一页 12 张，默认头像／全身照角标可见，无刷新按钮 |
| 同时选择 3 张照片 | 自动发起 3 次入库请求，无保存按钮；成功、429 失败、503 结果不确定分别显示 |
| 重试入库 | 只增加一次失败项 POST，沿用 fileId=201；上传授权仍为 3 次 |
| 核对不确定结果 | 使用 GET 找回 fileId=202，不新增 POST；合计 4 次入库请求最终新增 3 张照片，默认引用保持 |
| 分类与分页 | 全身照筛选只显示对应照片；单页隐藏分页；全部分类第二页发出 page=2&pageSize=12 并显示当前页条目 |
| 默认与删除 | 取消默认、重新设置均更新角标；打开删除确认未写入，确认后照片移除且对应默认引用清空 |
| 图片预览 | 点击照片打开 Ant Design 大图预览 |
| 拖入后切换类型 | 全身照类型下拖入，上传处理中切换为参考图，最终入库仍为 FULL_BODY |
| 处理中关闭保护 | 文件登记延迟期间“完成”禁用；处理完成后可关闭；待处理项刷新触发离页提示 |
| 空分类 | 显示简短空状态与添加入口，无分页 |

验证过程中的工具调整：首次路由匹配误拦截 Vite 的 /src/api/client.ts，增加 /api/ 前缀判断后恢复；首次文件选择同时使用 run-code 与 CLI upload 导致测试素材选择两次，重置隔离夹具后仅调用一次 upload 重验；分段控件的隐藏 radio 无法直接 check，改为点击实际可见标签后验证通过。以上未作为产品失败结论。

# 小程序首页穿搭手账验证

2026-11-25，按[用户确认的首页样例](../../02-需求文档/2026-11-13-小程序视觉优化/01-需求说明.md#2026-11-25-首页我的穿搭)核对小程序首页。微信开发者工具版本 2.02.2608080，基础库 3.18.0，iPhone 12/13 (Pro) 模拟器可用窗口为 390×671。隔离工程加载本次构建的首页，用内存数据模拟当前账号、任务、安排和常用搭配，示例照片为 240×320。通过 miniprogram-automator 0.13.0 操作。

## 页面与操作

| 操作 | 实际结果 |
| --- | --- |
| 打开有安排的首页 | 首套安排的两幅图共用一个封面地址，左侧放大细节，右侧完整显示。日期在第一行，「我的穿搭」和「常用搭配」均为 21px，页头标题和浅绿胶囊垂直居中。 |
| 切到无安排日期 | 矮横卡显示「安排搭配」和品牌照，点击后进入所选日期的日历。常用搭配接在横卡下方，无场景的搭配只显示名称。 |
| 点击页头胶囊 | 空闲时进入设计页。有活动任务时显示「查看进度」，普通设计进入设计详情，搭配任务进入对应搭配详情。 |
| 更换日期、打开日历、查看多套安排 | 日期选择器的 change 事件只触发目标日期的安排查询。点击安排卡或「查看当天全部」后，日历收到对应日期。 |
| 打开常用搭配 | 点击照片打开对应搭配详情，点击「查看全部」进入搭配列表。 |
| 使用长名称、创建第一套搭配 | 长中文名称在安排卡中换成两行，在相册双列中换成三行，均留在卡片内。常用搭配为空时，点击「创建第一套搭配」进入创建页。 |
| 等待任务结束，重试失败的读取 | 任务结束时只轮询工作台接口，胶囊恢复「去做设计」。模拟读取失败后点击「重新加载」可恢复首页。图片加载失败时显示占位，安排快照仍可查看。 |

## 构建与验证范围

首次模拟器检查发现常用搭配封面居中裁掉了示例人物的额头。相册改用 3:4 容器，保留等比铺满。用 Chromium 离线渲染构建产物中的首页和 TDesign 按钮模板及样式，分别检查 320px、390px 下的有安排、无安排、活动任务及缺图。两种宽度下封面和占位均为 3:4，日期和胶囊点击区高 44px。这里的窄屏测量使用浏览器映射的小程序标签、rpx 和测试数据。

最终版本在 390px 微信模拟器中，相册照片与缺图占位均为 172×229.33px，两张竖幅示例保留了头顶和鞋子。[有安排的首页](2026-11-25-小程序首页穿搭手账/01-有安排首页.png) · [无安排的首页](2026-11-25-小程序首页穿搭手账/02-无安排首页.png)

在 `apps/miniapp/` 运行 `npm test`，143 项全部通过，覆盖换日、封面失败与重试、账号切换及任务轮询。`npm run build` 完成类型检查、19 页路由、本地图片和 TDesign 依赖检查。最后一次构建的 29 份 WXML/WXS 和 27 份 WXSS 分别通过微信 `wcc` 与 `wcsc` 编译。

开发者工具首次打开隔离工程时模拟器启动失败。同步模拟器私有配置并指定已安装的基础库后，页面正常启动。已关闭隔离项目。以上操作使用本地测试数据，真机和线上服务联调仍待验证。

## 左侧日期入口复验

最终样式将日期、星期和下拉箭头放在同一个微信原生选日入口内。320px 和 390px 离线布局检查中，日期文字与页头标题左缘对齐，点击区高 44px。跨年日期、星期和箭头在 320px 下仍处于同一行。在构建产物中检查了 2027 年元旦和 2028 年闰日的日期及星期显示。调整后重新运行小程序测试，143 项通过，构建通过。

在 390px 微信模拟器中点开日期，底部出现微信原生年月日滚轮。点击「取消」后，首页保留「11月25日 周三」，没有发出业务请求。再次点开，将日期拖到 24 日并点击「确定」，首页显示「11月24日 周二」，仅请求该日安排的第一页。点击安排卡后，日历打开在 11 月 24 日。最终构建再次通过微信原生编译。[原生日期选择器截图](2026-11-25-小程序首页穿搭手账/03-原生日期选择器.png)

## 实际结果

| 操作 | 观察结果 |
| --- | --- |
| 打开隔离项目 | 新导入目录触发工作区信任提示，未继续。复用此前已导入的本地夹具目录后可编译运行。 |
| 编辑身高为 171，打开「尺寸历史」、展开第一条再返回 | 标题右侧入口可见；列表单独显示当前尺寸和两条历史，展开为只读字段。返回后身高仍为 171。 |
| 再次打开历史并使用第一条，随后取消 | 弹窗明确说明会替换未保存的输入。取消后当前尺寸摘要仍为 168，返回填写页仍为 171。 |
| 重复操作并确认 | 当前尺寸摘要更新为 164，返回后原表单同为 164。 |
| 最终构建：展开第一条并延迟应用返回 6.5 秒 | 「使用此记录」与「删除」同一行，明细为两列，无横向溢出。发出请求后立刻返回，表单先显示 168，成功后变为 164 并恢复可编辑。 |
| 最终构建：把夹具历史改为零条 | 当前尺寸摘要仍可见；历史区显示 0 条并提示通过「另存一条记录」创建。 |

以上是模拟器和隔离数据的代表路径，不计作正式回归。游客模式控制台有 `WAWorker.js` 权限探测及其错误上报提示，未阻止上述路径。分页失败重试、清空、删除及账号切换由代码测试覆盖；未在模拟器逐一操作，未单独度量滚动偏移。未做真机、真实接口联调或发布。已关闭隔离项目窗口并移除本轮生成的隔离构建目录。

## 2026-11-20 布局优化复验

依据[布局优化需求](../../02-需求文档/2026-10-30-微信小程序/01-需求说明.md#尺寸历史页布局优化)。微信开发者工具 Stable 2.02.2608080，基础库 3.18.0，iPhone 5（320×568）。开发者工具服务端口关闭，新游客项目导入返回系统错误 1。采用此前导入的游客项目，载入本次构建与本地接口替身。共有 26 条模拟快照，当前身高为 168 cm。

| 操作 | 实际结果 |
| --- | --- |
| 打开尺寸历史 | 顶部浅绿卡片突出当前尺寸，列表采用分隔线。完整记录摘要显示身高、体重和腰围，稀疏记录显示腰围和臀围，全空快照显示「未填写尺寸」。 |
| 打开长记录，滚动明细 | 记录时间与分组双列明细可读，滑到腿部和脚部时「使用此记录」仍固定在底部。 |
| 将历史列表滚到中段，打开并关闭 11 月 5 日的记录 | 关闭后各行仍在打开前的位置，列表顶部可见的完整日期仍为 11 月 7 日。 |
| 打开当前尺寸和记录详情的「···」，分别取消 | 菜单分别提供「暂不使用尺寸」和「删除记录」。取消后当前数值及历史总数保留，详情菜单取消后仍停在明细。 |
| 在填写页将身高改成 171 cm，应用 164 cm 快照后取消 | 确认框说明会替换未保存输入。取消后当前尺寸仍为 168 cm，返回表单仍保留 171 cm 草稿。 |
| 再次选择同一快照并确认 | 当前尺寸卡片和返回后的表单均显示 164 cm。 |
| 换成没有当前尺寸和历史的测试数据 | 显示「当前未使用尺寸」和「0 条」，保留另存记录的空态提示。 |

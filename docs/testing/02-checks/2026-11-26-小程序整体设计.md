# 小程序整体设计验证

2026-11-26，使用微信开发者工具 2.02.2608080、基础库 3.18.0 和 miniprogram-automator 0.13.0，在 iPhone 12/13 (Pro) 和 iPhone 5 模拟器上操作「设计 → 整体」。隔离工程加载本次构建，账号资料、照片、衣橱和生成接口由本地夹具提供。查看大图使用微信原生预览。[本次需求](../../02-需求文档/2026-11-13-小程序视觉优化/01-需求说明.md#2026-11-26-整体设计)

| 操作 | 实际结果 |
| --- | --- |
| 浏览示例并切换款式 | 资料未填写性别时，页面一次显示一款。点「男款」后切到对应的发型近景与全身图，没有新增业务请求。资料指定男款时只显示男款。「开始设计」随发型、穿搭、整体三个入口同排，390px 和 320px 宽度下均为 98×44px。[390px 整体造型](2026-11-26-小程序整体设计/01-整体造型.png) · [320px 整体造型](2026-11-26-小程序整体设计/04-窄屏示例.png) |
| 点「查看大图」，再关闭 | 微信原生预览显示男款的完整图片和 1/1 页码。关闭后回到「整体」，仍然选中男款。[微信原生大图](2026-11-26-小程序整体设计/02-原生大图.png) |
| 资料读取失败后重新加载 | 两款示例均可切换，页面提示暂时无法按个人资料匹配。恢复测试资料后点「重新加载」，只显示资料对应的女款。 |
| 开始整体设计并选图 | 无照片时，点击底部「添加本人照片」进入照片管理，未发出预检或生成请求。已提供全身照时默认选中，可改选头像再切回。草稿所选照片已删除时，点「选择本人照片」定位到照片区，重选后恢复「检查并继续」。首轮横框裁掉了全身照的头脚。改用竖向照片框后，390px 和 320px 下均能看全这张样例照片。[创建页](2026-11-26-小程序整体设计/03-设计创建.png) |
| 选择衣物、核对要求、返回修改 | 选择「针织开衫」，填写「保留自然发色，周五通勤。」后点「检查并继续」。确认单显示所选全身照、开衫和原文。返回修改后，三项选择都保留，生成请求数仍为零。 |
| 确认生成 | 两种宽度下各走完一次流程。每次发起两次预检，只在点击「确认生成」后发出一次创建请求，随后打开对应的模拟任务详情。320px 下确认按钮为 294×48px。[窄屏确认单](2026-11-26-小程序整体设计/05-窄屏确认单.png) |

小程序全量测试通过 162 项。构建通过类型检查、19 页路由和资源引用校验。微信原生工具编译了 30 份 WXML/WXS 和 28 份 WXSS。真机手势、真实照片上传和实际模型生成仍待验证。

## 点「开始设计」后的填写页

本轮从设计页点「整体 → 开始设计」，用同一组照片、21 件衣物在 390px 和 320px 模拟器各走完一次填写与确认。两次均从新草稿开始。照片失效和没有照片的场景另在 390px 核对。[填写页实施计划](../../02-需求文档/2026-11-13-小程序视觉优化/10-整体设计实施计划.md#填写页优化)

| 操作 | 实际结果 |
| --- | --- |
| 进入填写页，更换照片再选回 | 默认全身照以缩图和名称显示。点「更换」展开头像照与全身照，点任一张后立即收起并显示所选照片。390px 的缩图为 49×66px，320px 为 40×54px。首屏两个规格都能看到场景、风格、补充要求和搭配衣物入口。[390px 首屏](2026-11-26-小程序整体设计/06-填写页首屏.png) · [320px 首屏](2026-11-26-小程序整体设计/07-窄屏填写页.png) |
| 照片已删除，或账号尚无照片 | 草稿中的照片已删除时直接显示候选区，重选后收起。没有照片时点「添加本人照片」进入照片管理，两种情况均未发出预检或生成请求。 |
| 选择场景和风格 | 点「通勤」选中，再点一次清空。选「日常」和「简约」后，可分别切到「自定义」，输入「朋友的婚礼」和「复古学院风」。两种宽度下，每组四项各占一行，常用选项的点击区高 44px。 |
| 暂选单品、取消，再跨页完成选择 | 进入表单没有读取衣橱。首次打开面板请求第 1 页，暂选「针织开衫」时草稿仍为空。点「取消」后回到自动搭配。重新打开复用第 1 页，选开衫后滚动列表加载第 2 页，选中「浅蓝直筒长裤」。两次请求的 `pageSize` 均为 20。点「完成选择」后才把两件衣物写入草稿。320px 的固定完成按钮为 294×48px。[衣橱暂选](2026-11-26-小程序整体设计/08-衣橱暂选.png) |
| 预检、返回修改、确认生成 | 确认单逐项显示全身照、两件衣物、场景、风格和「保留自然发色，配一双平底鞋。」。返回修改后各项仍在，生成请求数为零。再次检查并确认后，模拟服务收到一次整体设计创建请求，照片、跨页单品和文字与第二次预检完全一致，随后进入返回的任务详情。[填写后确认](2026-11-26-小程序整体设计/09-填写后确认.png) |

在最终构建上另核对了请求次数。进入填写页时，测试账号有两张照片，首屏只读取默认全身照的缩图，首次展开候选区才读取另一张头像照。衣橱滚动到第 2 页后，在微信模拟器的选衣列表触发原生 `refresherrefresh` 事件，模拟刷新失败并点击「重试加载衣物」。记录到的请求页码依次为 1、2、1、1，刷新和重试后均保留暂选的开衫，草稿仍为空。本次通过组件事件验证刷新逻辑，真机下拉手势待验证。

穿搭模式也在同一模拟器打开了创建页。展开原有「必穿衣物」，点「针织开衫」后，选中状态和穿搭草稿立即更新，衣物列表仍在页内。

最终小程序测试通过 167 项，构建及微信原生编译通过，覆盖 30 份 WXML/WXS 和 28 份 WXSS。

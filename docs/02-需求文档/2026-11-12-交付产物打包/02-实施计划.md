# 交付产物打包实施计划

创建日期：2026-11-12。

依据：[需求说明](01-需求说明.md)与用户“可以，开始实施”的授权。目标为可拷贝的版本交付包，独立 Compose 使用已有镜像挂载程序运行，宿主机已有 Nginx 承接 HTTPS。主 agent 负责计划、协调、审查和整体验证，子 agent 执行实现与代码修复。

## 约束与共同契约

- 不改 Web 开发命令或已有开发 MySQL/Redis Compose 行为；不执行共享库迁移、供应商调用、远程发布或已有服务重启。
- server/web/MySQL/Redis 使用独立 Compose 项目和共同外部网络，默认 `lookmate`；网络别名分别 `lookmate-server`、`lookmate-web`、`lookmate-mysql`、`lookmate-redis`。仅 web 映射宿主机回环端口，默认18081，容器80。
- 应用源码 Compose 为 `apps/server/docker-compose.yml`、`apps/web/docker-compose.yml`。模板与说明放各自 `deploy/`；其 `.env.example` 设置 `LOOKMATE_VERSION=CHANGE_ME`，打包时改为交付版本。运行目录固定在目标组件目录，程序放 `releases/<版本>/`，与实际 config/runtime/data 分开。
- server 产物为 `releases/<版本>/lookmate-server.jar`，web 为 `releases/<版本>/dist/`。各 Compose 通过 LOOKMATE_VERSION 选择只读产物，实际配置及持久化路径使用模板中的明确路径；更换版本不覆盖实际配置和数据。
- MySQL/Redis 新增独立 `docker-compose.prod.yml`、`.env.prod.example`、`deploy/README.md`，复用已有 config。生产文件本身完整可用，打包时归集为组件的 `docker-compose.yml`、`.env.example`、`README.md`，不复制开发 Compose。
- ops 新增 `docker-compose.yml`、`deploy/.env.example`、`deploy/README.md`、`migrate-compose.sh`；只开放 info/validate/migrate，SQL 仍取 `ops/db/migrations/`。生产不依赖 Maven、Java 源码编译或开发 `.env.dev`。
- Flyway CLI未自带MySQL Connector/J；server/all包从已构建的Spring Boot JAR提取现有 `mysql-connector-j-9.7.0.jar` 到 `ops/drivers/`，迁移Compose单文件只读挂载至 `/flyway/drivers/`，不改变既有JDBC驱动行为。infra目标只收集中间件配置，不含ops。
- 使用固定补丁版本的 Java 21、Nginx 1.30.x、MySQL 8.0.45、Redis 7.4.11、Flyway 12.4.0 镜像，允许替换为经过核对的镜像地址或 digest；不得构建应用镜像或使用 latest。
- 交付包顶层 `lookmate-<版本>-<目标>/`，默认输出 `output/packages/`，附构建信息与 SHA256SUMS。只收集白名单文件，拒绝不安全版本字符串与已有输出覆盖。构建失败不发布交付包。

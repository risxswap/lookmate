# 基础资料与照片合并

创建日期：2026-10-27。页面合并及照片数量已确认；用户已授权开始实施。执行与验证状态见[实施计划](02-实施计划.md)。

## 目标与已确认范围

将“基础资料”和“我的照片”合并为“基础资料”，减少维护个人信息时的页面切换。照片不再采用大量图片的照片库展示，保留一张正面头像照、一张正面全身照和最多四张不同角度的补充照片，总数最多六张。补充照片可用于侧脸、背面或其他角度，不要求用户凑满。

沿用[个人资料需求](../2026-10-21-个人资料/01-需求说明.md)、[领域模型](../../01-项目总览/02-领域模型.md)和[首版需求](../2026-10-20-首版个人形象设计/01-需求说明.md)中未被本次明确调整的归属、私有访问及历史设计引用规则。

## 最新调整：上下分区与固定角度（2026-10-27，已授权实施）

本节替代下文历史左右布局和不分类补充照片方案。上方为头像和基础资料，头像改为右置，用户名、昵称、性别、出生日期在左侧两行排列；标签与控件统一对齐，收紧行距和上区留白（用户追加要求）。下方为照片区域，正面全身照居中，左侧上方侧脸、下方侧面全身，右侧上方后脑、下方背面全身。四个补充位始终占位并显示名称，全部选填。底部操作栏、照片即时保存及草稿保护保持不变。

固定角度需持久化，不能按照片时间或数组序号猜测。旧照片保持未分类，通过整理照片主动指定到空角度；已占角度不静默覆盖。保留服务端分页及存量容量约束，不删除或自动分类旧照片。

增量契约：Photo 增加可空 `angle`，取 `SIDE_FACE`、`BACK_HEAD`、`SIDE_BODY`、`BACK_BODY`；外部 photoType 保持原三类。`GET /api/photos/slots` 增加 `angles`（上述四键映射 Photo 或 null），既有字段兼容保留。`POST /api/photos/slots` 的 SUPPLEMENT 可带 angle，指定时原子新增或替换该角度（replacePhotoId 若传须匹配目标）；不传保留旧行为。`PATCH /api/photos/{id}/angle` 接收 version、angle，将本人非主要照片分配到空角度，200 返回 Profile 并递增版本；目标已占用返回409 `PHOTO_ANGLE_OCCUPIED`，非法角度或主要照片返回400，归属不存在返回404，版本过期返回409。所有写入沿用用户锁、原版本恢复及严格字段校验。

实现采用现有 user_photo.photo_type 的内部补充编码存储角度（字段 VARCHAR(16) 足够），DTO 对外映射为 REFERENCE 与 angle，REFERENCE 筛选包含全部角度编码。旧三类记录保持原样，不需表结构迁移；生成单图选择仍兼容。各写入口均不能产生同账号重复角度。

## 本轮实施边界

采用上述左右布局与局部保存方案。保留存量照片，不自动删除、重分类或覆盖；存在旧照片时提供整理入口，通过服务端分页查看并主动删除。主要照片沿用现有默认引用；补充照片取非主要照片，最多展示四张，超出部分明确提示并可在整理入口查看。无默认照片时不擅自替用户指定旧照片。

新增补充照片沿用 REFERENCE 存储编码，展示称为“补充照片”；不增加强制角度分类。既有参考图不迁走。补充照片继续通过现有设计选图入口单张选择，不新增多图生成或补充照片转主要照片功能。

主要照片上传或更换需原子保存照片与默认引用，补充照片更换原子替换记录；失败保留原图。后端在用户锁内检查容量，新增补充照片不得使非主要照片超过四张，全部新照片不得突破六张；存量超限时仍可查看、删除及等量替换，不自动清理历史数据。旧照片的历史设计引用继续保留。

增量契约与实现结果见下文，浏览器及 HTTP 证据见[验证记录](03-验证记录.md)。

## 增量接口契约

- `GET /api/photos/slots`：200 返回 `{version,portrait,fullBody,supplements,supplementTotal,total}`。两张主要照片为 Photo 或 null；supplements 是按创建时间、ID 倒序的最多四张非主要照片。计数包含存量照片，读取不改变默认引用。
- `POST /api/photos/slots`：必填字符串 `version`、`fileId`、`slot`（PORTRAIT / FULL_BODY / SUPPLEMENT）；仅 SUPPLEMENT 允许可选 `replacePhotoId`。主要照片替换当前默认照片；补充未传 replacePhotoId 时新增，传入时替换本人非主要照片。200 返回 Profile，版本递增一次。新增图片记录使用新 ID，删除旧照片记录但保留历史设计的独立文件引用。
- 非主要新增最多四张、总数最多六张；存量等量替换允许。旧 `POST /api/photos` 同样校验新增额度，保持其 Photo 响应和原版本语义。
- 原分页、详情、删除接口保留；整理入口按原页码查询。补充照片存储为 REFERENCE，原记录替换仍保留原类型。
- 容量冲突返回 409 `PHOTO_LIMIT_REACHED`；版本过期 409 `VERSION_CONFLICT`；非法 slot、字段或将主要照片作为补充替换目标为 400 `VALIDATION_ERROR`；他人或不存在照片 404 `PHOTO_NOT_FOUND`，文件归属/可用性沿用既有错误。所有写入先锁 user，并在同一事务检查容量、绑定新图、切换默认值、删除旧记录和递增版本。
- 网络响应不明时保留请求与版本，通过现有资料比较流程核对；重试沿用原版本，不能盲目生成新版本请求。上传成功不等于照片入库成功，页面单独呈现保存状态。

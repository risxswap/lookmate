# 个人资料

创建日期：2026-10-21。用户已授权实现个人资料前后端；本次细化沿用已确认的领域、表结构及公共契约。状态：前后端已实现并完成开发验证；真实七牛链路待联调。实施安排见 [实施计划](02-实施计划.md)。

## 范围与行为

实现个人资料页的基础资料、我的照片、身体尺寸三个标签，保留现有桌面布局、Ant Design 和深链接。基础资料可编辑或清空显示名称，用户名只读；保存后账号菜单同步。我的照片支持上传核验、按头像／全身照／参考图保存和筛选、分页、设置或清除默认头像及全身照、删除确认。复用已有七牛直传、文件核验与私有图片访问；未配置供应商时显示真实错误，不假报上传成功。

尺寸包含已确认的 27 项，单位、完整记录语义见 [接口契约](../../01-项目总览/05-接口契约.md#尺寸单位与数值)。每次保存新增历史并设为当前，可从当前值填写新记录、切换历史或清空当前引用。允许全部留空；历史不原地编辑。删除当前记录清空引用，不自动选择其他历史，不更改旧设计快照。页面提供分组、单位及测量位置说明。

资料编辑、默认照片、尺寸新增／切换／删除及照片删除使用同一个资料 version；冲突保留输入，提示刷新并比较服务端值后重试，不自动覆盖。新照片入库不修改资料默认引用，不递增资料版本。所有资源只允许本人访问；先锁 user 的短事务维护关联，图片外部操作仍在事务外。

## 本次接口契约

沿用 data/requestId 包装、UTC ISO 时间、字符串 ID 与版本、CSRF、未知字段拒绝及页码分页。具体资源不存在或属于其他账号返回 404。所有写请求为 JSON 对象。读取返回 null 表示未设置，不用空对象替代。

Profile：`id, username, displayName, version, currentMeasurementId, currentMeasurement, defaultPortraitId, defaultFullBodyId`。Measurement：`id, createdAt, updatedAt, current` 及 27 项扁平数值字段（全部可空）。Photo：`id, fileId, photoType, createdAt, updatedAt`。photoType 固定 `PORTRAIT / FULL_BODY / REFERENCE`。

| 方法与路径 | 请求 | data 与状态 |
| --- | --- | --- |
| GET /api/profile | 无 | Profile，200 |
| PATCH /api/profile | version 必填；displayName 未传保持，null 清空；字符串去首尾空白后 1～64 Unicode 码点，空串拒绝 | Profile，200 |
| GET /api/profile/measurements | page、pageSize | Page<Measurement>，200 |
| POST /api/profile/measurements | version 必填及 27 项可选尺寸；未传为 null | `{measurement, profile}`，201 |
| PUT /api/profile/current-measurement | version、measurementId 必填；后者可 null 清空 | Profile，200 |
| DELETE /api/profile/measurements/{id} | version 必填 | null，200；前端刷新 Profile 与列表 |
| GET /api/photos | page、pageSize、可选 photoType | Page<Photo>，200 |
| POST /api/photos | fileId、photoType 必填 | Photo，201 |
| PUT /api/profile/default-photos | version 必填；portraitId、fullBodyId 未传保持、null 清空 | Profile，200 |
| DELETE /api/photos/{id} | version 必填 | null，200；前端刷新 Profile 与列表 |

尺寸非空值接受 JSON 数字，必须大于 0、最多两位小数且不超过 DECIMAL(6,2) 存储上限 9999.99；本轮不增加未经确认的生理范围限制。拒绝字符串数值、布尔值、未知字段。默认照片必须是本人且类型匹配的照片；绑定文件仅允许本人核验通过且未过期或待清理的文件，TEMP 入库转 READY 并清除临时到期时间。删除照片只移除照片引用、清除匹配默认引用并交由已有文件清理流程复查全部引用。

错误：400 `VALIDATION_ERROR`（请求字段／类型／尺寸值／版本不合法），分页和路径编号沿用 `INVALID_REQUEST`；409 `VERSION_CONFLICT`；404 `MEASUREMENT_NOT_FOUND / PHOTO_NOT_FOUND / FILE_NOT_FOUND`；409 `FILE_NOT_USABLE`；其余认证、CSRF、存储不可用沿用已有模块。版本缺失或类型不合法为 400，过期为 409。版本为非负十进制字符串，成功的资料写操作递增；达到 Long 上限拒绝继续写入。

## 验收

- 名称保存／清空持久化并同步账号摘要；未传字段保持，未知字段拒绝。
- 27 项尺寸保存回显；空值、全空、两位小数、非法数值、历史切换／删除、分页正确；旧任务快照保持。
- 照片分类分页、归属和文件状态检查正确；默认类型检查、清空及删除默认引用正确；历史设计文件引用保留。
- 两个并发过期版本写入只能一个成功，失败不留下部分数据；跨账号查询或写入拒绝。
- 前端加载、失败重试、空状态、提交防重复、删除确认、冲突输入保留及刷新比较可用；401 沿用登录流程。
- 后端构建与真实隔离数据库测试、前端构建、实际 HTTP 响应与浏览器交互验证分别记录。真实七牛未配置时明确记录上传成功链路未验证。

不包含设计任务提交、模型调用、生产部署或既有开发库迁移。未更改首版业务规则、表结构及依赖版本。

## 2026-10-24 我的照片交互优化讨论草案

用户要求移除“刷新图片”按钮，并讨论其他按钮、信息与页面布局的优化。本轮仅调查和讨论，未修改实现；下列建议尚未确认，不替代现行行为。依据为当前源码、既有照片刷新截图及联网查阅的官方资料，未重新登录查看当前完整照片库。

建议采用照片网格：顶部为“全部／头像／全身照／参考图”分段筛选及一个“添加照片”主按钮；照片完整显示在统一尺寸的浅色画框中，点击预览，默认照片用简短角标标识。设置或取消默认、删除收进照片的更多菜单，删除保留确认。成功操作后自动更新；移除常驻图片刷新按钮，仅加载失败时提供重试。是否同时移除页面级“刷新我的照片”待确认。服务端分页保留，只有一页或无照片时隐藏分页控件。

上传建议为选择照片、核对缩略图与类型，最后统一“添加到照片库”。替代每张照片一个长名称保存按钮；逐项显示进度与结果，部分失败保留失败项供重试，不重复保存成功项。另一候选为选定类型后上传成功自动入库；该方案改变保存时机，需用户确认。新增照片仍不自动成为默认照片。

空状态建议为简短用途说明与添加入口；格式和大小限制放在上传区域。错误及成功反馈沿用 Message／Notification。此次不提议图片裁切、抠图或修改原图。

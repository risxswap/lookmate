## 已确认范围

frp 作为基础设施中间件管理，客户端 frpc 与服务端 frps 放在同一个 `infra/frp/` 目录中。目录共用不表示两个进程部署在同一机器：frps 位于公网节点，frpc 位于开发机器。

本次用于小程序开发调试，让小程序访问本地后端；不包含 Web 外网访问或生产部署。内网端在 `.vscode/launch.json` 中增加启动配置，仅调试时启动，不要求常驻。

用户已确认公网侧已有直接运行在宿主机上的 Nginx、可用域名和 HTTPS 证书。后续方案可复用该入口，实际域名和端口尚未提供。

## 已实施方案

本机直接运行 frpc，转发到本地后端；公网 Nginx 负责 HTTPS，经过 frps 和隧道访问 frpc。frps 的业务映射端口仅供入口 Nginx 访问。隧道使用认证与 TLS，业务权限仍由后端校验，不开放数据库或 Redis。

launch.json 新增独立的“启动 frp 隧道”入口，按需再考虑与“启动后端”组合启动。建议 frpc 前台运行，停止该调试入口时结束隧道；实施时验证进程清理行为，不使用脱离调试会话的后台常驻方式。

frps 以 Compose 运行，本机 frpc 使用原生二进制。配置、启动脚本和说明统一维护在 infra/frp，使用官方 v0.71.1，可信 Bash 环境配置注入参数，凭据不提交仓库。

针对宿主机 Nginx，建议 frps 使用容器桥接网络：连接端口按需发布供 frpc 连接；业务映射端口只发布到宿主机回环地址，由 Nginx 转发到该地址。示例为 Nginx → 127.0.0.1:18080 → frps 容器映射端口 → frpc → 本机 127.0.0.1:8080，其中 18080 仅为示例。容器内监听地址须允许 Docker 端口转发，不能把容器回环地址与宿主机回环地址混用。

# 发型专区页面与交互设计

日期：2026-10-30。状态：用户已授权实施，页面代码与代表路径验证完成。业务范围以[需求说明](01-需求说明.md)为准，实际验证范围见[开发验证](../../testing/02-checks/2026-10-30-发型独立专区.md)。

## 页面组织

沿用桌面端、现有侧栏、浅色背景、绿色强调色与 Ant Design 组件。侧栏新增“发型设计”，专区内用“发型图库 / 我的发型记录”切换主要内容。试发型是从图库或“AI 自由设计”进入的任务页面，不增加必须先选择模式的中间页。

| 页面 | 主要区域 | 主操作 |
| --- | --- | --- |
| 发型图库 | 页头、全部款式/已收藏、长度/刘海/卷直筛选、图片卡片、分页 | 查看款式并试用 |
| 款式详情抽屉 | 正侧背参考图、名称与特征、造型和打理说明 | 试这个发型；收藏款式 |
| 试发型 | 目标参考或自由设计要求、本人照片、本次条件 | 继续，确认设计 |
| 我的发型记录 | 状态筛选、记录卡片、分页 | 查看进度或结果 |
| 设计详情 | 任务状态、效果图与原图对照、目标参考、理发与打理建议 | 收藏效果、调整后再试 |

图库页头右侧提供“AI 自由设计”。试发型页显示“返回图库”以及当前方式；结果详情根据进入来源返回专区记录或统一记录，直接访问且无来源时回到相应类型的记录列表。菜单高亮与进入来源一致，不因复用详情组件而跳到另一个菜单。

## 图库与款式收藏

浏览和收藏无需本人照片。全部款式和已收藏共用长度、刘海、卷直筛选，切换范围或修改筛选回到第一页；详情关闭后保留筛选、页码、滚动位置和触发焦点。

图库占据完整内容宽度，不常驻本人照片表单。宽桌面建议四列，中等桌面三列、窄桌面两列，按实际可用空间收缩；保持头发轮廓完整，不用裁切填满图片框。图片下方展示名称与两三个特征，保留 AI 示意标识，不增加未经验证的适合度评分。

点击图片或名称打开详情抽屉。收藏按钮与详情触发区使用独立按钮，不能嵌套按钮；收藏操作不打开详情。收藏状态有文字或可访问名称，不只用颜色区分。抽屉内看正、侧、背参考图，底部提供主按钮“试这个发型”和次按钮“收藏款式 / 已收藏”。

收藏操作期间仅禁用当前款式的重复操作。请求成功后同步卡片和抽屉；失败恢复原状态并提供重试。已收藏视图中取消收藏成功后移除条目；若当前页变空，重新核对 total 并回到最后有效页。首期不增加批量管理或款式收藏分组。

全部款式只展示可用款式，已收藏保留已下架条目，显示文字标记并禁用试用，允许取消收藏；封面资源不可用时用占位图与款式名称表达，不导致整页失败。款式收藏只对当前账号可见。

图库和收藏均采用服务端 page、pageSize、items、total，使用 Ant Design Pagination；不全量拉取后切片。图库沿用默认12条和6/12/24页容量选项。

## 试发型

从详情点击“试这个发型”后进入专用试发型页，携带款式与版本。左侧主要展示目标参考图及多角度切换，右侧放本人照片与本次条件；窄桌面改为纵向布局，保证确认按钮可到达且不遮挡内容。相比现有图库与表单同屏，这是本轮拟议布局变化。

右侧顺序为：本人照片、默认不勾选的“同时尝试参考发色”、“想调整的地方”、折叠的更多条件、确认按钮。预选默认头像，允许从照片库更换或临时上传；沿用一张本人照片及临时上传不自动入库的规则。照片读取失败不阻止浏览，提供手动选择。

“更换款式”返回图库选择状态，保留本人照片及补充要求；只有点击试用新款式才替换目标，单纯浏览或收藏不改变草稿。换款后参考发色选项重置为不勾选，单次限制例外清除，避免把旧款式授权带到新款式。

AI自由设计使用同一任务页面：主区域填写想法与风格，旁边显示本人照片和提交操作，不展示目标款式或参考发色开关。两种方式各自保留要求草稿，切换时共享本人照片，清除旧的单次限制例外；自由设计提交不携带图库目标。

确认弹窗沿用现有核验流程，集中展示本人照片、目标、本次要求和发色选择。输入不足时在对应区域说明原因；资料冲突、款式变化或下架时保留输入并提示处理，不能自动改用另一款。提交成功进入任务详情，允许离开页面后在记录中继续查看。提交响应未知时保留原提交编号，查询原提交，不自动再创建一笔任务。

## 返回与草稿

已确认普通编辑草稿在站内导航期间保留，首期不做刷新恢复或跨设备同步，待确认提交继续保留原编号用于找回。实现限定于当前登录账号、本浏览器页签；图库筛选、分页与主栏目通过地址及现有页面状态机制恢复，刷新时有未提交修改使用浏览器支持的离开提示。个人照片与草稿内容不写入 URL。

站内去图库、记录或其他菜单后再返回，应能继续未提交编辑，不反复弹离开确认。新款式替换仅改变目标，保留当前图库方式的其他输入；“调整后再试”若将覆盖已有编辑草稿，先提示用户继续原草稿或使用历史输入。

已有“提交结果待确认”的恢复记录与普通草稿分开管理，沿用原恢复机制，不因刷新、切换栏目或清理普通草稿丢失原提交编号。退出登录、切换账号时清除当前编辑状态，防止跨账号回显。提交成功只清理对应已提交草稿，后续调整创建新任务。

## 我的发型记录与结果

固定查询发型类型，不再显示设计类型筛选；保留现有状态筛选、刷新和服务端分页。卡片显示原有任务名称、时间、状态及结果缩略图，没有效果图的任务不以图库示意图冒充生成结果。

成功详情展示原图与效果图对照、提交时目标快照、理发要点和打理建议；明确区分“收藏效果”和图库中的“收藏款式”。前者沿用现有方案收藏与收藏夹机制。专区首期不增加另一套效果收藏管理页，已有统一收藏继续作为管理入口。

操作仍以服务端 actions 为准，不根据状态名称自行推导可重试或可删除。专区与统一记录复用同一任务身份；收藏、删除及隐藏操作后刷新相关列表，重新进入时再次读取服务端状态。两个入口不会各自创建任务副本。

## 款式版本与下架

已确认：收藏显示最新版本、历史保留快照、下架前已接受任务继续执行、下架后不能基于该款式创建或重试任务。下表中的编辑提示及并发核验方式仍为实现建议。

| 场景 | 建议行为 |
| --- | --- |
| 收藏的款式更新 | 收藏指向款式，浏览展示当前版本；历史设计仍展示提交时版本 |
| 编辑期间款式更新 | 提示“款式已更新”，重新查看并确认最新款后继续，不静默替换 |
| 确认后、提交前下架 | 提交时再次核验并拒绝新任务，保留照片与要求，允许另选款式 |
| 已接受任务执行期间下架 | 按接受时快照继续执行；下架只影响新试用 |
| 下架款式的历史重试 | 若创建新任务则要求更换可用款式或主动切换自由设计；不自动去掉参考图 |
| 已产出图片的内部保存恢复 | 继续保存原结果，不按新试用处理 |

这里的下架指普通图库维护。具体重试模式和供应商限制需在技术契约中核对，不在本轮变更既有UNKNOWN状态或擅自重发外部请求。

## 空态、失败与可访问性

| 状态 | 页面反馈与下一步 |
| --- | --- |
| 无收藏 | “还没有收藏的发型”，提供“去看看款式” |
| 筛选无结果 | 保留条件并提供“清除筛选” |
| 无发型记录 | 提供“去挑选发型”和“AI自由设计” |
| 图库或详情加载失败 | 就地重试，不误显示空列表；已有数据显示刷新失败提示 |
| 无本人照片或上传未完成 | 明确缺失项，禁止继续确认，图库与收藏仍可使用 |
| 供应商不支持所需参考图 | 展示现有不可用原因并保留输入，不丢弃参考图强行提交 |
| 图片加载失败 | 占位和重试，保留名称、状态与其他可用操作 |

使用现有字体、颜色、间距和组件约定，绿色集中用于选中状态与主操作。按钮有明确名称和键盘焦点；弹窗和抽屉关闭后恢复焦点。检查800、1024、1280、1440宽桌面及长名称、多角度图片、窄窗纵向布局，不增加移动客户端范围。

## 后续验证清单

实现后验证：收藏与取消在卡片/抽屉/已收藏间一致；筛选分页和返回位置恢复；选款/自由设计草稿隔离；重入、刷新、退出账号行为；待确认提交不重复创建；旧发型入口与旧详情可达；专区和统一记录同步；下架及版本变化的待确认边界；键盘操作与窄桌面布局。

设计阶段依据现有组件与需求形成静态方案，随后已实施正式页面并完成代表路径验证。导航参考 ui-ux-pro-max 的 Active State 和 Deep Linking 通用规则；不直接采用其移动端返回建议作为桌面产品规范。

## 本轮可点击线框

2026-10-30 补充可点击线框，在会话中展示图库、收藏筛选、款式详情、试发型、确认及模拟记录。图像使用明确标注的占位，不是正式素材或最终视觉稿；线框仅展示部分筛选，详情以展开区域代替正式抽屉，不作为控件实现依据。没有真实上传、生成、分页接口或数据库写入。

已在本地浏览器走通收藏→已收藏筛选→查看款式→试这个发型→选择示例照片→输入要求→确认→模拟记录，并检查图库布局。脚本语法检查通过。这些结果只证明线框的代表操作可用，不替代产品验收、服务端测试或正式多尺寸视觉验证。

对应接口、路由、收藏表及历史兼容方案见[接口与数据设计](03-接口与数据设计.md)。后续已实施正式功能，以上线框验证仅为设计阶段记录。


## 卡片样式统一

图库使用Ant Design Card hoverable、cover、Card.Meta与actions，与穿搭图库统一标题留白、标签和操作区。悬浮封面、正文或收藏区均作用于整卡阴影，封面按钮不单独描边；图片和标题键盘可达，收藏按钮独立。保留发型1:1图片框及完整轮廓、原有三视图详情。

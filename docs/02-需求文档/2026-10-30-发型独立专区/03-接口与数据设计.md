# 发型专区接口与数据设计

日期：2026-10-30。状态：已按用户授权实施并完成隔离开发验证，业务规则见[需求](01-需求说明.md)。V9迁移仅执行于独立测试库；文中JSON仍为契约示例，实测证据见[开发验证](../../testing/02-checks/2026-10-30-发型独立专区.md)。

## 实施前基础与本轮边界

- `HairstyleController` 提供登录后的图库列表、详情及版本图片；`HairstyleCatalogService` 从项目资源读取当前版本，列表过滤 active，旧资源服务于历史快照。
- `design_favorite` 关联完整成功方案的 result_id，不能直接表示尚未生成的款式收藏。
- `GenerationService` 创建任务时核验款式版本；重试复用原快照，需要补充当前款式可用性核验，但不能用最新款式覆盖原重试快照。
- 前端已有统一导航、按账号和历史条目保留列表状态的 `usePageState`、提交恢复记录及生成组件；普通编辑草稿需要提升到专区之外的账号级内存状态，以承受站内卸载重挂载。

继续使用现有 server/web 与 Controller → Service → Mapper 分层。图库继续随项目发布，不引入运营端、在线图库编辑或独立发型服务。新增一张用户款式收藏表，复用设计任务、详情、文件和效果收藏。

## 路由与前端状态

| 路由 | 内容与兼容 |
| --- | --- |
| `/app/hairstyles` | 图库默认入口；scope=all/favorites，筛选及page/pageSize进入查询参数 |
| `/app/hairstyles/try` | 试发型；path=gallery/free，图库初次进入可带hairstyleId和hairstyleVersion |
| `/app/hairstyles/records` | 固定HAIRSTYLE类型的任务记录；沿用状态筛选和分页 |
| `/app/designs/{id}` | 继续作为唯一任务详情地址；from=hairstyles仅作为导航来源提示，不影响权限 |
| `/app/design/new?type=HAIRSTYLE` | 替换导航到发型专区，避免返回时反复跳转 |
| `/app/design/new?from={id}` | 读取并校验本人任务后按实际类型进入发型调整页或原设计页，不能丢失来源 |

旧入口同时携带type和from时，以经过权限校验的来源任务类型为准。保留必要场合输入但不复制未知查询字段；详情来源参数采用有限枚举，不接收任意外站返回地址。浏览器返回沿用项目导航历史；无历史时发型详情返回专区记录，其他类型返回统一记录。

列表缓存与收藏状态均带accountId；当前页批量读取收藏状态，避免逐卡查询。收藏成功更新列表与详情缓存，并失效已收藏列表；任务操作失效专区与统一记录的相关查询。重新进入和窗口重新聚焦时读取服务端结果，不承诺跨设备即时推送。

普通草稿使用账号隔离的内存容器，保存图库/自由设计两份输入和共享本人照片引用，不写localStorage、sessionStorage或URL，不将整个页面永久隐藏挂载。退出及换账号清空；待确认提交仍使用现有独立恢复记录。切换方式或目标清除旧单次限制例外。

## 图库与款式收藏接口

全部接口继承[通用契约](../../01-项目总览/05-接口契约.md)：登录与CSRF、严格字段校验、字符串ID、UTC时间和统一响应。用户身份来自会话，不接受userId。设计任务状态与actions不另造一套。

| 方法与路径 | 入参 | 成功响应 |
| --- | --- | --- |
| `GET /api/hairstyles` | 原page/pageSize/length/bangs/texture；新增scope，缺省all，仅all/favorites | 200，原PageDto；all只返回可用款，favorites包含已下架收藏 |
| `GET /api/hairstyles/{id}` | 稳定款式ID | 200，原详情加账号收藏状态；下架款对持有该收藏的当前账号返回不可用详情，无收藏则保持404 |
| `PUT /api/hairstyles/{id}/favorite` | 无请求体，不接受版本或其他字段 | 首次201、重复200；data为hairstyleId、favorited=true、favoritedAt |
| `DELETE /api/hairstyles/{id}/favorite` | 无请求体 | 200，data:null；本人未收藏也成功，不因款式已下架而拒绝 |

PUT要求款式当前可用。同账号同款只保留一条，重复PUT不修改收藏时间或排序；DELETE后重新PUT作为新收藏。下架时重复PUT也返回不可用错误，不把幂等解释为绕过可用性规则。

### 读模型增量

原款式详情字段及images保持兼容，增加以下字段：

| 字段 | 类型与含义 |
| --- | --- |
| availability | 必填字符串，AVAILABLE / UNAVAILABLE |
| favorited | 必填boolean，仅当前账号的状态 |
| favoritedAt | UTC时间字符串或null，未收藏时null |

可用款式展示当前目录版本。下架或从新目录移除的收藏使用保存时的展示快照，并明确availability=UNAVAILABLE；图片不可读可降级为images空数组，前端显示名称与占位，不能把异常标为可用。新增字段不可写回设计输入；服务端继续自行加载可信款式数据。

scope=all沿用平台目录顺序；scope=favorites按收藏created_at、id倒序。page默认1、pageSize默认20且最大100；界面主动传12。筛选在服务端分页之前完成，items和total使用完全相同条件。已下架收藏的筛选使用其展示快照，可用款式使用当前特征。

### 错误与前端处理

| HTTP / code | 场景 | 页面处理 |
| --- | --- | --- |
| 400 VALIDATION_ERROR | 非法筛选、分页、scope、ID格式或不允许的请求字段 | 标明输入问题，不自动扩大查询 |
| 404 RESOURCE_NOT_FOUND | 不存在的款式；下架且当前用户无该收藏 | 返回图库，保留普通输入 |
| 409 HAIRSTYLE_UNAVAILABLE（新增） | 新收藏、提交或重试的款式已下架 | 更新不可用状态，允许换款或取消收藏 |
| 409 HAIRSTYLE_CHANGED（已有） | 编辑使用旧版本而当前款式已更新 | 展示更新提示，重新选定当前版本后预览 |
| 503 HAIRSTYLE_CATALOG_UNAVAILABLE（已有） | 当前目录未成功加载或结构损坏 | 显示暂不可用，可重试；不能把整个图库误判为下架 |

其余认证、限流、维护、生成预算与依赖错误沿用原规则。收藏失败不展示成功状态；列表刷新失败可保留已有内容，但提示其非最新数据。

## 新表建议：hairstyle_favorite

只表达当前账号收藏的稳定款式，不关联design_result，不复用favorite_folder。所有字段必填且无默认值，由应用写入；id按项目约定自增。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | BIGINT AUTO_INCREMENT | 主键，对客户端如需暴露则为字符串 |
| user_id | BIGINT | 归属账号 |
| hairstyle_id | VARCHAR(64) | 现有小写字母、数字和连字符款式标识 |
| display_snapshot | JSON | 收藏时的展示信息，仅用于当前款式不可用时回显 |
| created_at | DATETIME(3) | 首次收藏时间，UTC |
| updated_at | DATETIME(3) | 创建时与created_at一致，重复收藏不刷新 |

主键id；唯一索引`(user_id, hairstyle_id)`；列表索引`(user_id, created_at, id)`。InnoDB、utf8mb4_bin，无外键，取消收藏物理删除关联行，不删除图库资源或设计任务。

display_snapshot由服务端生成，包含name、version、length、bangs、texture、description、careAdvice及图片ID/角度/资源路径。只保存元数据，不复制二进制、本人照片、密钥或签名URL；当前字段长度及图片数量沿用图库校验。其语义为“收藏时展示信息”，不宣称是下架前最后版本。可用时始终从当前目录展示最新内容，历史设计继续使用各自任务快照。

稳定hairstyle_id跨版本保持同一款式含义，不得复用旧ID给完全不同款式。目录下架可使用active=false或从当前目录移除；发布时保留历史版本资源。当前目录应在开放流量前验证唯一ID、枚举与资源完整性，坏目录失败不能成为批量下架。

## 查询与事务

全部款式列表继续在服务端对有界平台目录筛选分页，仅为当前页ID批量查询该用户收藏，不拉全量用户收藏给前端。

已收藏列表由SQL对当前用户执行COUNT与LIMIT/OFFSET。为兼容资源目录，服务端从当前目录构造两个集合：全部可用ID、满足筛选的可用ID。SQL条件为“ID属于筛选命中集合，或ID不属于全部可用集合且display_snapshot特征满足筛选”。空集合显式改写逻辑，不能生成IN()。分页后只为当页条目补齐当前目录或快照展示。COUNT和列表在同一只读事务使用相同目录快照和条件。

目录目前48款，平台ID集合有界；这一设计不会读取全量用户收藏再分页。未来目录扩大到影响SQL参数量时再评估投影表，首期不引入第二张目录表。JSON条件仅用于下架条目的有限回显路径；实施时用真实分布和EXPLAIN核对，不声称已验证性能。

收藏写入短事务先锁user，再查当前账号的款式收藏；核验目录可用后插入，唯一约束兜底。取消收藏也先锁user，只删除当前账号匹配行。资源描述、图片摘要等准备在事务外完成，事务内不读大图片、不调用外部供应商。正常目录在单进程生命周期内不可变，发布重启切换版本，不增加热更新并发协议。

## 任务准入与历史兼容

创建、预览继续校验当前款式与版本。重试FULL及IMAGE_ONLY都会创建新任务，因此均核验原hairstyleId当前可用；可用时仍复用旧快照，不静默切成最新款式。下架时返回HAIRSTYLE_UNAVAILABLE，actions同步不提供原样重试；“调整后再试”可带入照片和要求，但阻止提交失效目标，要求主动选新款或切自由设计。

已接受任务执行与保存恢复只读自己的快照，不因为当前目录下架而拒绝执行。原提交编号找回、同键同输入重放应先定位已接受任务；即使之后下架，也返回原任务而不是重复创建或误报新试用被拒绝。新提交键及首次重试键仍受当前可用性限制。保留UNKNOWN不自动重发原则。

既有无目标款式的自由设计不受图库下架影响；整体设计与穿搭流程不增加图库输入。历史详情仍通过版本资源查看原图，效果收藏机制不变。

## 迁移与验收准备

只需新增收藏表迁移，不回填既有design_favorite；旧库没有款式收藏数据。当前工作区最高迁移为V8，实际实施前重新检查并分配下一个未占用版本，不能预占或改写已发布迁移。由ops显式执行，server只检查结构兼容性；本轮不生成或执行SQL。

实施验收需覆盖：账号隔离、重复收藏与并发取消、下架回显、筛选后分页与total、末页取消、目录损坏503、版本更新、两种重试模式下架拒绝、已接受任务继续与幂等找回、列表同步、草稿和旧链接。真实模型还原效果单独联调，不能以本轮图稿或模拟响应代替。

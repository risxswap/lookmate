## 账号流程

### 已确认

- 新用户通过微信登录创建账号，无需先设置用户名和密码。
- Web 增加微信扫码登录，微信用户不必为了使用 Web 补设密码；替代此前“需要 Web 时补设用户名和密码”的建议。
- 两端登录同一业务账号，共用衣橱、照片、设计记录等业务数据。
- 保留现有用户名密码登录，作为老用户入口，与新增微信扫码登录并存；微信新用户仍无需设置密码。
- 本次不清理原账号，不自动合并账号；旧账号绑定流程及冲突拒绝规则见下文，接口与并发处理待设计。

### 首次微信登录（已确认）

用户已确认微信身份尚未关联业务账号时展示两个入口：

- 新用户，直接开始：用户主动选择后创建业务账号，不填写用户名和密码。
- 已有账号，绑定登录：验证原用户名和密码，将微信绑定到原账号，继续使用原有业务数据。

已关联账号的微信身份直接登录对应账号，后续无需重复选择。未关联身份仅完成微信身份核验时不自动创建业务账号，避免老用户尚未选择绑定就产生空账号。绑定冲突、重复操作及并发处理待细化。

### 微信绑定关系（已确认）

用户已确认一对一绑定：一个业务账号最多绑定一个微信，一个微信只能关联一个业务账号。原账号已绑定其他微信时，拒绝本次绑定并提示原因，不覆盖原绑定，不合并账号或业务数据。现有未绑定微信的用户名密码账号可以继续存在并使用密码登录。

该约束须由服务端在并发绑定时保持；数据库约束与事务方案尚未设计。首版已确认不提供微信解绑和换绑，只展示绑定状态；后续如需支持，另行设计身份验证和账号恢复流程。

### Web 扫码登录确认（已确认）

用户已确认以下交互流程：

1. Web 展示登录码，用户用微信扫描后进入小程序。
2. 小程序展示“登录 Lookmate 网页版”和当前账号，提供“确认登录”和“取消”。
3. 用户明确点击确认后，原浏览器登录；仅扫码不自动登录。
4. 微信尚未关联账号时，先完成上述注册或绑定流程，再返回登录确认页，不因注册或绑定成功自动批准 Web 登录。

确认与浏览器领取结果仍须验证登录请求有效性；注册或绑定期间请求过期时不得继续建立 Web 会话，有效期与过期恢复规则见下节。本次确认小程序承接扫码确认的产品流程，小程序码接口、权限和技术实现仍待核验，未实施或验证。

### 登录码有效期（已确认）

用户已确认登录码有效期为生成起 5 分钟，扫码后不延长。过期后 Web 显示“登录码已过期”，用户点击刷新生成新码；刷新后旧码立即失效，不能再确认登录。

注册或绑定过程中登录请求超时，保留已完成的账号操作，提示重新扫码；不能因此自动回滚注册、解除绑定或通过过期请求建立 Web 会话。确认及领取时均校验请求有效性，不能只依赖客户端倒计时。具体接口与并发实现仍待设计。

### 取消 Web 登录（已确认）

用户已确认，在手机端点击“取消”后，本次登录码立即失效，Web 显示“已取消登录”；再次登录需点击刷新，生成新码。

取消只影响本次 Web 登录请求，小程序保持登录，已完成的注册或绑定保留。取消与确认、领取并发时的状态转换及错误契约待技术设计细化，不据此推定可以撤销已建立的浏览器会话。

### Web 登录页入口（已确认）

用户已确认 Web 登录页设置“微信扫码”和“账号密码”两个页签，默认显示“微信扫码”及登录码；“账号密码”保留现有用户名密码登录和注册入口。该调整尚未实施，现有页面不代表已支持扫码。

### 小程序访问边界（已确认）

用户已确认首版不提供游客浏览模式，全部业务功能登录后使用。未登录进入小程序先显示登录页，常规登录成功后进入首页；从 Web 扫码进入时，完成登录后返回扫码确认页，继续遵守有效期与明确确认规则。

衣橱、个人资料、设计记录等仍按账号隔离；登录入口不代表开放其他业务资源。公开平台图库的未登录浏览也不纳入首版。小程序不提供主动退出登录；会话恢复方式按下文已确认规则执行。

### 小程序不提供退出登录（已确认）

用户已明确小程序不需要退出登录，首版不提供该入口，替代此前“我的”页账号设置中包含退出及当前会话退出的建议。Web 原有退出登录功能保留。

不提供退出入口不等于会话永久有效或免于服务端身份校验。会话恢复规则见下节；账号不可用、微信身份变化及重新登录失败的具体提示仍需设计，首版不支持解绑、换绑的决定保持。

### 小程序登录状态恢复（已确认）

用户已确认打开小程序时，已有会话有效则直接进入；会话过期时尝试通过微信身份自动恢复登录。自动恢复失败或微信身份尚未关联业务账号时进入登录流程，不无提示地创建账号或绑定旧账号。

恢复后查询原任务进度，不自动重复提交生成请求。该规则不等于自动重放其他失败的业务写请求；Web 扫码进入仍按专门流程返回确认页。自动恢复必须由服务端重新核验身份及账号有效性，不能仅凭客户端缓存的账号信息建立会话。会话期限及重试限制见后续已确认规则，并发恢复实现待设计。

### 新用户资料补充（已确认）

用户已确认首次常规登录后直接进入首页，不增加强制完善资料流程。浏览图库、录入衣物时不要求先填完整个人资料；各业务操作本身的必填要求继续沿用。

发起设计时按具体模式检查所需本人照片和衣橱条件，不满足时提示补充。昵称、偏好和身体尺寸等保持选填，不增加首次登录必填项。Web 扫码进入仍优先返回扫码确认页，不被资料引导中断。

### 小程序会话有效期（已确认）

用户已确认小程序登录会话有效期为登录成功起 30 天，普通访问不延长该期限。到期后按已确认流程通过微信身份重新核验并自动恢复，建立新的会话；恢复失败或身份未关联时进入登录流程。

服务端始终校验账号状态，账号不可用时不能恢复登录。Web 沿用现有会话期限，不随本次决定调整。30 天是应用登录凭证有效期，不代表微信侧凭据具有相同期限；具体凭证实现仍待设计。

### 修改密码后的会话与微信绑定（已确认）

用户已确认老账号修改密码后，已有 Web 和小程序会话全部失效，微信绑定关系保留。小程序可重新核验微信身份并自动恢复登录；Web 可重新扫码或使用新密码登录。

修改密码撤销旧会话，不撤销已绑定微信的登录资格。会话失效继续沿用既有语义：当前会话在改密成功后结束，其余旧会话在后续请求时拒绝，不承诺撤回已经执行中的请求。恢复必须新建有效会话，不能重新启用旧凭证。

### 自动恢复登录的重试（已确认）

用户已确认会话失效时自动尝试一次微信身份恢复；多个接口同时发现失效，共用同一次恢复，避免重复请求。恢复失败后停止自动重试，显示原因和“重新登录”按钮，由用户主动重试，不因后续并发失败立即重新启动自动恢复循环。

恢复失败保留当前账号的本地草稿，不自动重放失败的提交或保存操作。草稿继续按账号隔离，不能因恢复登录而向其他账号展示。具体状态机与页面提示待技术设计。

### 微信新用户昵称与账号头像（已确认）

用户已确认微信新用户未填写昵称时显示“微信用户”，未设置账号头像时显示默认头像。用户可在个人资料中自愿修改，不强制获取微信昵称或头像，不增加首次登录必填项。

账号头像与 AI 设计使用的正面照片分别管理，修改账号头像不替换设计照片，也不默认将设计照片用作账号头像。昵称缺省展示不作为登录用户名或账号唯一标识。头像存储、文件引用和接口字段尚未设计，不能把现有正面照片字段直接当作独立账号头像实现；具体设计需核对数据库和接口。

### 昵称与账号头像跨端同步（已确认）

用户已确认昵称与账号头像由小程序和 Web 共用。任一端修改后，另一端刷新展示最新值；Web 同样提供账号头像修改入口。本人设计照片继续独立管理，不随账号头像修改而替换。

本次仅确认上述资料能力两端同步，不扩展为所有后续功能必须同步上线，也不增加实时推送要求。Web 新增头像编辑纳入本需求范围，随个人资料能力实施；字段与接口、文件引用及并发更新规则待设计，尚未实施或验证。

# 小程序独立修改密码实施计划

2026-11-19，依据[我的页结构](01-需求说明.md#我的页结构已确认)和[改密后的会话约定](01-需求说明.md#修改密码后的会话与微信绑定已确认)。

## T1 小程序改密页面

- [x] 将 `pages/me/index` 的「修改密码」入口接到现有 `go` 导航，保留 `account.hasPassword` 条件。移除原页表单、临时输入和展开样式。
- [x] 在 `app.json` 注册 `pages/change-password/index`。独立页沿用账号检查、全局表单样式和 TDesign 按钮，密码只保存在当前表单。提交期间禁用重复操作，失败在表单页显示原因。
- [x] 提交沿用 `POST /auth/password` 及 `currentPassword`、`newPassword`。成功后清空密码并返回「我的」，由已有的 `onShow` 触发会话恢复。无密码账号直接进入页面时也无法提交。
- [x] 在 `apps/miniapp` 执行 `npm test` 和 `npm run build`。使用模拟接口核对保存、失败、取消和权限，在微信开发者工具核对菜单跳转、返回和独立页面布局。

## T2 确认新密码

- [x] 在新密码下方加入「确认新密码」密码框。两次输入完全一致才能保存；不一致时在确认框下方提示。确认值仅用于表单校验，提交字段和会话流程沿用 T1。
- [x] 离线回归覆盖确认值为空、不一致、修正后提交及请求字段。运行小程序测试和构建，在开发者工具核对三个密码框。

## 实施与验证结果

T1 已实施，由 `password_page` 子任务完成代码和离线测试。`npm test` 通过 114 项，覆盖入口跳转、返回前未提交、原密码错误后保留输入、提交成功后返回、重复提交保护、无密码账号限制，以及离开页面后忽略迟到结果。`npm run build` 通过 19 个页面路由及组件资源检查，微信 `wcc` 和 `wcsc` 分别编译 29 份 WXML/WXS 和 27 份 WXSS。

微信开发者工具 Stable 2.02.2608080 的 iPhone 12/13 (Pro) 模拟器中，点击「我的 → 修改密码」进入独立页面，两个密码框和保存按钮均显示。用原生返回键回到「我的」后，页面仅显示修改密码入口。真实密码写入、成功后的微信会话恢复和真机操作待验证。

T2 由 `password_confirmation` 子任务实施。`npm test` 通过 115 项，覆盖确认值为空和尾随空格不一致时拦截提交、修正后可提交、请求体保留原有两个字段，以及失败保留、成功清空三个输入。构建和微信原生编译通过，开发者工具已核对三个掩码输入框。真实密码写入和真机操作待验证。

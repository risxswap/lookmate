# 穿搭灵感库页面与生成设计

日期：2026-10-30。状态：页面流程、24套AI素材规划、规划与生图分工、偏好优先级和版本下架规则已确认并实施。见[需求说明](01-需求说明.md)。场合不自动预填、专区只收录普通穿搭设计已确认；具体像素仍为实现建议。接口与数据实现见[接口与数据设计](03-接口与数据设计.md)，验收范围见[实施与验证结果](07-实施与验证结果.md)。

## 1. 页面组织

沿用现有桌面端侧栏、浅色背景、绿色主操作和 Ant Design，不建立新的视觉体系。复用发型专区的浏览、详情、编辑、记录流程，但按穿搭目标调整内容。

| 页面 | 主要内容 | 操作 |
| --- | --- | --- |
| 穿搭灵感 | 全部/已收藏、场合与风格筛选、整套搭配图片、服务端分页 | 查看灵感、收藏；工具栏右侧进入AI自由搭配 |
| 灵感详情抽屉 | 完整参考图、名称、场合、风格、配色与穿法要点 | 用我的衣服搭、收藏灵感 |
| 穿搭设计编辑页 | 目标参考、本人全身照、本次要求、必穿单品、更多条件 | 更换灵感、继续确认 |
| 我的穿搭记录 | 固定穿搭类型、状态筛选、任务卡片、分页 | 查看进度与结果 |
| 结果详情 | 本人效果、实际衣物、借鉴与差异、原参考快照 | 沿用已有收藏效果、调整后再试及可用任务操作 |

建议沿用 `/app/outfit-design` 作为灵感首页，新编辑页为 `/app/outfit-design/try`，记录页为 `/app/outfit-design/records`；任务详情继续使用 `/app/designs/{id}`。路由方案尚未实施，现有菜单目前仍直达编辑页。

所有站内穿搭入口和“调整后再试”链接统一更新为最新专区路由，不为旧地址和查询参数保留兼容跳转。整体设计和发型设计保留各自正式功能入口，本轮不为整体设计增加灵感选择。来源参数只用于导航，不改变任务权限。

## 2. 灵感首页与详情

页头为“穿搭设计”，说明“挑一套喜欢的感觉，用自己的衣服搭出来”。下方是“穿搭灵感 / 我的穿搭记录”两个标签页。

灵感工具栏左侧为“全部 / 已收藏”、场合和风格筛选，右侧为“AI自由搭配”。首期每个筛选选择一项，两类条件共同生效；更改条件回到第一页。场合建议为日常、通勤、约会、聚会、出游；风格建议为简约、休闲、通勤、复古、运动休闲、温柔。这里的通勤风格不自动等同正式场合要求。

列表按内容宽度采用四、三、两列布局，建议卡片最小宽度220px、间距16px；1024px桌面应保持至少两列，无横向滚动。超宽窗口限制卡片最大尺寸并居中排列。筛选允许换行，不截断标签。图库每页主动请求12条，可选12/24条，后端完成筛选与分页，页面使用返回的items和total及Ant Design Pagination。

每张卡片显示一张完整全身参考图、名称、两个主要标签和独立收藏按钮。采用统一3:4画框，完整展示人物及服装，不裁掉脚部或靠拉伸填满；素材构图统一，避免大面积空边。点击图片或名称打开抽屉，收藏不触发抽屉。平台AI素材标注“AI穿搭示意”，不标注适配分数、热度或未经验证的推荐理由。

抽屉建议宽560px，展示完整大图和三组简明说明：配色、比例与层次、穿法。示例：“浅色内搭连接灰色外套，深色直筒裤收住整体；外套敞开，内搭下摆收进裤腰。”不将材质、保暖或防水等不可证实属性写成事实。首期每套一张主图，不要求像发型一样提供三视图。

底部主操作为“用我的衣服搭”，次操作为“收藏灵感 / 已收藏”。浏览及收藏不要求已有照片或衣物。关闭抽屉恢复原筛选、页码、滚动位置和键盘焦点。无结果时允许清除筛选；无收藏时提供切回全部的操作，不重复添加创建按钮。

## 3. 编辑与确认

选中灵感后进入独立编辑页，不把照片表单常驻在图库中。左侧展示参考图和搭配要点，右侧展示本人照片与输入；窄桌面顺序堆叠，确认按钮不遮挡内容。

输入顺序：

1. 本人全身照：预选现有默认全身照，允许从照片库更换或临时上传，仍只使用一张本人照片。
2. 本次要求：选填，提示“喜欢这套的哪些地方？有什么想调整的？”无需再复述整套搭配。
3. 场合：选填，不根据参考款自动填写。可展示建议场合，用户主动选择后才写入表单；未填写按日常处理，更换参考款不覆盖已填场合。
4. 必穿单品：沿用衣橱抽屉，不选则自动挑选。明确提示“其余单品由AI从你的衣橱搭配”。
5. 更多条件：风格补充、天气和尺寸，沿用现有选填规则，不根据日期推断天气。

“更换灵感”回到选款状态，只有点击新款的“用我的衣服搭”才替换参考；保留照片、要求、场合和必穿单品，清除原确认结果与单次限制例外。建议灵感搭配与自由搭配保留各自草稿，共享本人照片；自由搭配不携带旧参考。普通草稿仅在当前账号、当前页签的站内导航期间保留，刷新不保证恢复；退出或换账号清空。历史调整覆盖已有草稿前提示选择，提交恢复记录继续独立保存原提交编号。

确认弹窗展示本人照片、参考灵感、本次要求、必穿单品及限制冲突。预览仍是无模型核验，不在此宣称已找到相似衣物或承诺可复刻。必要照片未完成上传时定位缺失项，目录故障与供应商不兼容时保留输入并提示原因。提交成功进入任务详情，响应未知时找回原提交，不自动再次生成。

## 4. 生成规则与接入方向（已确认）

### 已确认的业务约束

参考款提供风格目标，本次明确要求优先；必穿与明确禁忌必须遵守。真实衣物必须来自本人衣橱，无法完整复刻时尽力接近并解释差异。基础衣物不足或硬要求无法满足时停止。只改穿搭，保留发型与本人特征；既有示意鞋例外保留。

### 规划与生图分工

当前 `GenerationExecutor` 已分别组装规划图片和生图图片，但发型目录参考通过两条路径共同附加。穿搭灵感不能直接复用该行为，需要区分参考用途。

在既有一次规划调用中提供：本人照片、本人衣橱候选图、灵感图及平台整理的搭配要点。为灵感图使用独立的标识，明确“只参考配色、轮廓、层次和穿法，图中衣服不属于候选单品，图中人物不是本人”。平台目录的标签只能作为风格参考，不得覆盖用户单品的人工修订。

候选筛选仍按既有必穿、基础类别覆盖和多样性规则运行；首期不增加向量检索、图片相似度服务或额外模型调用。灵感图占用规划图片预算，筛选和预算核验必须预留该位置；容量不足时明确拒绝，不静默丢弃必穿、本人图或灵感图。

规划输出只选服务端提供的衣橱ID，由现有程序核验归属、基础覆盖及必穿。增加可展示的“借鉴要点”和“主要差异”，具体结构在接口契约阶段定义。用户选中某款视为本次风格意图，优先于一般长期风格偏好；长期明确限制仍走现有冲突和单次例外确认流程，选款本身不代表同意突破限制。该偏好优先级已确认。

生图只接收本人照片、规划选中的实际衣物图和已经落实到这些单品的穿法说明，不传平台灵感图。这样可以降低直接复制示例衣服、人物或背景的风险，但不保证模型完全遵从，仍须真实效果验证。规划原始参考保留在任务快照中供详情回看。

不增加规划完成后的选衣确认步骤，沿用一次提交后自动规划与生图。没有适合的衣物不能用参考图中的衣服凑齐；自由搭配沿用现有路径。生图已指定GPT Image 2（`gpt-image-2`），使用现有`openai-edits`接入，不使用Kolors或自动回退到Kolors；本人加实际衣物图的渠道能力、尺寸与预算在联调中验证。

## 5. 结果、收藏与记录

结果页优先展示本人效果与实际单品。原灵感以较小参考卡显示，明确标注“参考灵感”，与本人原图/效果图对照分开；不把平台图片当作已生成结果。

文字先解释实际选择，再说明借鉴和差异，例如“保留浅上深下的配色；用你的灰色开衫替代参考西装，整体更休闲”。参考未实现但影响使用的差异放在效果图附近，其余并入方案说明。没有依据时不生成相似度评分。

灵感收藏表达以后想尝试，效果收藏继续整理本人成功结果，两者独立；取消灵感收藏不删除设计。建议首期灵感不分组，列表提供全部/已收藏即可，收藏只对当前账号可见。

穿搭记录固定查询OUTFIT类型，显示处理中、成功、失败及结果未知等已有状态，以服务端actions提供操作。已确认本专区只收录普通穿搭设计，不混入常用搭配的纯文字评价或独立AI任务；统一记录保持原行为。删除、隐藏、收藏效果后同步刷新两个列表，不产生任务副本。

## 6. 首批素材规划（已确认）

首批制作24套，每种风格4套，兼顾不同模特呈现、裤装/裙装、轻薄/叠穿及配色。不是为每个筛选组合强行凑齐一款。场合与风格允许一套多标签，避免同一图片换标签充数。

| 风格 | 4套构思方向 |
| --- | --- |
| 简约 | 黑白基础、灰白层次、米色同色系、深蓝点缀 |
| 休闲 | 衬衫牛仔、针织直筒裤、条纹宽松裤、轻外套叠穿 |
| 通勤 | 西装直筒裤、衬衫半裙、开衫长裤、简洁连衣裙 |
| 复古 | 格纹棕色系、牛仔叠穿、针织背心、复古裙装 |
| 运动休闲 | 卫衣长裤、运动外套、T恤短裤、轻户外层次 |
| 温柔 | 浅色针织、柔和衬衫、低对比裙装、轻盈连衣裙 |

上述为素材策划，不是已经制作或校验的图片。采用平台制作的AI示意图，沿用图库版本化发布方式；不抓取博主照片。人物姿态自然、全身完整、服装轮廓清楚、背景简单，不用大幅道具或文字遮住衣物。人物仅用于展示穿法，不按用户性别、年龄或体型自动屏蔽款式。

每套素材准备稳定编号、版本、名称、主场合及场合标签、风格标签、一张主图、配色要点、比例与层次、穿法说明。建议名称不超过20个汉字，各组说明1至2句。制作后逐张核对图文一致、衣物边界、四肢和穿法合理性；不合格素材不入库。具体制作提示词与质量验收随素材任务细化，本轮不生成图片。

## 7. 更新、下架与恢复（已确认）

采用发型专区已有规则：收藏跟随当前版本，历史任务保持提交时图片与说明快照；编辑期间版本变化须重新查看并确认，不能静默换款。已下架收藏保留名称与快照、可取消收藏，不再发起新设计。

下架前已接受任务继续按快照执行，内部结果保存恢复继续完成。下架后不创建基于该灵感的新任务，包括FULL和IMAGE_ONLY重试；用户可以明确改用另一灵感或自由搭配。原提交键重放仍返回原任务，不将其当作新建重试。旧版本资源缺失或摘要不匹配时明确失败，不能替换为新图。

目录读取失败应显示“灵感库暂不可用”，不能误当作空库或全部下架。收藏写入结果未知时重新读取状态，不反复切换；生成写入未知继续使用现有幂等恢复。普通草稿与待确认提交不得互相覆盖。

## 8. 接口与实现边界

拟复用登录权限、设计预览/提交/详情/重试、文件与衣橱选择接口，新增灵感列表、详情、本人灵感收藏能力。穿搭输入拟增加参考ID与版本，由服务端加载可信目录，不接收客户端提供的图片URL或搭配说明。自由搭配无参考；发型和整体类型传入穿搭参考应拒绝，避免静默忽略。

任务需保存参考图片及要点的不可变快照，确认摘要和幂等请求摘要均覆盖参考身份与版本。按最新统一结构保存，无参考的自由设计明确使用null；不做旧快照兼容。图库资源独立于用户文件清理。

不新增应用、运营端、任务服务或模型调用阶段。收藏持久化、快照结构、错误码、权限、页码边界和迁移需在下一步接口与数据设计中具体定义；表结构及契约细化现已记录在[后续技术草案](03-接口与数据设计.md)；不写迁移、不把草案同步成现行接口。

## 9. 验收场景

实施后至少验证：筛选/分页/收藏与返回位置；浏览无需照片；灵感和自由草稿隔离；更换款式保留输入并清除旧确认；只有参考图但没有完整衣橱时不可生成；近似替换的说明与实际单品一致；必穿和禁忌未被参考款覆盖；生图输入不混入灵感服饰图；原键恢复不重复创建；版本更新及下架边界；专区与统一记录一致；所有站内入口使用最新路由，无参考自由设计正常工作。

布局检查1024、1280、1440px桌面、长名称、加载失败和键盘操作。图库列表与抽屉图片不得裁掉关键衣物，参考图与本人效果有明确标签。程序测试只能验证约束与输入，实际服装保真、穿法与图文一致性另用真实供应商样例评估。

本轮已核对现有页面、领域规则及代码路径，细化方案获用户确认；未运行页面、制作素材、调用模型或执行业务测试。

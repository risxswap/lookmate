# 穿搭灵感库接口与数据设计

日期：2026-10-30。状态：已实施，V10已创建且仅在隔离库执行。已确认业务见[需求说明](01-需求说明.md)，页面见[页面与生成设计](02-页面与生成设计.md)。用户已明确系统仍在开发中，以最新设计为准，不要求历史兼容；场合不自动预填、专区仅收录普通穿搭设计已确认。接口已完成HTTP代表场景验证，范围见[实施与验证结果](07-实施与验证结果.md)。

## 1. 现状与设计边界

已核对现有HairstyleController、HairstyleCatalogService、HairstyleFavoriteService、GenerationService、GenerationEngine、GenerationExecutor、WorkspaceService及RecordsMapper：

- 发型目录随项目版本发布，用户收藏单独持久化；可复用这种组织方式，不复用发型资源ID或收藏数据。
- 设计输入经过严格字段校验，新增字段必须同时进入预览、提交、规范化摘要与快照，不能只改前端。
- 现有输入快照schemaVersion为2，规划输出为1，重试和详情actions存在版本判断；实施时统一更新为最新结构，不增加旧版读取分支。
- design_result.plan_provenance已保存验证后的规划输出，可承载新增借鉴说明，不必为文本再加结果表列。
- 普通设计与常用搭配AI任务共用design_task；现有列表只有designType、status筛选，单用OUTFIT不能表达“本专区普通穿搭记录”。

继续使用server/web和既有分层，不新增服务或运营端。灵感目录与图片是平台资源，不属于用户衣橱、file_asset或design_favorite。

## 2. 命名与资源目录

平台穿搭灵感使用outfit-inspirations作为API资源名，内部名称OutfitInspiration；避免与已有/api/outfits常用搭配混淆。

建议资源目录为server内的版本化classpath资源，当前版本配置为lookmate.outfit-inspirations.current-version，重启生效。每一版目录有唯一版本，如v1；稳定款式ID跨版本保持含义，不能将旧ID重用于完全不同的搭配。更新内容发布新版本，禁止覆盖已发布图片字节。

目录条目包含：id、version、active、sortOrder、name、primaryOccasion、occasions、styles、image及styling。image保存资源文件名、MIME、宽高、字节数及SHA-256；styling包含palette、silhouette、wearing三个说明字段。所有文件在启动时核验路径、存在性、摘要和结构，不允许客户端传入任意路径或外部URL。

建议限制：id为`[a-z0-9][a-z0-9-]{0,63}`；version为`v[1-9][0-9]{0,8}`；name为1至20个Unicode码点；styling各字段1至500码点；每款恰好一张主图；occasions/styles为非空、去重的已定义枚举数组。平台目录单图硬上限拟定为5 MiB、目录最多100条，作为可配置的开发准入值；生成阶段另外受总图片/字节预算约束。首批实际产物须核对，不凭文档宣称图片已合格。

首期场合编码：DAILY日常、COMMUTE通勤、DATE约会、PARTY聚会、TRAVEL出游。风格编码：MINIMAL简约、CASUAL休闲、COMMUTE通勤、RETRO复古、SPORT_CASUAL运动休闲、SOFT温柔。primaryOccasion必须属于occasions。该字典用于平台灵感筛选，不修改用户长期偏好字典或日历自定义场景。

全部列表按sortOrder、id升序，作为平台目录展示顺序的明确例外；收藏列表仍按收藏created_at、id倒序。目录不可用返回故障，不返回伪造空目录。发布需保留所有仍供收藏和历史任务展示的旧资源，首期不做自动平台资源清理。

## 3. 灵感接口

继承[通用契约](../../01-项目总览/05-接口契约.md)：登录会话、写操作CSRF、字符串ID、UTC时刻、ApiResponse包装及统一错误。以下JSON均指包装内的data。请求不接收userId；收藏和任务只访问当前账号。

| 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- |
| GET /api/outfit-inspirations | page默认1，pageSize默认20/最大100；scope=all或favorites，默认all；可选occasion、style | 200，PageDto：page/pageSize/total/items |
| GET /api/outfit-inspirations/{id} | 稳定灵感ID | 200，详情 |
| GET /api/outfit-inspirations/assets/{version}/{filename} | 受限目录版本及文件名 | 200图片字节、真实Content-Type、nosniff、私有不缓存策略 |
| PUT /api/outfit-inspirations/{id}/favorite | 不接受请求体 | 首次201、重复200；inspirationId/favorited/favoritedAt |
| DELETE /api/outfit-inspirations/{id}/favorite | 不接受请求体 | 200，data:null；未收藏也成功 |

列表界面主动传12或24。参数非法返回400，不默默忽略筛选；两种筛选取交集，匹配标签数组任一元素。省略筛选表示全部；前端清除时删除参数，不发送空字符串或字符串null。超出末页返回空items和真实total，页面重新定位有效页。

全部列表只包含当前可用款；favorites包含本人已收藏的下架款。下架详情仅向持有该收藏的账号返回不可用展示；其他情况返回404。历史任务通过自己的inputSummary展示原参考，不依赖下架详情权限。平台版本图片不包含用户信息，登录后可读取目录白名单中的旧版本图，不意味着可以对下架款新建任务。

### 返回对象

列表和详情共用以下有界对象，避免逐卡详情请求：

```json
{
  "id": "minimal-gray-layers",
  "version": "v1",
  "name": "灰白层次通勤",
  "primaryOccasion": "COMMUTE",
  "occasions": ["COMMUTE", "DAILY"],
  "styles": ["MINIMAL", "COMMUTE"],
  "image": {
    "id": "minimal-gray-layers-main",
    "url": "/api/outfit-inspirations/assets/v1/minimal-gray-layers.webp",
    "width": 768,
    "height": 1024
  },
  "styling": {
    "palette": "灰白上装搭配深色下装。",
    "silhouette": "上装保持利落，下装采用直线轮廓。",
    "wearing": "外套敞开，内搭下摆收进裤腰。"
  },
  "availability": "AVAILABLE",
  "favorited": false,
  "favoritedAt": null
}
```

示例只是契约样本，图片尚未制作。image为对象或null，资源丢失的下架收藏允许null；正常可用条目必须有已核验主图。availability为AVAILABLE/UNAVAILABLE。favoritedAt为UTC ISO时刻或null。对客户端不返回classpath位置、摘要原始字节或生成凭据。

PUT按当前目录判断可用性。重复收藏不改收藏时间、展示快照和排序；删除后重新收藏视为新收藏。目录故障时PUT返回503，DELETE仍能按本人关系幂等取消；下架后重复PUT返回409，不因已有收藏绕过可用性检查。

## 4. 收藏数据与事务

仅新增outfit_inspiration_favorite表，不新建平台灵感主表，不把灵感收藏混入结果收藏或常用搭配分组。

| 字段 | 类型 | 空值与写入规则 |
| --- | --- | --- |
| id | BIGINT AUTO_INCREMENT | 主键、NOT NULL |
| user_id | BIGINT | NOT NULL，会话用户 |
| inspiration_id | VARCHAR(64) | NOT NULL，跨版本稳定ID |
| display_snapshot | JSON | NOT NULL，服务端生成收藏时展示快照 |
| created_at | DATETIME(3) | NOT NULL，UTC，应用显式写入 |
| updated_at | DATETIME(3) | NOT NULL，首次与created_at相同 |

唯一索引(user_id,inspiration_id)，分页索引(user_id,created_at,id)。InnoDB、utf8mb4_bin，无外键；除自增主键外无自动默认值。取消收藏物理删除关系，不删除平台资源或任务。display_snapshot保存当时名称、标签、版本、styling、图片文件名和安全元数据，不保存用户照片、图片二进制、临时签名URL或密钥；不是“下架前最后版本”。当前款可用时以当前目录显示，只有下架时读收藏快照。

写入先准备有界目录信息，再在短事务锁user，检查本人关系及当前目录可用性后插入；唯一约束兜底。取消也先锁user。事务内无外部调用或大图片读取，沿用同账号统一锁顺序。目录在进程生命周期内固定，发布切换要求停止旧实例接受新请求，不设计混合目录版本在线热更新。

全部目录在服务端筛选分页，仅批量查询本页的本人收藏状态。favorites使用SQL COUNT和LIMIT/OFFSET，不能先加载全部收藏再在前端或应用层切片。可用条目根据当前目录匹配ID集合筛选，下架条目根据display_snapshot的枚举数组筛选；空ID集合显式处理，不生成IN()。COUNT与items使用同一目录快照、同一SQL谓词和只读事务，查询始终带user_id。首期24款，ID集合有界；JSON筛选路径及执行计划在实施时验证，不承诺未测性能。

## 5. 设计请求与预览

继续使用POST /api/designs/preview和POST /api/designs，前者200，后者202。原input对象新增两个字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| outfitInspirationId | string或null，可省略 | 平台灵感稳定ID；非空只允许普通OUTFIT设计 |
| outfitInspirationVersion | string或null，可省略 | 与ID同时有值，必须为当前可用目录版本 |

两个字段均省略或null表示自由搭配，按最新规则统一规范化为两个null键。单边有值、空字符串、类型错误、非OUTFIT非空引用均返回400。不得同时携带发型目标；不扩展常用搭配AI请求、OVERALL或HAIRSTYLE能力。JSON重复键及未知字段继续拒绝。

客户端只提交ID和版本，不能提交inspirationReference、image、styling或自行构造的快照。预览和创建由服务端加载可信目录，预览响应新增outfitInspirationReference，字段为id/version/name/primaryOccasion/occasions/styles/image/styling，不含收藏状态；无参考时为null。inputSummary增加同名安全字段，历史读取来自提交快照而不是当前目录。

输入例子（省略既有字段）：

```json
{
  "designType": "OUTFIT",
  "outfitInspirationId": "minimal-gray-layers",
  "outfitInspirationVersion": "v1"
}
```

已确认场合不自动预填：服务器不把目录primaryOccasion写入用户occasion。前端可展示推荐场合，只有用户明确选择后才作为请求提交；空场合沿用已有日常缺省规则。参考只表达风格目标，不能暗中变成正式着装硬要求。

预览保持无模型调用。预览摘要覆盖ID、版本及可信参考内容；创建重新核验版本、可用性、资料、图片和预算。首次新建时禁止静默采用最新版本，要求用户重新查看后预览。规范化摘要包含这两个参考键，缺省与显式null统一处理；不保留旧摘要算法或为开发期旧提交提供重放兼容。最新设计下同键同输入仍严格幂等。

## 6. 输入、输出快照与生图

### 输入版本

所有设计任务统一使用最新input_snapshot.schemaVersion=3，inputSummary.schemaVersion同步为3，包括普通设计、发型、整体及常用搭配AI任务；不再并行支持输入版本2。所有创建入口、读取、预览、执行、详情actions和FULL/IMAGE_ONLY重试统一修改。版本标识用于校验当前结构，未知或旧结构拒绝处理，不做转换或补字段回读。

统一快照包含outfitInspirationReference，无参考时为null；有参考时保存不可变图片描述：稳定ID、版本、资源文件名、MIME、宽高、字节数、SHA-256、标签与styling。客户端DTO只映射安全字段。参考身份与版本保存在normalizedRequest中。非空参考仅允许普通OUTFIT设计，必须验证参考完整性；fixedOutfit在所有新快照中明确写入boolean，普通设计为false，常用搭配AI任务为true。

这里的统一结构不取消正常业务中的参考资源版本：按最新结构创建的任务仍固定提交时的参考素材，避免目录更新改变已接受任务。

### 规划输出与保存

所有规划路径统一输出schemaVersion=2，NO_MATCH同样使用2；校验与持久化只支持该最新结构，不保留输出1的适配分支。新增字段为plan.inspirationAdaptation：

```json
{
  "borrowedElements": ["浅上深下的配色", "利落的直线轮廓"],
  "differences": ["用灰色开衫替代参考西装，正式感有所降低。"]
}
```

READY且有参考时必须提供此对象；borrowedElements为1至5条非空文本，differences为0至5条，每条最多500个Unicode码点；没有明显差异时允许空数组，不强迫编造替换。NO_MATCH仍没有plan及适配说明。自由搭配、发型、整体及常用搭配AI任务的READY plan也包含inspirationAdaptation，值固定为null；NO_MATCH的plan仍为null。输出键、类型、长度和模式关系严格核验，不静默截断，不因输出错误再增加自动修复模型调用。

适配说明写入原design_result.plan_provenance，沿用同一结果短事务，无新增结果列。DesignResultDto增加可空inspirationAdaptation，详情从已验证的provenance投影；无参考设计的此字段为null，不支持旧输出version=1回读。IMAGE_ONLY复制原文字方案和此说明，不重新解释灵感；FULL按原参考快照重新规划。现有matchLevel不当作图片相似度评分，重要差异同时沿用limitations在效果图附近提示。

### 图像与预算

规划输入加入一张独立标记的灵感图，候选仍只能选择本人衣物ID。灵感图不允许进入items.referenceImageIds；服务端应区分person、candidate、inspiration角色，不能仅凭“已发给模型的图片ID”就允许结果引用。参考元数据及图中文字均是数据，不能覆盖系统约束或本人身份。

在现有候选筛选之前预留本人图与一张灵感图的数量和字节预算，保留必穿和基础类别覆盖。预览仅验证当时可检查项，创建和执行重新核验。不得通过静默丢弃必穿、灵感或本人图来满足预算。

生图只发送本人照片、选中衣物图和落实到实际单品的穿法；不发送灵感图、图中服饰图片或原始参考描述，避免提示词暗示复刻不存在的衣服。原始灵感及借鉴说明继续用于历史展示。规划预算和生图预算分别核验，不能像发型一样把目录图同时计入两条路径。

平台图片不进入design_task_asset或用户文件清理；用户本人/衣物/输出文件仍按原引用规则保留。执行从不可变版本资源加载并核验SHA-256，摘要不符或缺失时明确失败，不换成最新图。生图模型按用户要求使用`gpt-image-2`，协议采用现有`openai-edits`，接入渠道沿用开发配置。禁止使用Kolors或向Kolors回退。配置和预算检查保留，实际渠道的多图能力及响应格式需验证，不因模型选择已确认而跳过校验。

## 7. 版本、下架、幂等与错误

| 场景 | 行为 |
| --- | --- |
| 新建或预览旧版本 | 当前款可用但版本不同，409，要求重新查看当前款 |
| 新建、首次FULL/IMAGE_ONLY重试遇到下架 | 409，不创建新任务，actions不提供原样重试 |
| 当前款已更新，但原款仍可用，重试旧任务 | 复用原版本快照和资源，不静默换新版本；旧资源损坏时拒绝 |
| 已接受任务之后下架 | 按原快照继续执行、恢复或保存结果 |
| 同账号原键、原规范化请求重放 | 先返回原任务，即使目录后来下架；不同请求仍409幂等冲突 |
| 隐藏或删除后的原键行为 | 完整继承现有生命周期规则，不以灵感功能恢复被删除/隐藏任务 |
| UNKNOWN | 仍不自动重发，不提供原样重试；用户主动调整创建新任务沿用原风险提示 |

处理顺序保留原幂等查询优先于新任务目录准入；不得把目录加载故障变成已接受任务找回失败。首次创建和重试仍要核验当前目录，平台资源的执行加载则使用任务自己的旧版本。

| HTTP与错误码（新增为建议） | 场景 | 前端处理 |
| --- | --- | --- |
| 400 VALIDATION_ERROR | 字段、枚举、模式或成对参数非法 | 保留输入并提示，不自动换模式 |
| 404 RESOURCE_NOT_FOUND | 不存在或无权读取的灵感/任务 | 回列表或重选，勿泄露其他账号 |
| 409 OUTFIT_INSPIRATION_CHANGED | 当前版本与输入不一致 | 展示更新提示，用户选定后重新预览 |
| 409 OUTFIT_INSPIRATION_UNAVAILABLE | 下架，不能新收藏/创建/重试 | 保留输入，允许换款或主动切自由搭配 |
| 503 OUTFIT_INSPIRATION_CATALOG_UNAVAILABLE | 当前目录损坏、加载失败 | 提示暂不可用并允许重试，不视为空列表 |
| 409 OUTFIT_INSPIRATION_ASSET_INVALID | 固定版本资源缺失或摘要不符 | 保留历史与输入，禁止自动替换图片；后台失败以同码记录在任务结果中 |
| 422 INPUT_BUDGET_EXCEEDED | 图片数量或字节预算不足 | 显示已有预算提示，不丢图继续 |

资料冲突、CSRF、登录、限流、维护、供应商不兼容及幂等冲突沿用原错误协议。后台任务错误由详情200响应携带失败结果，不能与同步HTTP状态混淆。取消收藏不依赖目录可用性，历史图片失败不妨碍读取其余任务文字和已有本人效果。

## 8. 专区记录与前端状态

建议为GET /api/designs增加可选scope=all/design，默认all保持当前统一列表语义。design表示普通设计，专区固定请求designType=OUTFIT&scope=design；非法scope为400。page、pageSize、status及排序沿用原规则。

需要同步RecordsService、RecordsMapper的列表与COUNT。普通任务统一按最新input_snapshot.fixedOutfit=false筛选，常用搭配AI任务为true；不依赖可删除的搭配关系判断类型，不增加缺少字段时的历史兜底条件。此分类不得仅由前端过滤当前页，否则total和分页失真。自由搭配同样属于普通设计，不以是否有灵感参考区分。建议先以现有账号/类型/时间索引缩小范围，再用实际数据EXPLAIN决定是否增加索引，当前不预建JSON索引。

用户已确认专区只收录普通穿搭设计；常用搭配AI评价及出图任务留在原入口，统一记录默认all。

路由按页面设计；详情from=outfit-design仅为有限导航来源枚举。来自统一记录保持统一记录返回；专区进入则保持穿搭菜单高亮。直接访问普通OUTFIT详情且无来源时可默认返回穿搭记录，固定搭配任务沿用其原入口，不按OUTFIT一概重定向。

草稿按账号和gallery/free隔离，参考ID/版本及普通输入一起保存；切换自由模式不携带参考字段。更换目标、恢复历史输入后清除旧预览与单次限制例外。待确认提交保存原输入与原键，不允许用新款覆盖待确认提交后再复用旧键；先找回/明确处理原提交。所有站内入口及调整后再试链接更新为最新路由，不保留旧穿搭入口的兼容跳转；整体与发型功能仍有各自正式入口。

所有查询键带accountId；收藏后更新当前卡片与详情，并失效收藏列表。任务操作同步失效统一记录和专区记录。收藏取消导致末页为空时根据服务端total修正页码；错误态与空态分开。

## 9. 迁移、发布与验收

当前仓库最高迁移为V9，本需求只计划新增收藏表迁移，编号在实施时重新检查，不提前锁定V10或修改已发布脚本。由ops显式迁移，server仅检查兼容性。无旧灵感收藏需要回填，不迁移design_favorite。

按最新设计配套更新前后端、全部任务创建与执行入口及测试夹具，不设计旧客户端适配、多版本混跑、旧快照转换或旧版本回退支持。开发期旧测试任务及其关联数据不作为兼容验收对象；若实施环境存在不符合新结构的数据，先明确环境与处理范围，再进行隔离库重建或受控清理。本次设计调整不授权直接删除共享库数据，不回写已执行的Flyway历史。

按最新结构创建的任务所引用的素材版本仍须保留，这是任务快照与重试的业务要求。迁移成功不等于模型配置可用。

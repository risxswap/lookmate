# 前端页面与菜单布局

创建日期：2026-10-20。最后更新：2026-10-21。

状态：页面与菜单布局已确认，保留工作台作为登录后的默认首页。2026-10-20 用户授权先实现前端代码，按 [实施计划](02-实施计划.md) 推进页面布局与本地交互，业务接口联调不在本轮范围。

## 目标与范围

为桌面端用户组织发型设计、穿搭设计和个人资源入口。沿用 [首版需求](../2026-10-20-首版个人形象设计/01-需求说明.md) 的业务范围与权限，以及 [架构设计](../../01-项目总览/03-架构设计.md) 的技术选型。UI 使用 Ant Design，执行约束见 [前端协作约定](../../../apps/web/AGENTS.md)。

## 已确认布局

登录后采用左侧固定菜单、右侧内容区，不设置顶部导航栏；头像、用户名与账号菜单位于侧栏底部。侧栏保持一级菜单，详情页从列表进入。公开首页、登录页与注册页使用独立布局。

| 菜单 | 内容与布局 |
| --- | --- |
| 工作台 | 默认首页；统一的“开始形象设计”入口、进行中的任务和最近结果 |
| 设计记录 | 全部记录与我的收藏两个页内标签；记录按设计模式和状态筛选，收藏标签内管理收藏夹 |
| 我的衣橱 | 图片卡片网格与分类筛选；点击查看或编辑衣物及饰品 |
| 个人资料 | 基础资料、我的照片、身体尺寸三个页内标签 |

侧栏底部账号菜单保留个人资料快捷入口与退出登录。默认首页约定不替代已有登录后安全返回目标页面的行为，认证规则沿用 [登录注册需求](../2026-10-20-登录注册/01-需求说明.md)。

形象设计统一为一个页面，提供“整体设计”“只改发型”“只改穿搭”三种模式；发型和穿搭不再作为独立侧栏菜单。工作台提供开始入口，设计记录页提供新建设计入口。设计时选择本人照片、填写要求，并按模式提供尺寸与必穿单品选项。整体设计结果以一张整体效果图为主，分别展示发型说明、穿搭清单和搭配理由；单项模式展示对应内容。业务定义见 [设计与任务](../../01-项目总览/02-领域模型.md#设计与任务)。

本轮确认替代此前七项菜单及两类独立设计入口方案，“我的方案”不作为菜单名称。

延续现有绿色主色与浅色背景，照片和效果图作为主要内容；设计结果使用大图与说明，衣橱和收藏使用卡片。

## 业务与状态边界

私有页面只展示当前账号的数据，沿用既有会话失效处理。任务、上传、识别、收藏及删除规则引用首版需求，不因菜单划分改变业务行为。生成中的任务可从工作台和设计记录继续查看；失败与结果待确认应按既有规则呈现，不能只展示成功结果。

本轮前端实现不修改业务接口或 SQL。现有接口与数据库只定义 HAIRSTYLE、OUTFIT 两类，且结果明细互斥；整体设计需要支持同一任务同时保存发型与穿搭内容，其模式编码、字段适用性、明细校验和迁移方案在实施前细化。各业务页面实施前细化必要接口、空数据、加载、失败反馈及可执行操作。运营后台和手机适配继续不在首版范围。

## 后续细化与验收

页面路由、具体宽度与间距、工作台展示数量、详情页结构和各业务表单交互后续细化。整体设计的照片预选与清晰度要求、单项模式对未修改部分的保留要求、默认模式，以及模式切换时的输入保留规则仍待细化。

实施后检查以下结果：

- 无返回目标的正常登录进入工作台，已有安全返回行为保持有效。
- 四个一级菜单能进入对应页面并正确显示当前选中项。
- 个人资料页可切换基础资料、照片与尺寸；账号菜单可进入个人资料并退出登录。
- 工作台能进入统一设计页面并选择三种模式，并从任务或最近结果进入对应详情；无数据时提供相应引导。
- 桌面浏览器下菜单、内容与主要操作可见，长文本、图片和相关状态正常呈现。

本轮实施与验证结果见实施计划，真实业务数据和生成流程后续联调。

# 设计记录删除与操作统一

创建日期：2026-10-28。

状态：用户已确认交互方案，并于 2026-10-28 授权修改业务代码。前后端已实现，完成隔离数据库与模拟 API 浏览器代表路径验证。实施分工及接口约定见[实施计划](02-实施计划.md)。

## 背景与范围

设计记录卡片当前在底部并排展示收藏与查看详情，没有删除入口，后端尚无设计任务删除接口。衣橱已有标题查看详情、右侧更多菜单和删除确认弹窗，本次沿用该交互。

范围包括全部设计记录、收藏列表及设计详情的单条删除入口，以及列表操作整理。不增加批量删除、回收站或任务取消能力。

## 已确认行为

- 点击记录标题查看详情；卡片右侧使用 `•••` 菜单，移除底部并排操作按钮。
- 菜单按可执行操作显示查看详情、收藏或取消收藏、删除记录；删除放在末尾并使用危险色。收藏资格沿用现有规则。
- 收藏列表的管理归属操作收进菜单，保留已加入收藏夹数量的说明。
- 详情页提供相同删除或隐藏入口，状态限制与列表一致。
- 完整成功及确认失败的任务可删除；等待、规划、生图、保存中的任务不显示删除操作，后端执行时仍须再次校验状态与归属。
- 结果待确认的任务提供“隐藏记录”，明确告知隐藏不取消外部调用。后台核实、最长七天保留及清理沿用[领域模型](../../01-项目总览/02-领域模型.md#收藏与删除)。
- 删除前使用确认弹窗，说明设计结果及收藏关系一并删除、无法恢复；本人照片与衣橱单品不受影响，图片按有效引用关系清理。没有收藏或生成结果的记录，提示应与实际影响一致。
- 用户只能操作自己的记录。删除或隐藏失败保留当前记录，并显示可理解的错误；请求期间防止重复提交。
- 成功后刷新记录、收藏及相关数量；删除当前页最后一条后回到有效页码，保持原筛选条件。详情删除成功后返回记录列表。

## 验收条件

1. 列表标题可进入详情，更多菜单与衣橱采用一致的入口和删除确认方式；收藏列表可从菜单管理归属。
2. 已完成和失败记录可删除；删除已收藏设计后，其全部收藏夹归属同时消失，照片和衣物仍可访问。
3. 活动任务不可删除；页面数据过期或跨账号直接请求同样无法绕过限制。
4. UNKNOWN 记录隐藏后不再显示；后续结果不使其重新出现，后台引用及期限清理遵守现有规则。
5. 删除失败不会误移除记录；删除当前页最后一条后分页有效，总数与收藏数据同步。
6. 列表与详情入口遵守相同状态规则；取消确认不产生修改。

验证证据见[前端浏览器记录](../../testing/02-checks/2026-10-28-设计记录操作.md)及[后端验证](../../testing/02-checks/2026-10-28-设计记录删除后端.md)。浏览器使用模拟 API，后端使用隔离 MySQL 与 MockMvc；未执行真实供应商清理或生产验证。

## 实施结果

接口细节见实施计划。复用现有 hidden_at、purge_after 和图片引用字段，无新增迁移；保留重试独立快照及常用搭配来源效果图引用。隐藏清理按终态或七天期限执行，单条失败留待重试；未增加供应商结果查询能力。

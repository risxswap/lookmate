## T1 后端上传及访问（backend 实现 agent）

- 修改 ObjectStorage/QiniuObjectStorage：对象元信息查询、私有缩略参数签名、凭证格式约束；查询与外部请求不进数据库事务。
- 修改 FileService/FileMapper/FileController/AssetScheduler：complete 同步登记原图并返回 200，不解码、不转码、不生成缩略图；删除后台核验调度，保留引用安全清理；兼容历史记录；必要时去掉失效配置。
- 生成结果保存不再生成缩略图对象；按原始结果格式与字节保存，保留有效性检查、幂等恢复和业务引用。清理同 key 去重；所有消费者兼容空尺寸。Thumbnailator 不再用于上传，若完全无用途则移除依赖与死代码。
- 更新相关 Java 测试/替身，覆盖新契约、原图不加工、签名、错误及生命周期边界；检查识别仍异步入队。运行定向测试、Spotless，提供实际证据。只修改 apps/server 范围，主 agent 维护文档。

## T2 上传界面（frontend 实现 agent，可与 T1 并行）

- 修改 ImageUpload 及照片、衣橱、设计页面：本地预览，complete 200 后直接可用，删除核验轮询；失败可重试完成登记，避免重复上传与重复提示。释放 object URL，避免移除/卸载时请求污染草稿。
- 更新上传说明：格式与 20 MB，无核验/2500 万像素等待文案。图片识别状态保留为业务状态，不混同上传。
- 保持既有组件布局及接口数据类型，补充针对性验证并运行 Node 24 下 npm run build。仅修改 apps/web 范围，主 agent 维护文档。

## T3 合并验证（主 agent）

- 审查契约、原图引用、清理和异步识别依赖，修复交回相应实现 agent。
- 运行后端 ./mvnw verify 和前端构建；适当使用隔离 HTTP/浏览器场景验证上传完成后可保存，绝不在共享库运行破坏性测试。

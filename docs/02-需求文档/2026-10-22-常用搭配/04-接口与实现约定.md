# 常用搭配接口与实现约定

2026-10-22。本次实施基线；沿用通用响应、CSRF、账号隔离、字符串 ID、UTC 时刻、分页 page=1/pageSize=20 最大100、严格未知字段及未传/清空语义。未明确的展示细节采用下述实现默认值，不扩大 AI 自动推荐范围。

## 搭配与快照

- 名称去首尾空格后1–100字符；备注可空、最多2000字符。1–32件去重的单品，可不完整。分组名1–50字符，同账号名称唯一；每套至多20个分组。
- 搭配 version 和 revision 均为字符串整数，初始0。所有编辑更新 version；仅单品组合/顺序或 note 改变递增 revision。名称、分组、置顶改变不使评价失效。
- 保存单品原始名称、类别、颜色、有效特征和图片 ID 快照；同一单品在搭配中未替换时，编辑继续保留原快照。源衣物更新不追溯更新搭配；用户移除再加入可选用当前信息。源删除时 missing=true，快照和资产仍保留。
- 从设计保存复制成功且包含穿搭的方案快照，不依赖源单品仍存在；后续编辑不回写原设计。搭配保留独立图片引用，原收藏变化不影响它。
- 删除搭配解除分组与其直接资产引用；已创建的 AI 任务保留其独立快照与任务资产，沿用任务生命周期。未知/活动任务不被搭配删除取消。
- 工作台请求 pageSize=4，后端 pinned DESC, created_at DESC, id DESC；筛选结果内仍置顶优先。无置顶时显示最新搭配；无强制置顶数量上限。衣橱默认pageSize=20。

## 数据结构

OutfitItem：`dressId, dressName, categoryId, categoryName, categoryCode, color, imageFileIds: string[], missing: boolean`（必要时附 features 快照）。

Outfit：`id, name, note: string|null, pinned, version, revision, groups: OutfitGroup[], items: OutfitItem[], sourceDesignId: string|null, createdAt, updatedAt`。

OutfitGroup：`id, name, version, createdAt, updatedAt`。

列表返回 PageDto：`items,total,page,pageSize`。详情沿用 Outfit，不混入多页任务结果，AI 历史独立分页。

## CRUD 接口

| 方法 | 路径 | 请求/结果 |
| --- | --- | --- |
| GET | /api/outfits | page,pageSize,groupId?；Outfit 分页，置顶优先 |
| GET | /api/outfits/{id} | Outfit |
| POST | /api/outfits | name,note?,dressIds:string[],groupIds?:string[],pinned?:boolean；201 Outfit |
| PATCH | /api/outfits/{id} | version 必填；name,note,dressIds,groupIds,pinned 按未传保持；200 Outfit |
| DELETE | /api/outfits/{id}?version=... | 200 null；校验归属与版本 |
| POST | /api/outfits/from-design/{taskId} | name?,groupIds?,pinned?；201 Outfit，来源方案含穿搭且完整成功 |
| GET | /api/outfit-groups | page,pageSize；分组分页 |
| POST | /api/outfit-groups | name；201 OutfitGroup |
| PATCH | /api/outfit-groups/{id} | version,name；200 OutfitGroup |
| DELETE | /api/outfit-groups/{id}?version=... | 200 null，仅解除归属 |

归属未知统一404；格式400 VALIDATION_ERROR；版本409 VERSION_CONFLICT；同名409 OUTFIT_GROUP_NAME_EXISTS；新选源衣物不可用409 DRESS_NOT_USABLE；文件不可用沿用 FILE_NOT_USABLE。删除分组影响搭配 groups 和 version，revision不变。前端遇到版本冲突保留草稿，显式刷新后再编辑，不自动覆盖。

## AI 接口

复用持久化 design_task/现有调度和供应商调用，单独关联 outfit_ai_job（T2 V5），不引入独立线程池或无限队列。EVALUATION 与 IMAGE 为任务目的，designType仍是 OUTFIT。所有选定单品都是固定集合，不能自动增减换衣；IMAGE 沿用既有示意鞋例外并显著标注。

| 方法 | 路径 | 请求/结果 |
| --- | --- | --- |
| POST | /api/outfits/{id}/ai-jobs | Idempotency-Key UUIDv4；`kind:EVALUATION|IMAGE,revision:string,personFileId?:string|null`；202 Job |
| GET | /api/outfits/{id}/ai-jobs | page,pageSize；Job分页，创建倒序 |
| GET | /api/outfit-ai-jobs/{taskId} | Job，成功或失败均200 |
| GET | /api/outfit-ai-jobs/by-request/{key} | 当前用户已接受提交；不存在404 |
| POST | /api/outfit-ai-jobs/{taskId}/retry | 新 Idempotency-Key；`mode:FULL|IMAGE_ONLY`；202 Job，仅后端 actions 允许时可操作 |

Job：`taskId,outfitId,revision,kind,status,stale,createdAt,updatedAt,errorCode,errorMessage,actions:string[],outputFileId:string|null,result:DesignResult|null`。result沿用现有设计结果字段，EVALUATION使用其summary/designReason/colorAdvice/wearingAdvice/items等；与已有 DesignResult 对齐，可增加 notices。stale按当前搭配revision比较；原搭配删除后任务仍可读。actions使用VIEW、RETRY_FULL、RETRY_IMAGE，不允许把仅评价收藏为完整设计。

EVALUATION不强制照片，不要求图片生成凭据；只请求一次规划/评价，允许不完整搭配，无照片时禁止实际上身判断。IMAGE要求有效本人照片，基础穿搭不足或引用源已删除时拒绝并提示编辑；一次规划和一次生图，不复用可能已过时的评价。每个Job保留生成时完整输入和资产引用，既有历史不覆盖。无配置返回503 GENERATION_UNAVAILABLE；revision不匹配409 OUTFIT_CHANGED；同key异请求409 IDEMPOTENCY_CONFLICT；未配置模型/图片预算仍保留现有安全门禁。

前端保留未确认提交键，同key查询或重发找回；只在明确终态失败且actions允许时用新key重试。活动状态3秒可见页轮询，UNKNOWN停止自动轮询，不自动重发。任务可能在搭配修改后完成，仍关联旧revision，不能当成当前结果。

## 后端内部协作约定

T1 提供 `OutfitService.detail(Long user,String id)` 返回 OutfitDto，及 `snapshotForGeneration(Long user,String id,String revision)` 返回 Map：`id,name,note,revision,items`（items为上述单品快照列表，含 features）。T2在账号锁事务内调用，T1不发外部请求；T2按当前快照保存固定候选与任务资产。若现有生成输入需更多图片字段，由T2根据fileId查询本人资产补齐，不读取当前衣橱替换快照。

V4由T1维护，保存 outfit、outfit_item、outfit_item_asset、outfit_group、outfit_group_member 等；文件清理 directReferences 必须包含独立搭配引用。V5由T2维护任务关联表及必要增量。T1先将兼容检查推进V4，再通知T2接续V5。两个迁移只在隔离环境运行；ops显式执行。


## 实施补充

Outfit增加可空`sourceOutputFileId`：从成功设计保存时独立保留原效果图引用，删除源设计不会释放搭配仍持有的文件。原图对应初始revision=0，后续单品或穿法修改后只能作为历史图展示，不能标为当前效果。V6增加对应列，资产引用仍在outfit_item_asset中维护。


从设计复制时，自动采用的标题与穿法分别按Unicode码点取前100/2000字符，原设计内容保持完整；用户显式输入的名称继续严格校验，不截断。TaskSummary的outfitId/jobKind对普通任务为null；搭配任务的inputSummary.requiredDresses与既有设计摘要使用相同的dressName字段，旧name型快照只在读取投影时兼容，不改写历史输入。

# 我的衣橱首屏实施计划

2026-11-25，用户确认按交互稿改造小程序「我的衣橱」。初始视图为「衣物 / 全部」，优先让用户按分类找单件。沿用当前账号的服务端分页、衣物编辑页与搭配管理入口。[需求说明](01-需求说明.md#2026-11-25-我的衣橱首屏讨论)

- [x] T1 页面布局。修改 `apps/miniapp/src/pages/wardrobe/index.wxml` 和 `index.wxss`。在暖白标题栏下同排放文字页签和随页签切换的添加按钮。衣物页显示横滑分类、当前结果总数、最近添加和双列方图。搭配页显示分组入口及 3:4 封面，保留置顶、件数和场景。空分类可点「查看全部衣物」，空衣橱可添加衣物。保留现有图片失败、分页、加载反馈与详情跳转。核对 320px 和 390px 屏宽。
- [x] T2 列表与封面。修改同页 `index.ts`，按需补充小程序测试。切换分类时直接查所选分类第一页，切换过程中清掉上一个条件的结果，点已选分类无需重查，刷新和翻页仍可重试。衣物摘要省去与名称相同的分类。搭配有来源图时使用该图；手动搭配取最多两件不同衣物的首图并排，只有一张可用图时铺满，无图时给占位。沿用私图缓存和账号隔离。T1 与 T2 使用 `item.metaLabel` 显示衣物摘要、`item.coverParts`（每项含 `fileId`、`url`）显示搭配图；分类重置复用 `chooseCategory`。
- [x] T3 验证与交付。T1、T2 合入后在 `apps/miniapp` 运行 `npm test` 和 `npm run build`。在隔离的微信开发者工具项目验证「全部 → 下装 → 单品详情 → 返回」、空分类恢复、两处添加入口、搭配卡与分组入口。检查长名称、缺图、窄屏布局，保存截图，同步需求和功能总览。

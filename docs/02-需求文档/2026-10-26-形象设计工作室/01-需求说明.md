## 目标与现状

让用户围绕自己的照片表达设计意图，减少选填表单和重复信息带来的负担。首次使用能发现上传入口，已有照片和衣橱的用户无需重复填写个人资料。

当前创建页按模式、照片、要求、必穿单品分卡片纵向排列，右侧为提交摘要；确认弹窗展开个人资料；详情页先展示任务信息，再展示效果图和文字。现状依据 `NewDesignPage.tsx`、`PreviewDetails.tsx` 和 `DesignDetailPage.tsx` 的静态核对，未将代码检查当作视觉验收。

业务规则沿用[首版需求](../2026-10-20-首版个人形象设计/01-需求说明.md)、[领域模型](../../01-项目总览/02-领域模型.md)和[生成技术契约](../2026-10-20-首版个人形象设计/03-生成技术契约.md)。本次调整信息层级和操作呈现，不改变生成、权限、收藏及重试条件。

## 页面与视觉

桌面宽屏采用左侧约 55%、右侧约 45% 的两栏布局。左侧承载本人照片和效果图，右侧承载当前阶段的操作与说明。沿用全局导航，以暖白背景、深色文字和少量绿色强调选中状态及主操作；减少重复卡片边框。照片使用完整展示方式，不为填满容器裁掉头部或脚部。

```text
形象设计
今天，想看见怎样的自己？
┌─────────────────────┬────────────────────┐
│                     │ 整体设计 / 发型 / 穿搭 │
│      本人照片        │                    │
│                     │ 这次想尝试什么？     │
│                     │ [自由描述……]        │
│                     │ 场合快捷标签         │
│ 更换照片             │ 更多条件 ▾          │
│ 必穿单品小图 / 添加   │ 个人偏好摘要         │
│                     │ [继续，确认设计]     │
└─────────────────────┴────────────────────┘
```

线框用于说明层级，不作为最终尺寸图稿。窄桌面窗口优先保障输入区可读、按钮可见；空间不足时上下排列。目标是常用创建操作集中在一屏到一屏半，长内容允许自然滚动，不通过裁切内容达到目标。具体间距、图片高度和断点留待可查看图稿核对。

## 创建与确认

2026-10-26 补充修正：上述候选缩略图规则也适用于“从衣橱添加”抽屉中的衣物候选。正常加载不显示刷新按钮，图片等比 cover 填满图框；失败保留重试。工作室主图和结果图仍完整展示。

2026-10-26 补充：照片候选列表正常加载后不显示刷新按钮；照片等比缩放并裁切边缘以填满图框。加载失败保留重试入口。仅候选缩略图采用此规则，工作室主图和效果图继续完整展示。

1. 照片区默认展示本次使用的本人照片。无照片时展示上传入口和拍摄建议；选中后显示“更换照片”，选择照片库与上传合并在该入口内。上传未完成时不得提交，失败在照片区域提供恢复操作。临时上传仍只用于本次设计，不自动入库。
2. 模式在右侧顶部切换，只展示相关输入；发型模式隐藏必穿衣物与天气。模式切换后的照片适用性应有清晰提示，不静默替换用户手选照片。沿用进入页面时按模式读取默认照片的行为，已有照片时不自动替换。
3. 自由描述为主要输入。场合标签只辅助选择并支持自定义，未填写按既有默认规则处理。风格、天气、尺寸选项按需展开，有值时显示摘要。长期偏好默认展示摘要，可查看完整内容；不要求重新填写。
4. 必穿单品默认显示“由 AI 从衣橱搭配”及添加入口。抽屉内筛选、分页选择，关闭后保留选择；主页面以缩略图显示已选单品并允许移除。分页使用服务端 page、pageSize、items、total 和 Ant Design 分页，不全量拉取切片。
5. 主按钮为“继续，确认设计”。确认层优先展示照片、模式、当次要求、必穿单品及明确限制；个人资料和尺寸详情折叠展示。最后由“确认并开始生成”提交，不自动发起生成。
6. 冲突在相关要求旁说明，提供修改输入或既有的“仅本次允许”操作。调整例外后自动重新核验，核验完成且对应最新输入之前禁止提交；旧响应不得覆盖新输入。一般偏好和明确限制仍按既有规则区分。

## 连续体验与任务链接

创建入口保留 `/app/design/new`；提交被接受后更新为 `/app/designs/{id}`，在同一工作室布局中切换内容，避免视觉上重新进入一套任务管理页面。连续体验指布局和内容承接，不要求浏览器地址不变。

刷新、重新登录或从设计记录打开任务链接时，从服务端恢复对应任务状态，不重新提交。离开生成页面不影响后台执行。生成中的输入显示为只读摘要；修改要求通过“调整要求再设计”创建新任务，不修改原任务快照。

| 阶段 | 图片区域 | 说明与操作区域 |
| --- | --- | --- |
| 创建 | 本人照片、必穿衣物缩略图 | 模式、要求、确认入口 |
| 排队与生成 | 保留原照片并明确标为原照片；效果图尚未生成 | 展示真实阶段，可离开页面；已保存文字可查看 |
| 保存结果 | 不将尚未可靠保存的结果当作成功 | 显示正在保存，不提供完整成功操作 |
| 完整成功 | 大效果图，支持与原照片切换 | 简短方案、单品与穿法、收藏及存为常用搭配等可执行操作 |
| 确认失败 | 无图时提供清楚的状态占位 | 保留已完成文字，按失败阶段提供服务端允许的重试操作 |
| 结果待确认 | 不误报失败或成功 | 说明仍在核实，不自动再次生成；沿用现有找回与隐藏规则 |

不展示推测的百分比或完成时间，不增加规划完成后的人工确认步骤。提交响应不确定时保留原编号和输入，先找回原提交；沿用既有幂等恢复流程。

## 结果阅读

效果图为首要内容，右侧先展示简短方案说明，再展示相关操作。原图与效果图明确标识，不暗示精确试穿。选用衣物以小图配具体穿法展示；详细理由、发型建议和本次输入快照按需展开。重要限制、近似满足说明及示意鞋来源仍按既有规则出现在图片附近，不收进默认折叠内容。

收藏、存为常用搭配、调整要求再设计按任务实际能力显示。仅文字成功不提供完整设计收藏。任务编号等次要信息放入详情区域；历史无效果图记录仍可阅读已有内容。

## 能力边界与失败处理

所有照片、衣物和任务沿用当前账号权限。图片读取失败保留说明和重试入口，不能以无关模特图伪装用户结果。资料过期、上传失败和输入错误在对应区域解释并保留可恢复输入。

生成默认关闭及当前供应商对穿搭、整体设计的限制继续有效，不通过 UI 改版启用能力或丢弃衣物参考图。模式不可用时应在开始生成前明确解释原因；现有接口能否支持进入页即展示能力状态，在实施前核对，不预设新增接口。

不新增聊天式生成、自动抠图、自动天气查询、后台通知服务或数据库迁移。现有接口与状态为复用基线；连续页面不要求新增后台任务类型。

## 验收与后续

- 无默认照片时能直接找到上传入口；已有照片且不填选填项时可以进入确认，仍遵守衣橱完整性和供应商能力限制。
- 选衣抽屉跨页保留已选项，主页面可移除，提交内容与选择一致。
- 确认层可查看完整依据，例外修改后重新核验，慢响应不会误放行旧输入。
- 创建、生成中、成功和失败具有连续布局；刷新及直接打开任务链接不会重复生成。
- 文字成功图片失败、结果待确认、上传失败、图片加载失败和生成不可用均有明确状态及合法操作。
- 效果图完整展示；必要提示紧邻图片；键盘可操作选择器、抽屉与确认层，关闭后焦点返回触发入口。
- 后续图稿检查宽屏与窄桌面、长要求、多件必穿衣物和长方案，确认布局后再按实施授权执行。

实施结果：创建与详情采用约 55/45 双栏，1100px 及以下上下排列；主图完整展示，详细尺寸见本轮页面截图。切换模式保留已选照片并提示适用范围。现有接口没有独立能力查询，本轮在预览阶段展示不可用原因并禁止提交，未新增接口。构建、44 项自动测试和隔离页面代表场景通过；真实服务、上传和供应商端到端联调不在本轮验证结论内。

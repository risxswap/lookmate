# 搭配详情页布局实施计划

2026-11-26，范围为小程序已保存搭配的查看态。[需求与既有约定](01-需求说明.md#2026-11-26-详情页布局)

- [x] T1 查看页排版。修改 `apps/miniapp/src/pages/outfit-detail/index.wxml` 和 `index.wxss`。首屏排紧名称、编辑、真实场景与置顶信息，主图或最多四件单品拼图紧随其后。当前上身图可预览及保存，生成操作仍先选择本人全身照。当前上身图及占位使用 3:4 画框，避免矮屏单独压低画框高度；保留等比例铺满、缺图重试及已删除衣物提示。重新组织单品条、穿法笔记和日历次要入口、AI 摘要及历史的层级。用 `item.metaLabel` 显示单品信息，空值略去。样式限定在查看态。
- [x] T2 单品信息。修改同页 `index.ts`，复用衣橱现有名称、颜色和分类的摘要规则，必要时将该规则放入 `features/dresses.ts` 并更新衣橱的调用处。详情使用搭配快照，保留原有图片复用、缺失标记、顺序及分页。根据需要在 `tests/outfit-detail.test.mjs` 补充回归。
- [x] T3 验证。合入 T1、T2 后在 `apps/miniapp` 执行 `npm test`、`npm run build` 和微信原生编译。在 320px、390px 隔离微信模拟器验证当前上身图、单品拼图、预览、编辑与取消，检查日历入口、建议、历史及照片选择；覆盖长标题、无图或缺失衣物。记录截图、实际验证范围及真机缺口。

两种屏宽的微信模拟器都已核对当前效果图、单品拼图及主要入口。157 项小程序测试、构建和 19 个页面路由检查通过；微信原生编译器通过 30 份 WXML/WXS 和 28 份 WXSS。[验证记录与截图](../../testing/02-checks/2026-11-26-小程序搭配详情布局.md)

# 首版个人形象设计需求

创建日期：2026-10-20。最后更新：2026-10-20。

本文件重新整理此前已确认的首版需求。业务范围已确认，技术参数与整体数据库设计仍待审阅；尚未实施或执行行为验证。本次文档重写不新增搭建、编码或部署授权。

## 背景与目标

个人用户希望用本人照片、可选尺寸和衣橱单品尝试发型或穿搭，得到效果图与简短说明，并在离开页面后继续查看生成结果。首版由 AI 自动完成设计，以桌面浏览器为使用平台。

## 范围与角色

首版实施用户服务端 `server` 和用户 Web `web`。访客可以查看公开介绍页并注册、登录；用户从统一形象设计入口选择整体设计、只改发型或只改穿搭，管理自己的资料、照片、衣物、任务和收藏。页面采用工作台、设计记录、我的衣橱、个人资料四项菜单，详见 [页面与菜单布局](../2026-10-20-前端页面与菜单布局/01-需求说明.md)。

不包含手机适配、小程序、原生 App、运营后台、收费、真人设计师流程、多轮对话或局部图片编辑。手机号、第三方登录、找回密码、“记住我”和设备管理页面不在首版范围。备份方案已暂缓；后台结果暂存和进程恢复仍保留。

## 业务定义与权限

[领域模型](../../01-项目总览/02-领域模型.md)集中维护账号、尺寸、照片、衣物、任务、收藏和删除规则。所有私有资源按账号隔离；用户不能读取其他账号的资源或取得其图片签名，不提供其他用户作品浏览。已签发的短期图片链接在有效期内可被持有者使用。

## 用户流程与可见结果

| 流程 | 触发操作与成功结果 | 关键失败、限制与关联规则 |
| --- | --- | --- |
| 注册与登录 | 注册成功进入登录页；登录后进入工具；退出结束当前会话 | 注册开关控制开放；用户名全局唯一；会话超期须重新认证 |
| 维护个人资料 | 保存显示名称与完整尺寸历史，切换或删除当前尺寸 | 尺寸可全空；历史不原地修改；过期编辑版本保留输入并提示比较 |
| 准备照片 | 上传并通过核验，可临时使用或保存照片库，设置默认照片 | 不支持的格式、超限或核验未完成的图片不可提交；发型和穿搭分别预选默认头像、全身照 |
| 维护衣橱 | 录入或编辑单品图片、名称、类别及可选资料 | 必填资料与固定类别规则见领域模型；不强制自动识别或抠图 |
| 提交设计 | 选择本人照片、文字要求、可选必穿单品及尺寸；预览本次输入后提交 | 每次 1 张本人照片、1 张效果图；穿搭不指定必穿单品时从已有衣橱自动选衣，可不使用尺寸；账号名额与容量不足时明确提示 |
| 查看任务 | 页面关闭后后台继续，再次打开可查询阶段与结果 | 重复提交不新建额外任务；活动任务按约定轮询，结果待确认停止持续自动轮询 |
| 处理失败 | 用户手动重试，创建关联原任务的新任务；可复用已成功文字方案重试生图 | 不将结果未知当成确定失败，不自动重发生图；仅文字成功不属于完整成功 |
| 整理收藏 | 收藏本人完整成功方案，建立或调整多个收藏夹归属 | 收藏夹名称规则与取消、删除行为见领域模型 |
| 删除与清理 | 删除允许删除的任务、照片或衣物；隐藏结果待确认任务 | 活动任务不能删除或取消；图片按引用保留；隐藏不取消供应商调用 |

## 验收条件

以下为计划验收结果，尚未执行。实现后在本需求中记录实际验证证据，复杂时再拆分验证记录。

- 两个账号不能通过业务 API 读取对方资源或取得对方图片的访问签名；已签发图片链接在有效期内可被持有者使用，与私有签名访问约定一致。
- 尺寸修改及当前值切换不改变旧任务的输入；默认照片可在提交前替换。
- 所选衣物和本人照片进入生图请求；关闭尺寸后该次任务不使用尺寸数据。
- 重复提交、页面关闭、生成失败和结果未知分别呈现正确状态。
- 模型切换不改变已有任务的模型选择，手动重试可追溯原任务。
- 删除衣物、照片、方案或收藏夹时遵循各自的保留和清理规则。
- 注册成功进入登录页；退出仅结束当前会话，空闲期限和登录绝对期限分别生效。
- 尺寸全部清空后保存为新的完整历史记录；删除当前记录后不自动选择其他记录。
- 未通过核验、已过期或正在清理的图片不能用于业务提交；上传失败时呈现可理解的原因。
- 采用版本校验的个人资料、图片人工修订和收藏夹中，过期编辑版本不能覆盖新值；前端保留用户输入并提示刷新比较。
- 容量达到限制时明确拒绝新增工作，保留已接收任务；结果待确认不触发自动重发生图。
- 仅完整成功的方案可以收藏；取消收藏、删除收藏夹和删除方案分别产生约定结果。

## 身体尺寸细化（已确认，尚未实现）

按讨论扩充至 27 项可选尺寸，涵盖身高体重、躯干、肩背、手臂、腿部、头围及左右脚长脚宽。使用 DECIMAL(6,2)，字段不带单位后缀，体重为 kg，其余为 cm；不增加测量时间、方式或备注。完整字段见 [数据库设计](../../01-项目总览/04-数据库设计.md)。新增记录、当前值和任务快照沿用既有规则；后续验收应覆盖各字段保存与回显、空值、两位小数及历史快照不随当前值变化。当前仅更新 SQL 和文档，尚未运行数据库或前后端验证。

## 穿戴命名与必填图片（已确认）

穿戴单品表改为 dress，分类表对应 dress_category，涵盖帽子等饰品。每条穿戴记录必须有至少一张已核验且属于当前用户的图片，允许多张，第一张作为封面。dress_image.asset_id 保留 NOT NULL；整组不能为空和关联有效性由代码处理。图片集合一次保存后触发整组识别，识别值逐图保存，人工修订优先，执行信息位于独立 dress_recognition。尚未实现应用校验。

## 衣橱自动搭配与图片理解（已确认）

系统从用户实际拥有的单品中自动搭配，用户可指定必穿单品；首版只使用已有单品，缺少时提示。DeepSeek 负责图片理解与规划，用户可以修正识别结果，GPT Image 2 负责效果图。结果展示单品清单及说明并保留来源快照。此决定替代此前可不依赖衣橱自由生成、图片只作生图参考的方案。已确认入库及换图后识别，识别失败保留单品，支持重试或手动补齐。识别字段、调用归属及候选快照已写入 SQL，尚未执行迁移或实现应用行为。

识别状态与特征持久化已生成 SQL 草案：验证目标包含识别失败仍可管理单品、换图后旧结果不能覆盖、人工修订优先，以及输出单品清单属于提交时固定的本人衣橱候选。详细数据契约见数据库设计；这些行为尚未运行验证。

衣橱单品 dress 不做编辑版本冲突控制，按服务器最后成功保存为准，移除 version 及 manual_confirmed_revision。手动补齐直接保存，设计提交时校验资料和图片，不增加独立确认步骤。图片集合 image_revision 仍保留，用于识别结果有效性判定。

## 方案固定栏目（已确认，仅设计）

方案固定展示名称、概述、风格、场景和设计理由。穿搭补充配色与整体穿着建议，并逐件展示实物快照、选择理由和穿着方式；发型展示名称、长度、刘海、分缝、卷直、发色和打理说明。数据分别由 design_result、design_result_item、design_result_hairstyle 保存；首版不采用任意段落结构。SQL 已按该决定更新，具体字段见数据库设计；尚未执行迁移或实现业务代码。

## 统一形象设计（2026-10-20 已确认，待实现）

整体设计在同一任务中完成发型与穿搭，用户也可选择只改发型或只改穿搭；业务定义见 [设计与任务](../../01-项目总览/02-领域模型.md#设计与任务)。此决定替代两类独立入口，保留每次一张本人照片、一张效果图的既有边界。

现有数据库及接口的两类模式与互斥明细尚未适配整体设计。实施前需细化模式编码、字段适用性、结果明细校验及迁移方案；本轮未修改 SQL 或接口实现。后续验收需覆盖三种模式、整体方案同时呈现两部分说明，以及任务快照和重试保留所选模式。

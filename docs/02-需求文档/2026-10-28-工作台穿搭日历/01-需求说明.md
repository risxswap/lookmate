# 工作台穿搭日历

创建日期：2026-10-28。用户已确认核心规则、认可独立预览，并授权正式代码实施。现已完成前后端实现和隔离开发验证；共享开发库及生产尚未执行 V8 迁移。完整契约见[正式实施计划](03-正式实施计划.md)，验证范围见[开发检查](../../testing/02-checks/2026-10-28-工作台穿搭日历.md)。

## 已确认方向

- 工作台增加日历与场景穿搭，以提前安排“哪天穿哪套”为主。
- 一天允许多套搭配，按需增加，不强制填写时间。
- 场景采用预置选项并允许自定义。
- 计划保留安排时的单品组合与穿法；修改常用搭配不会自动改变计划，主动替换时才更新。
- 进行中的任务和最近设计改为紧凑列表，减少空间占用。

沿用[现有工作台](../2026-10-20-工作台/01-需求说明.md)、[常用搭配](../2026-10-22-常用搭配/01-需求说明.md)和[领域模型](../../01-项目总览/02-领域模型.md)中的账号隔离及资源规则。

## 实施规则

主区域采用周历与当天安排，月历用于选择日期；右侧展示任务和最近设计，下方按场景浏览常用搭配。首页保留标题和设计主入口，准备资料入口收紧为链接。

2026-10-29 用户要求“准备下一次设计”更醒目：保留侧栏位置与三个跳转目标，增加浅绿色背景、左侧强调线和更清晰的标题；三个资料入口使用可识别的按钮外观，保留键盘焦点与悬停反馈。仅调整展示，不新增数据查询或业务规则。视觉强化已实现并通过构建及浏览器验证，见[计划 T4](03-正式实施计划.md#t4-准备下一次设计视觉强化2026-10-29)。用户随后要求准备区独立成块：从任务卡片中移出，作为右侧独立卡片展示，已实现并完成1280/1024浏览器复验，见计划T5。

场景预置通勤、日常、约会、运动、聚会、旅行；场景与常用搭配分组独立，一套搭配可标记多个场景。允许先填写日期和场景、稍后选衣；安排按创建时间和 ID 倒序分页。场景最多 20 字，备注最多 80 字。日期使用本地日历日期，不转换为 UTC 时刻。

原搭配删除后保留计划、快照和图片，并提示来源已删除；原衣物删除时标记缺失，不移除快照。仅修改日期、场景或备注时不更新搭配快照，显式替换才重新读取搭配。计划修改和删除受版本保护，新增使用请求键避免重试重复创建。

可带场景进入已有设计页面，但不自动提交生成；生成结果沿用现有保存常用搭配流程，再选入日历。不包括实际穿着记录、天气、提醒、拖拽排序或生成后自动关联。

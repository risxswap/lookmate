# 工作台穿搭日历正式实施计划

2026-10-28。用户已认可可点击布局并明确授权实现代码。本计划依据[需求说明](01-需求说明.md)和独立预览，保留正式应用的导航、色彩及响应错误约定。

## 实施范围与规则

- 正式工作台采用左日历与当天安排、右任务和最近记录、下方场景搭配。周历为主，月历用于选日；今天按浏览器本地日期，计划日期是 YYYY-MM-DD，不做 UTC 时刻转换。
- 一天可多条安排；场景必填（最多20字），默认日常；备注可空、最多80字。不要求时刻。允许只记场景、稍后选搭配。按创建时间和ID倒序，使用服务端分页。
- 场景预置通勤、日常、约会、运动、聚会、旅行；可自定义。场景与现有分组分开，一套搭配最多20个场景，用户在场景搭配区为搭配设置场景。复用现有搭配，不自动推断或给存量搭配分配标签。
- 计划独立保存安排时的搭配名称、单品组合、穿法及图片引用。后续修改常用搭配不追溯更新；仅显式替换时读取最新内容。原搭配删除保留计划及图片，标记来源已删除；原衣物删除显示缺失但保留快照。删除计划或替换搭配仅释放该计划的引用，清理继续核查全部有效引用。
- 计划属于当前会话账号；写入先锁user，使用版本保护；拒绝未知字段、跨账号引用和不可用文件。新增用clientRequestId在计划存续期内幂等，重试保留同键；删除后不保证旧键幂等。
- 不实施实际穿着记录、天气、提醒、拖拽排序、自动生成或生成后自动关联。可带场景进入已有设计入口，生成结果可沿用现有保存常用搭配流程，再选择到计划。
- V8由ops显式迁移；仅在隔离环境验证，不迁移共享开发库或生产，不自动重启正在使用的共享后端。

## 固定接口契约

沿用标准data包装、字符串ID/version、UTC createdAt/updatedAt及Page `{items,page,pageSize,total}`；日期范围from/to包含端点，最大42天。通用分页默认1/20、最大100。

### 场景与搭配

- `GET /api/outfit-scenes?page=1&pageSize=20` → Page<{name:string}>；预置顺序固定，用户自定义按创建时间/ID倒序，其名称与预置去重。场景从创建计划或设置搭配标签时保存，不提供删除/重命名接口。
- `GET /api/outfits` 增加可选 `scene` 精确过滤，与groupId取交集；保留既有置顶优先和分页；OutfitDto增加 `scenes:string[]`，旧接口字段不变。
- `PUT /api/outfits/{id}/scenes` `{version:string,scenes:string[]}` →200 OutfitDto；空数组清除，重复名称去重，校验每项非空最多20字、最多20项；更新outfit.version，不改变revision。

### 日历计划

- `GET /api/outfit-plans?date=YYYY-MM-DD&page=1&pageSize=20` → Page<OutfitPlan>。
- `GET /api/outfit-plans/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD` → `{days:[{date:string,count:number}]}`；仅返回有记录日期，聚合数量用于周/月标记，不返回全量记录供前端分页。
- `POST /api/outfit-plans` `{clientRequestId:string, date:string,scene:string,note?:string|null,outfitId?:string|null}` →201 OutfitPlan；clientRequestId为UUID，重复相同规范化载荷返回原记录，不同载荷409 IDEMPOTENCY_CONFLICT。
- `PATCH /api/outfit-plans/{id}` `{version:string,date?:string,scene?:string,note?:string|null,outfitId?:string|null}` →200 OutfitPlan；未传保留，note:null清空；outfitId未传保留原快照，null清空，同ID显式传入也刷新为当前快照。
- `DELETE /api/outfit-plans/{id}?version=...` →200标准响应。
- OutfitPlan: `{id,version,date,scene,note,sourceOutfitId,sourceMissing,outfit,createdAt,updatedAt}`。note/sourceOutfitId/outfit可null；sourceMissing为boolean；outfit为保存时OutfitDto，groups/scenes也可保留但不据其动态覆盖计划；items.missing读取时核对，其他快照内容不变。
- 非法字段/日期/分页400 INVALID_REQUEST；他人及不存在404 OUTFIT_PLAN_NOT_FOUND或OUTFIT_NOT_FOUND；版本409 VERSION_CONFLICT；文件409 FILE_NOT_USABLE。创建结果未知时保留请求键和输入，手动重试同一载荷；变更载荷需新键。更新/删除结果未知不自动重试或换版本覆盖，保留输入并提示刷新核对。

## 数据设计

V8新增outfit_plan（user/date/version/scene/note/source_outfit_id/snapshot JSON/client_request_id/request_hash、时间，账号请求键唯一、账号日期创建排序索引）、outfit_plan_asset（plan_id/asset_id唯一、资产引用索引）、outfit_scene（outfit_id/name唯一、账号场景索引）、outfit_scene_option（账号name唯一）。所有业务表主键、user_id、created_at、updated_at，无外键。名称比较与项目utf8mb4_bin保持一致。

计划快照和资产引用同事务写入；资产按ID升序锁定与校验。旧搭配删除需清除outfit_scene，不删除计划。FileMapper.directReferences必须包含outfit_plan_asset。应用兼容检查要求V8且读取新表所需列。

## 目标与范围

衣物图片上传后自动去除背景，衣橱展示透明抠图，减少拍摄背景对展示的干扰。首版只做去背景，不重绘衣物，不增加真人穿搭照服装提取、衣架修补、衣物识别或生图能力。挂拍衣架可能残留，不承诺自动去除。

## 已确认的预期行为

1. 用户上传衣物图片到七牛，server 完成现有文件核验后立即发起抠图，不等待衣服保存或图片绑定；用户侧异步等待结果。
2. server 后台直接调用本地 ONNX 推理组件取得透明 PNG，保存至七牛并更新处理状态；不在用户上传请求内等待推理。
3. 衣橱展示抠图后的衣服；用户不满意时可重新上传照片，核验后自动抠图。保留未抠图源文件，不再将切回原图作为正常展示选择。抠图失败不阻止衣服保存；首次结果未就绪和换图处理期间的具体展示待细化。
4. server 统一负责用户权限、图片归属、任务状态、失败重试及存储，不增加独立图片服务或内部 HTTP 接口。
5. 文件核验、方向修正、元数据处理与缩略图逻辑继续由 server 负责；本地抠图处理同样遵守输入大小与像素上限。透明图及其缩略图不能沿用当前统一转 JPEG 的处理方式。

服务技术边界以 [架构设计](../../01-项目总览/03-架构设计.md#server-内置衣物抠图2026-10-23已确认待实现) 为准，取舍见 [技术决策](../../04-技术决策/2026-10-23-server内置衣物抠图.md)。既有衣橱行为见 [我的衣橱](../2026-10-20-我的衣橱/01-需求说明.md)。

## 验证范围（待执行）

- 上传并核验后无需保存衣服即可开始抠图，成功后衣橱展示透明 PNG；其他账号不能访问源图、结果或替换该衣物照片。
- 用户不满意时可重新上传照片，核验后自动抠图；不把未经确认的“切回原图”作为该操作的替代。
- 模型不可用、处理失败或超时时，衣服与原图仍保留，不显示虚假的处理成功。
- 输入超过限制或容量已满时明确拒绝，不出现无界并发或排队。
- 使用白衣白底、黑衣暗背景、细肩带、蕾丝、衣架和复杂背景样本检查漏抠、误删和残留；记录模型版本、硬件、输入尺寸、单张端到端耗时与峰值内存。质量合格标准及性能目标待确定。

## 实施前待完善

- 模型及权重版本、来源和授权；RMBG-1.4 与 BiRefNet 轻量版均为候选，没有选定默认模型。
- ONNX Runtime Java 的具体版本、Java 21 与部署平台的兼容性、CPU／GPU 运行组合和实际资源配置。
- 本地组件的输入输出、错误分类、模型就绪条件、原生资源释放及超时后的并发名额管理。
- 简单处理状态、重新上传照片入口，以及换图后防止旧结果覆盖新图；首版不展开复杂高可用和自动恢复机制。
- 原图／抠图关联、历史引用和清理方案；本轮不设计表或迁移。
- 衣物识别和设计生成使用哪种图片、已有衣物是否补处理，以及首次处理和换图处理期间的展示。

本轮只保存设计，不再规划 apps/image 工程；未创建实施计划或修改代码、数据库和运行配置。

## 首版简化范围与剩余问题

2026-10-23 用户明确：上传完即抠图，展示抠图后的衣服，不满意可重新抠图；前期不要求完善的高可用设计。上传触发和展示方向已确定，不再作为待确认问题。保留输入限制、账号权限、有界并发、失败提示及旧结果不能覆盖新图等基本正确性要求，不扩展独立任务服务、复杂自动重试、模型热切换或多实例容灾。

用户进一步确认：“重新抠图”指重新上传一张照片，再自动执行抠图。首版不提供对同一张照片反复推理的独立入口，也不增加参数调整、模型切换或人工修边。此规则针对效果不满意的处理，不替代执行失败时的错误处理。

重新上传的照片必须重新核验，不允许绕过现有文件核验规则。识别／生成使用哪种图片尚未确认，不根据展示规则自动替换模型输入。首轮处理中的占位展示、换图处理期间是否保留上一张结果，以及失败后的展示方式待细化。

# 实施计划

依据[需求说明](01-需求说明.md)，用户已授权修复并确认同步图库至七牛。主agent负责调查、契约、审查、真实同步与验证，两个子agent分别处理服务端与小程序。保留现有工具链和业务快照语义。

## T1 服务端与同步工具

负责服务端Java、定向测试及 `tools/sync-catalog-assets.mjs`，由后端子agent实施。

- [x] 为两类平台图片增加受鉴权access端点，variant及响应遵循需求说明。
- [x] 复用ObjectStorage/QiniuObjectStorage与现有目录校验，按不可变key生成带缩图参数的签名URL。原图接口和送模快照保持现有语义。
- [x] 普通THUMBNAIL保留320×320并补WebP质量80，图库THUMBNAIL使用480×640质量80，DISPLAY使用1280×1280质量85。
- [x] 编写无新增运行依赖的Node.js同步工具，读取根目录现有properties格式 `.env.dev` 或显式配置路径。同步全部已登记版本图片，使用现有上传域名、空间及凭据，校验已存在对象，失败可重跑，不打印凭据或签名URL。
- [x] 通过定向测试覆盖非法资源、variant、签名参数顺序、同步key算法与旧原图行为，运行Java21下Maven格式检查与相关测试。

## T2 小程序

负责 `apps/miniapp/src` 及对应测试，由小程序子agent实施。与T1共享的只有需求中的HTTP契约。

- [x] displayUrl申请同源平台资源的access地址，使用THUMBNAIL默认值，详情指定DISPLAY，缓存按账号、原始资源和variant隔离。
- [x] 保留wx.downloadFile，七牛下载不携带业务token，失败可重试，继续校验账号。
- [x] 普通用户列表及头像请求THUMBNAIL。列表缩图后的个人照片主动预览按需申请DISPLAY，效果图保存与原图路径保持可用。
- [x] 回归缺图保留目录、分页、图片变体、鉴权发送范围及失败重试，运行npm test与npm run build。

## T3 集成与交付

主agent在T1/T2完成后执行。

- [x] 审查跨层URL、签名、原始快照兼容及差异，问题交回实施子agent修正。
- [x] 实际同步现有七牛空间并记录数量与重复执行结果，使用签名URL验证缩图尺寸与字节数。
- [x] 验证运行服务的更新方式，在授权和可用环境范围内完成开发者工具代表路径复验，记录需要的服务重启或后台配置。
- [x] 同步功能总览、架构、接口契约与文档导航，记录实际结果和未验证项。

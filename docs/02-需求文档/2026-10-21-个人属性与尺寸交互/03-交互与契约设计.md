# 个人属性与尺寸交互：设计细化

日期：2026-10-21。依据 [已确认需求](01-需求说明.md)。本文件为已确认技术设计，正式前后端与V2迁移代码已实现，隔离环境开发验证见实施计划和验证记录；生产及共享开发库未迁移。业务决定沿用需求，本文给出字段、契约和状态处理的具体方案。图稿是布局设计，测量线仍需在实施时逐项绘制和核验，不代表已完成可用页面或标准人体测量插图。

## 页面及视觉规格

保留现有侧栏、字体、Ant Design 控件和浅底绿色强调风格。四个标签的深链接为 `basic / photos / measurements / preferences`；非法 tab 回到 basic，原有深链接继续可用。页面范围仍为桌面浏览器。

图稿：[尺寸填写](04-尺寸填写图稿.svg)、[兴趣与偏好](05-兴趣偏好图稿.svg)。示例值仅用于布局，不作为默认用户资料。

内容区宽度至少 1120px 时，尺寸编辑区由约 720px 的人体填写区及 280px 测量说明组成；不足时说明移到填写区下方。输入框保持至少 140px 宽，不随人体缩小。主体图使用已确认的中性灰矢量剪影，背景低对比，测量路径加粗并使用端点、箭头与文字。围度的隐藏路径虚线表示；体重只显示输入和称量说明。底部保存栏在资料内容区内吸底，不遮挡输入和历史；历史每页 10 条。

初始进入选常用尺寸，不自动聚焦输入框；说明区提示选择要了解的尺寸。聚焦字段后显示对应说明，不抢焦点。每个字段提供可键盘操作的“如何测量”入口。切换组保留草稿，切组后说明区重置为该组提示；正背面只决定可见字段，非可见字段照常保存和校验。

| 视图 | 字段（全部来自既有 27 项） |
| --- | --- |
| 常用／正面 | height、weight、chest、waist、hip |
| 躯干／正面 | neck、chest、underbust、waist、abdomen、hip、shoulder、frontWaistLength |
| 躯干／背面 | backWidth、backWaistLength；肩宽可显示只读辅助定位，不增加第二份数值 |
| 手臂 | armLength、upperArm、forearm、wrist |
| 腿部 | inseam、outseam、thigh、knee、calf、ankle |
| 头部与脚部 | head、leftFootLength、leftFootWidth、rightFootLength、rightFootWidth |

每项测量说明沿用当前 `measurementGroups` 中的定义：图的起止点、绕行路径必须与该定义一致。内腿长到地面、外腿长从腰线到地面，不改为成衣裤长。长度图标起点终点；围度图标绕行及水平关系。左右脚是本人左右。头脚组使用多个独立局部图，不将所有输入叠到一个全身图。实施验收对全部 27 项逐一核对；素材不是医疗或裁剪精度承诺。

偏好页填写顺序、自定义输入、即时冲突提示与保存反馈按 [需求说明中的已确认填写体验](01-需求说明.md#偏好页填写体验已确认待实施) 执行，尚待实施。各组依次排列，标签换行，不设置横向滚动标签带；名称加色块表达颜色。每个多选显示已选数量，补充文字显示字符数。明确限制单独成组并解释其与一般不喜欢的区别。完整字段均可通过键盘访问，不用颜色作为唯一状态提示。

## 日期及基础字段

- `gender`：接口与数据库均为 `FEMALE / MALE`，基础资料可 null。数据库类型 VARCHAR(16)，默认 NULL，不给已有用户或注册用户填女；尺寸表单初始化的默认女只存在页面草稿。
- `birthDate`：接口为严格 `YYYY-MM-DD` 或 null，数据库 `birth_date DATE NULL`。合法日期范围为 MySQL DATE 可存储的 1000-01-01 到业务当天；下界为存储约束，不是年龄政策。不接受日期时间字符串、空串或自动纠正的无效日期。
- 业务日期采用 Asia/Shanghai；服务器计算并校验，浏览器展示按同一基准，数据库时间戳仍使用 UTC。周岁按提交日是否达到当年生日计算；2 月 29 日生日在非闰年以 3 月 1 日达到新周岁。没有生日则年龄为 null，不从照片猜测。
- displayName 沿用现有长度和清空规则。性别、生日及偏好不加入登录账号摘要，由 Profile 统一返回。

## 偏好字段和存储

新增 user_preference，与 user 通过 UNIQUE(user_id) 一对一；含 id BIGINT 自增主键、user_id BIGINT NOT NULL、created_at/updated_at DATETIME(3) NOT NULL，不建外键。首次成功保存偏好时创建，注册和读取不创建。清空后保留记录；用户资料页读到无记录时返回 preferences=null，前端将其显示为空表单。

以下 JSON 列均可空；SQL NULL 表示未提供，非空数组保存选中项，不使用 JSON null。接口将已存在记录的空集合统一返回 []，不会将 [] 解读为“没有偏好”。普通枚举和文本清空后 SQL NULL。不设置独立 version，使用 user.version。

| 接口字段 | 数据库字段 | 类型 | 内容 |
| --- | --- | --- | --- |
| interests | interests | JSON | 标签数组，允许自定义 |
| styles | styles | JSON | 标签数组，允许自定义 |
| preferredColors | preferred_colors | JSON | 标签数组，允许自定义 |
| avoidedColors | avoided_colors | JSON | 标签数组，允许自定义 |
| fits | fits | JSON | 固定编码字符串数组 |
| hairLengths | hair_lengths | JSON | 固定编码字符串数组 |
| restrictions | restrictions | JSON | 固定编码字符串数组；其他限制写说明 |
| dyeAcceptance | dye_acceptance | VARCHAR(16) | ACCEPT / REJECT / null |
| permAcceptance | perm_acceptance | VARCHAR(16) | ACCEPT / REJECT / null |
| groomingEffort | grooming_effort | VARCHAR(16) | LOW / MEDIUM / HIGH / null |
| outfitNote | outfit_note | VARCHAR(500) | 穿搭补充 |
| hairNote | hair_note | VARCHAR(500) | 发型补充 |
| restrictionNote | restriction_note | VARCHAR(500) | 明确限制补充 |

标签数组元素严格二选一：`{"type":"PRESET","code":"HIKING"}` 或 `{"type":"CUSTOM","text":"城市漫步"}`，不允许额外键。数组维持用户选择顺序，不排序。未知编码拒绝，服务端不接受客户端提交显示名称替代编码。

| 字段 | 稳定编码与显示名 |
| --- | --- |
| interests | HIKING 徒步、CAMPING 露营、CYCLING 骑行、RUNNING 跑步、FITNESS 健身、TRAVEL 旅行、PHOTOGRAPHY 摄影、MUSIC 音乐、READING 阅读、ART 艺术 |
| styles | MINIMAL 简约、CASUAL 休闲、BUSINESS 通勤、SPORTY 运动、OUTDOOR 户外、RETRO 复古、STREET 街头、ELEGANT 优雅、SWEET 甜美、ANDROGYNOUS 中性 |
| preferredColors / avoidedColors | BLACK 黑、WHITE 白、GRAY 灰、BEIGE 米色、BROWN 棕、RED 红、ORANGE 橙、YELLOW 黄、GREEN 绿、BLUE 蓝、PURPLE 紫、PINK 粉 |
| fits | LOOSE 宽松、REGULAR 合身、SLIM 修身 |
| hairLengths | SHORT 短发、MEDIUM 中长发、LONG 长发 |
| restrictions | NO_HIGH_HEELS 不穿高跟鞋、NO_MIDRIFF 不穿露腰款、NO_TIGHT 不穿紧身款、NO_SHORTENING 不接受剪短 |
| groomingEffort | LOW 简单省事、MEDIUM 愿意适当打理、HIGH 愿意花时间打理 |

多选最多 20 项；自定义标签 1～20 个 Unicode 码点，补充文本最多 500 个 Unicode 码点。标签执行首尾空白裁剪及 NFC 规范化，再按码点计数；同字段以 PRESET code 或 CUSTOM 规范化文本去重（大小写不折叠），保留首次顺序。自定义与预设中文名完全相同则归一为该预设。补充文字裁剪首尾空白，空白文本归一 null，不改变内部换行。未知键、非数组、数组 null 元素、错误类型及超限拒绝；不静默截断。

前后端都检查：喜欢和不喜欢颜色集合有相同规范化项；fits 含 SLIM 且 restrictions 含 NO_TIGHT。两种冲突保存返回 400 VALIDATION_ERROR，message 指明冲突，保留草稿。SHORT 与 NO_SHORTENING 不判冲突：用户可能本来就是短发，不接受进一步剪短。其他语义相似词或自由文本冲突不做确定性推断，后续生成模块检查实际要求。

## 接口增量契约

沿用现有 data/requestId 包装、字符串 ID/version、CSRF、账号隔离、未知字段拒绝和分页。新增 Profile 属性：gender、birthDate、preferences；preferences 为 null 或包含上表全部 13 个字段的对象，不含用户 ID、独立版本或数据库记录 ID。现有 Profile 字段不变。Measurement 不增加性别或生日字段。

| 方法 | 请求与缺省语义 | 成功 data |
| --- | --- | --- |
| GET /api/profile | 不变；一致读取用户及偏好 | 扩展 Profile，200 |
| PATCH /api/profile | version 必填；可选 displayName/gender/birthDate；未传保持，null 清空 | 扩展 Profile，200 |
| PATCH /api/profile/preferences | version 必填；上表任意偏好字段可选，至少传一个；未传保持，null 清空；数组 [] 同样清空 | 扩展 Profile，200 |
| POST /api/profile/measurements | version、gender 必填且不可 null；27 项尺寸可选，未传为 null，不继承数据库旧值 | 原有 {measurement,profile}，201；profile 为扩展 Profile |

偏好整页保存发送全部 13 个字段，不影响 PATCH 的缺省保持规则。首次保存未传字段为空；全部清空也允许创建一条空偏好记录，并递增资料版本一次。提交尺寸前将当前草稿的全部 27 项发送，避免“未传清空”造成误解。不得在尺寸请求中提交生日、显示名称或偏好。

基础资料请求示例（日期与值为示例）：

```json
{"version":"12","gender":"FEMALE","birthDate":"1995-06-18"}
```

偏好局部请求示例：

```json
{"version":"13","interests":[{"type":"PRESET","code":"HIKING"},{"type":"CUSTOM","text":"城市漫步"}],"dyeAcceptance":"REJECT","outfitNote":null}
```

尺寸请求示例（未列出的 25 项为 null）：

```json
{"version":"14","gender":"FEMALE","height":165,"weight":55}
```

错误继续使用现有顶层 `{code,message,requestId}`：400 VALIDATION_ERROR 用于类型、日期、编码、限制或必填错误；409 VERSION_CONFLICT；401/403 沿用认证与 CSRF；404 沿用资源归属校验；数据库不可用沿用现有错误映射。字段错误前端可即时定位，后端 message 提供可读原因，不为此任务扩展全局错误结构。校验 PATCH 时先合并当前值后检查跨字段冲突，不能只检查本次字段。

GET 用户和偏好使用一致读；所有版本化写请求先锁 user、比对 version，随后修改关联记录并将版本加一，提交后返回一致的 Profile。偏好首次创建依赖 user 锁与 user_id 唯一索引；JSON 校验和日期解析可在锁外执行，依赖旧值的合并和校验在锁内执行。没有外部调用放入此事务。

其他尺寸历史、照片接口不改路径、返回类型与业务语义；其中返回 Profile 的接口统一使用扩展结构。旧尺寸请求因缺 gender 将返回 400；server/web 需配套更新，发布要求刷新旧前端，不能声称对旧请求完全兼容。

## 页面状态和失败恢复

页面维护一个服务器基线（Profile/version）、唯一 gender 编辑值，以及 basic/measurements/preferences 的字段草稿。photos 沿用已有上传草稿，不纳入其他标签的提交。尺寸页仅在进入时 gender 为空时默认女；基础资料清空后也不立即偷偷填女，直到用户再次进入尺寸编辑流程。页面初次读取成功前不应用默认值，不把读取失败展示成空账号。

本页同时只允许一个资料版本化写操作进行，提交期间禁用相关编辑与保存。成功响应更新共同基线和版本，仅将实际已提交字段标记为已保存，其他标签草稿保留。基础资料保存提交显示名称、生日及唯一性别编辑值；尺寸保存只提交性别与尺寸；偏好保存不提交性别。基础资料保存成功不令未保存尺寸变成已保存。

同一页已成功的写入可安全推进本页所有草稿共用的版本，因为接口未写其他字段；其他设备的变更不能直接套用新版本。后台刷新保留脏字段，若服务器值或版本变化则进入比较状态，明确展示旧值、当前输入、服务端新值；用户选择保留输入或采用服务端值后再手动保存。版本冲突不自动重试。历史切换、清空当前引用或删除当前记录也通过这一协调流程；有未保存数值时先提醒，性别编辑值始终保留。

尺寸请求超时或连接断开时，冻结原请求体及原 version，显示“保存结果尚未确认”，可刷新历史核对，但不能凭同值记录断言本次已成功。若用户重试，仅重发原请求与原 version；第一次已提交则版本校验阻止第二次插入。若返回冲突，继续核对并由用户选择已有记录或明确新建；不得刷新 version 后自动重发。此机制不是持久化幂等键：页面关闭、其他设备写入及旧版本冲突不能找回本次精确响应。正常保存成功后主动再次保存仍允许新增同值记录。

基础资料和偏好未知结果同样保留原输入、版本并提供刷新比较，不显示确定失败或确定成功。已明确成功但刷新历史失败，显示“已保存，历史列表刷新失败”，只重试查询，不再次提交。切换整个路由或关闭页面时有脏值则提醒；浏览器离开提醒受浏览器能力限制，不承诺刷新后恢复。

## 后续生成模块对接

仅记录对接设计，不实现任务提交或供应商调用。服务器以同一个提交时刻取得 Asia/Shanghai 日期，在任务的短事务中读取一致的用户资料及实际使用的偏好、尺寸，持久化不可变输入快照。示例结构为 personalContext：gender、age、ageAsOf（日期）、preferences、constraintOverrides；出生日期不进入模型输入。年龄 null 与 0 区分，缺失兴趣不转换成“无偏好”。具体任务 JSON 外层沿用生成模块契约，不新增独立快照表。

constraintOverrides 保存用户明确允许本次突破的限制标识和原限制内容，默认空；只对本次任务有效，不改变 user_preference。结构化限制由稳定编码标识，自由文本限制以提交时快照文本定位。冲突检查绑定当前资料版本、当次要求和待提交输入；任一变化需重查，不能把之前的确认用于不同输入。检查中和失败时不创建任务、不消耗任务名额，保留要求并提供重试；尚未检查不能显示“无冲突”。明确冲突显示原限制、当次要求和“仅本次允许／返回修改”。自由文本冲突检测存在模型能力边界，不能宣称穷尽所有冲突。

生成模块实施前再确定冲突检查接口、模型调用和与提交幂等键的衔接；这些属于尚未实施的生成能力，不阻塞本次资料模块设计。旧任务不回填当前资料，查看时缺失个人资料快照即显示当时未记录。

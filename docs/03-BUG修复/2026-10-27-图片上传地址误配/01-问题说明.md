# 图片上传地址误配

日期：2026-10-27。状态：已按实际空间区域修正本地配置，待重启后端并复验。

用户在 http://127.0.0.1:5173 上传图片，浏览器向 https://lookmate-file.labno3.com/ 发起请求，报告缺少 Access-Control-Allow-Origin，上传失败。

## 证据与结论

- 本地 `apps/.env.dev` 的 `lookmate.assets.upload-url` 和 `lookmate.assets.download-domain` 均为 `https://lookmate-file.labno3.com`。
- `QiniuObjectStorage.uploadUrl()` 直接返回配置；`ImageUpload.tsx` 将 token、key 和 file 组装为 FormData，POST 到授权响应中的 uploadUrl，且使用 credentials: omit。
- 执行 `curl -sS -I --max-time 20 -H 'Origin: http://127.0.0.1:5173' https://lookmate-file.labno3.com/`，返回 HTTP 403、`x-error-info: qiniu_center_auth.center_auth.access`，未返回 Access-Control-Allow-Origin。此为无签名 HEAD 探测，并非实际上传 POST 的完整复现。

现有配置将图片访问域名用于上传，应首先纠正上传端点。七牛表单上传要求使用上传域名，且区域应与空间匹配，见[官方区域与端点说明](https://developer.qiniu.com/kodo/1671/region-endpoint-fq)。本轮未查询该空间区域，也未排除正确端点下存在其他跨域配置问题。

## 修复与验证步骤

1. 在七牛控制台核实空间区域，将 `lookmate.assets.upload-url` 改为对应的 HTTPS 上传地址。例如华东浙江 z0 使用 `https://up-z0.qiniup.com`；其他区域按官方列表选择。
2. 下载域名继续使用现有图片访问域名。重启后端，重新选择图片，获取新的上传授权。
3. 浏览器 Network 确认 upload-intents 返回正确 uploadUrl，上传 POST 成功，后续 complete 登记成功，图片可保存和展示。

本轮未改业务代码或私有配置，未重启服务，未进行真实上传复验。给 Spring Boot 添加跨域配置不会改变七牛域名的响应；前端 no-cors 不能替代正确的上传端点与响应授权。

## 配置修复

用户随后授权直接修改。使用本地配置调用七牛区域查询接口 `/v4/query`，返回区域 z0，上传域名列表为 `upload.qiniup.com`、`up.qiniup.com`。已将 `apps/.env.dev` 的 `lookmate.assets.upload-url` 改为 `https://upload.qiniup.com`，下载域名保持原值。查询与记录未输出密钥。尚未重启后端或执行真实图片上传，需重启后重新申请上传授权并验证。

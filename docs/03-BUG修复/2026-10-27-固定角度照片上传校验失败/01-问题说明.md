# 固定角度照片上传校验失败

日期：2026-10-27。用户已授权修复并检查其他角度。对应[固定角度需求](../../02-需求文档/2026-10-27-基础资料与照片合并/01-需求说明.md)和[实施计划 T14](../../02-需求文档/2026-10-27-基础资料与照片合并/02-实施计划.md)。

## 现象与原因

侧脸照片上传完成后，保存请求 `POST /api/photos/slots` 携带 `{"fileId":"15","slot":"SUPPLEMENT","angle":"SIDE_FACE","version":"9"}`，返回 HTTP 400、`VALIDATION_ERROR`、`请求字段或格式不正确`。用户原 requestId 为 `09bed94d-9ec5-43fd-ac59-af9bde501ef7`；本轮在原页面点击“重试保存照片”复现同一参数和错误，requestId 为 `04b2fc67-34c9-40f5-8c43-54fc90784739`。

开发后端仍运行固定角度功能更新前的代码。8080 端口旧 Java 调试进程 PID 28441 从当天 13:57:07 持续运行，而当前 ProfileService.class 的编译时间为 14:42。当前源码已允许 angle 和全部四种角度；此前功能交付记录也明确注明共享开发服务需重启加载新接口。前端热更新后提交新增字段，旧后端严格字段校验拒绝请求。

四个补充角度 SIDE_FACE、BACK_HEAD、SIDE_BODY、BACK_BODY 都携带 angle，因此同受旧后端影响。正面头像 PORTRAIT 和正面全身 FULL_BODY 不携带 angle，不受这次字段不兼容影响。

## 处理与验证

通过 Cursor 现有“启动后端”调试会话执行重启，加载当前实现，保留原启动配置。新进程 PID 89735，`GET /actuator/health` 返回 UP。未修改生产业务代码、数据库结构或真实照片。

实际页面刷新后，`GET /api/photos/slots` 返回 HTTP 200，angles 包含 SIDE_FACE、BACK_HEAD、SIDE_BODY、BACK_BODY 四个键，确认开发服务已加载角度接口。原失败上传弹窗在重启期间关闭，未再次选择或保存用户照片；用户可重新上传侧脸照片。

新增回归由子 agent angle_regression 执行，主 agent 已审查并核对 Surefire 报告。Java 21 下执行 `./mvnw -Dtest=ProfilePhotoSlotsIntegrationTest,ProfileIntegrationTest test`（LOOKMATE_INTEGRATION=true，加载独立测试配置），33 项通过，0 失败、错误或跳过；Spotless 与 `git diff --check` 通过。详见[测试摘要](02-回归测试.txt)。

新增 10 项参数化用例覆盖四个补充角度和两个主要照片位置的新增、替换，以及非法角度、主要照片携带 angle 的拒绝与无写入；合法流程从 version=9 开始，验证版本递增及照片落在正确位置。测试使用独立 MySQL schema `lookmate_profile_slots_20261027_qa_angle_6284`，应用 V1–V7；完成后已删除该库与临时凭据。MockMvc 验证 Controller JSON 解析、Service 及真实 MySQL 持久化，不代替真实供应商上传或认证过滤器验证。

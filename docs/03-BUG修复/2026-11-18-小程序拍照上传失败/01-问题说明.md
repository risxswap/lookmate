# 小程序拍照上传失败

日期：2026-11-18。状态：已修正本地上传地址并重启后端；七牛真实直传验证通过，Android 真机拍照与照片登记待复验。

## 现象与定位

用户在 Android 手机上通过局域网调试小程序，拍照上传提示“图片上传失败，请重新选择并上传”，页面另有“重新加载”入口。

该提示来自 `apps/miniapp/src/lib/files.ts` 的 `wx.uploadFile.success` 非 2xx 分支。此时已申请上传凭证，但还没调用 `/files/{fileId}/complete` 登记照片。网络中断、图片格式预检及登记失败使用其他提示。

本地 `.env.dev` 的 `lookmate.assets.upload-url` 实际为 `https://lookmate-file.labno3.com`，与下载域名混用。`FileService.intent()` 将该配置原样返回给客户端；VS Code 后端调试配置通过 `LOOKMATE_DEV_CONFIG` 加载此文件。

使用本地配置查询七牛 `/v4/query`，HTTP 200，空间区域为 `z0`，返回上传域名 `upload.qiniup.com` 和 `up.qiniup.com`。七牛要求使用空间对应的上传端点，见[官方区域说明](https://developer.qiniu.com/kodo/1671/region-endpoint-fq)。此前图库同步也曾因该配置失败，使用命令行覆盖地址后才成功，覆盖参数没有修正应用配置，见[当时的记录](../../02-需求文档/2026-11-14-小程序图库缩图与七牛接入/01-需求说明.md)。

## 复现与修复

通过 `node --input-type=module` 读取本地配置，以同一张 68 字节 PNG、同一上传凭证和唯一诊断对象 key 对比两个地址。凭证限定该 key，设置 `insertOnly=1`、`fsizeLimit=20971520`、`detectMime=1` 及 JPEG/PNG/WebP 白名单，与应用上传策略一致。仅改变上传 URL：

| 检查 | 实际结果 |
| --- | --- |
| 原配置 `https://lookmate-file.labno3.com` | HTTP 401，无上传成功 hash |
| 区域端点 `https://upload.qiniup.com` | HTTP 200，返回上传成功 hash |
| 删除本轮唯一诊断对象 | HTTP 200 |

该对比确认上传地址误配可导致客户端进入上述报错分支；本轮没有捕获手机原请求，不能据此排除真机上的其他问题。诊断未登记业务文件或照片，未输出密钥或上传凭证。首次诊断脚本因 Base64 编码缺少填充被七牛拒绝；修正脚本编码后取得上表结果，脚本错误不属于应用缺陷。

已将 `.env.dev` 的 `lookmate.assets.upload-url` 改为 `https://upload.qiniup.com`，下载域名沿用原值。通过 VS Code 重启“启动后端”调试会话，8080 监听进程由 PID 35835 更换为 40982。未修改业务代码、数据库、frp 或云端部署。

## 验证边界

重启后执行以下检查，均返回 HTTP 200、`status=UP`：

```sh
curl -fsS --max-time 15 http://127.0.0.1:8080/actuator/health
curl -fsS --max-time 15 https://lookmate.labno3.com/actuator/health
```

本次为配置修复，未改变源码或依赖，未重复运行应用构建与单元测试。真实七牛直传成功不能代替小程序完整上传验收。微信后台的 `uploadFile` 合法域名需包含 `https://upload.qiniup.com`；本轮未核实或修改后台域名列表。

后续在 Android 调试小程序中重新拍照，申请新的上传凭证，确认上传 HTTP 200、complete 成功、照片保存后可展示；同时检查相册选图。手机重试、真实照片登记、相册路径及上传域名校验仍待复验。

## 2026-11-18 后续排查：微信拦截上传域名

衣物详情添加照片时出现“图片上传中断，请重新选择并上传”。微信开发者工具 Stable 2.02.2608080、基础库 3.18.0 的 Console 显示 `https://upload.qiniup.com` 不在 `uploadFile` 合法域名列表中。工具的“项目配置 → 域名信息”中，业务配置的上传域名仍为 `https://lookmate-file.labno3.com`。这次请求已取得七牛上传地址，随后被微信拦截，未发出直传请求。

恢复上传需要在微信小程序后台的服务器域名设置中，将 `https://upload.qiniup.com` 加入 `uploadFile` 合法域名，保留现有条目，再同步开发者工具的项目配置并重新编译。当前会话无法访问微信管理后台，配置生效与整条上传链路待复验。

小程序现在会将微信返回的域名校验失败显示为“微信上传域名未配置，请联系管理员”。新增回归用例在修改前收到原通用提示并失败，修改后通过，也确认被拦截时不会登记照片。`npm test` 共 62 项通过，`npm run build` 通过。本机 HTTPS 探测七牛上传端点时证书校验通过，GET 返回 HTTP 405。该探测未传输照片。

用户随后在微信后台添加了上传域名。刷新开发者工具的项目配置后，已在 `uploadFile` 合法域名列表中看到 `https://upload.qiniup.com`，随后重新编译，小程序首页正常加载。实际文件直传和登记待复验。

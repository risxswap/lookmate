# frp 客户端启动失败

2026-11-13 已修复本机配置引号，安装 frpc 并完成客户端配置校验。

## 触发与实际结果

用户通过 VS Code 的“启动 frp 隧道”运行 `exec bash infra/frp/frp.sh client`，配置文件由 `LOOKMATE_FRP_CONFIG` 指向 `infra/frp/.env`。

使用同一配置执行 `bash infra/frp/frp.sh verify`，在加载配置时退出，错误为 `unexpected EOF while looking for matching '\''`，退出码为 2。该校验与 client 共用配置加载、端口、token 和二进制查找步骤。

## 原因与证据

1. 本机 `.env` 第 2 行为 `FRP_SERVER_ADDR=''118.25.26.67'`，开头多了一个单引号。原文件 Bash 语法检查失败，在临时副本中改为 `FRP_SERVER_ADDR='118.25.26.67'` 后语法检查通过。
2. 使用修正引号的临时副本继续校验，提示 `FRP_TOKEN 至少需要 32 个字符`，退出码为 1。脱敏检查确认当前 token 长度为 17。
3. 临时副本将 token 替换为 32 字符测试值后继续校验，提示 `找不到 FRPC_BIN 指定的 frpc，请按 README 安装`。当前配置为 `FRPC_BIN=frpc`，当前 PATH 和常见安装路径均未找到该程序，本机为 Darwin arm64。

启动项中的脚本路径、工作目录及配置路径均与现有文件对应。原始故障发生在脚本本地配置加载阶段。

## 处理步骤与验证范围

修正地址行的引号。使用 `openssl rand -hex 32` 生成 token，将同一值填入本机与公网端的 `FRP_TOKEN`。按 [frp 说明](../../../infra/frp/README.md)安装 Darwin arm64 v0.71.1 客户端，或将 `FRPC_BIN` 指向已有同版本 frpc 的绝对路径。

随后执行 `bash infra/frp/frp.sh verify`，通过后再运行 VS Code 启动项。

本轮采用临时配置副本逐项复现，临时文件已清理，实际 `.env` 与 launch.json 保持调查时状态。客户端公网连接及 VS Code 完整启动结果待配置和依赖处理后验证。记录中只保存 token 长度。

用户再次报告配置引号错误后，已将实际 `infra/frp/.env` 第 2 行修正为 `FRP_SERVER_ADDR='118.25.26.67'`。`bash -n infra/frp/.env` 通过，再执行 `bash infra/frp/frp.sh verify` 已通过配置及 token 校验，当前提示 `找不到 FRPC_BIN 指定的 frpc，请按 README 安装`。用户已调整 token，当前待准备客户端二进制或配置其实际路径。

用户继续报告缺少 frpc 后，已从官方 v0.71.1 发布下载 Darwin arm64 压缩包，并核对项目记录的 SHA-256 `d15d0324b99e14619c9aa46e37f6db588c06a09be4bc6f7948890b6b61077842`。客户端安装在被 Git 忽略的 `infra/frp/bin/frpc`，本机 `.env` 的 `FRPC_BIN` 已指向其绝对路径。

`frpc --version` 返回 `0.71.1`，`bash -n infra/frp/.env` 通过。使用 VS Code 启动项相同的 `LOOKMATE_FRP_CONFIG` 执行 `bash infra/frp/frp.sh verify` 返回配置语法正确，退出码为 0。VS Code 连接公网 frps 的结果待用户重新启动后核对。

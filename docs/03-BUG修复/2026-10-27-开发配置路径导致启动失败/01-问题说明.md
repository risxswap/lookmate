# 开发配置路径导致启动失败

日期：2026-10-27。状态：已修复并验证。

## 问题与根因

用户要求使用项目内现有 `.env.dev` 修复启动报错。实际文件位于 `apps/.env.dev`，VS Code 后端与迁移配置却指向根目录 `.env.dev`；后端命令行和迁移工具默认指向 `apps/server/.env.dev`。

Java 21 下，在 `apps/server` 设置 `LOOKMATE_DEV_CONFIG` 为项目根目录 `.env.dev`，执行 `./mvnw spring-boot:run -Dspring-boot.run.profiles=dev`，退出码为 1，报错 `Config data resource ... does not exist`。失败发生在配置加载阶段。

## 修复

VS Code 后端及迁移入口统一指向 `apps/.env.dev`；后端 dev 默认从启动目录 `apps/server` 加载 `../.env.dev`，迁移工具默认读取 `apps/.env.dev`。继续支持 `LOOKMATE_DEV_CONFIG` 绝对路径覆盖，配置不存在时仍明确失败。同步根目录、服务端和迁移说明。

未修改私有配置内容，保留用户已有的 `.env.dev.example` 删除状态。未执行数据库迁移。

## 验证

- Java 21.0.8，从 `apps/server` 不设置覆盖路径，执行 `./mvnw spring-boot:run -Dspring-boot.run.profiles=dev`：启动成功，监听 8080，MySQL 连接池初始化成功。
- `GET http://127.0.0.1:8080/actuator/health`：HTTP 200，`status=UP`，含数据库与 Redis 健康检查。
- `./mvnw verify`：BUILD SUCCESS；包含格式检查、编译与打包，193 项测试中 112 项通过，81 项按环境条件跳过，失败和错误均为 0。未执行完整业务集成回归。
- `bash ops/migrate.sh info`：BUILD SUCCESS，证明迁移入口能读取同一份配置并连接数据库；只查询迁移信息。
- `git diff --check`：通过。VS Code 配置路径已核对，未操作 IDE 启动按钮。

## 后续配置位置调整（2026-10-27）

用户将配置移到项目根目录后，授权统一加载位置。本节取代上文关于 `apps/.env.dev` 的当前路径约定，原记录保留为历史证据。后端默认从 `apps/server` 加载 `../../.env.dev`，VS Code 后端与迁移、迁移工具默认均指向根目录 `.env.dev`，保留 `LOOKMATE_DEV_CONFIG` 覆盖。未修改私有文件内容。Spring 独立配置加载探针、路径检查、脚本语法、迁移入口编译及格式检查通过；未启动业务进程或执行迁移。详见[实施计划与验证](02-实施计划.md)。

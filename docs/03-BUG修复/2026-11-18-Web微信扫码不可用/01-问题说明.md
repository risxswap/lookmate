# Web 微信扫码不可用

日期：2026-11-18。状态：已定位当前阻断点，微信后台处理及完整链路复验待完成。本次仅诊断，未修改业务代码、配置或微信后台，未重启服务。

## 现象与复现

Web 默认微信扫码登录无法取得登录码。预期由 `POST /api/auth/qr` 返回小程序码，微信扫码进入小程序明确确认后，原浏览器领取登录会话；依据见[小程序接口与数据设计](../../02-需求文档/2026-10-30-微信小程序/04-接口与数据设计.md#web-扫码)。

本机 Web `http://127.0.0.1:5173`、后端 `http://127.0.0.1:8080` 及公网 `https://lookmate.labno3.com` 分别使用独立 Cookie 会话，先 GET `/api/auth/csrf`，再携带返回的 CSRF 头和 Cookie POST `/api/auth/qr`，请求体 `{}`。三个入口均成功获取 CSRF，但取码均返回 HTTP 503：

```json
{"code":"WECHAT_UNAVAILABLE","message":"微信登录码暂不可用"}
```

逐次请求标识、环境及操作见[接口临时验证](../../testing/02-checks/2026-11-18-Web微信扫码诊断.md)。

## 根因证据

使用 `.env.dev` 中的微信配置直接核实上游，AppID 与小程序项目配置一致；密钥及访问令牌未持久化到证据。

1. 微信 `/cgi-bin/token` 返回 HTTP 200，有 `access_token`，`expires_in=7200`。本次调用的凭据可正常获取令牌。
2. 微信 `/wxa/getwxacodeunlimit` 返回 HTTP 200，但内容为错误 JSON，而非图片：

   ```json
   {"errcode":85412,"errmsg":"personal entity not verified rid: 6afda219-31b0db70-4305188e"}
   ```

   请求参数为 `page=pages/scan/index`、`env_version=develop`、`check_path=true`，诊断 scene 为 `diagnostic20261118`。

微信明确以“个人主体未认证”拒绝生成小程序码，这是当前取码的阻断点。`WechatClient.qr()` 对非图片响应统一抛出 `WECHAT_UNAVAILABLE`，未解析错误 JSON，因而用户只看到泛化提示，见[对应实现](../../../apps/server/src/main/java/cc/riskswap/lookmate/integration/wechat/WechatClient.java)。

本次已排除取码请求未通过 Web 代理、CSRF 被拒绝、完全缺少微信凭据等解释。微信已经返回业务错误，不属于此次取码请求的网络连接失败。该证据不代表后续页面路径、版本权限、微信登录及浏览器领取均已验证。

## 建议与验证边界

在该 AppID 对应的微信公众平台小程序账号核对个人主体认证状态，按后台要求完成认证后，重新取码。无需据此更换主体或调整已有业务范围。官方文档页面本次未能访问成功，认证入口、办理条件及费用未作断言；根因来自实际微信接口响应。

后续可以在保持错误脱敏的前提下，为已知微信错误码提供明确提示，并记录安全的错误码与关联标识，避免再次只能看到“暂不可用”。这属于建议，本次未实施。

认证处理后应先确认取码返回图片，再验证开发版访问权限、扫码进入确认页、注册或绑定、确认及原浏览器单次领取。本次未取得有效登录码，以上步骤及真机均未验证，不能宣称扫码登录修复完成。

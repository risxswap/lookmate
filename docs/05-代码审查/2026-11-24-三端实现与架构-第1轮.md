### R1 · P1 · 释放日历引用会影响仍在衣橱使用的图片

删除带搭配的日历安排，或为它换一套搭配时，服务会把移除的旧图标为待清理。此时衣橱或常用搭配可能仍持有引用。新设计排除带有 `cleanup_after` 的图片，只有这一张图的衣物会从候选中消失，指定为必穿时返回 409 `REQUIRED_DRESS_UNAVAILABLE`。旧任务有单独的引用保护，不能覆盖新设计的选图。实际删除对象前仍会检查引用，现有证据指向选图失效。[日历释放引用](../../apps/server/src/main/java/cc/riskswap/lookmate/service/OutfitPlanService.java#L122) · [标记条件](../../apps/server/src/main/java/cc/riskswap/lookmate/dao/mapper/DressMapper.java#L73) · [选图条件](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationService.java#L1196)

清理器每轮按更新时间和 ID 取最早 10 条，遇到仍有引用的文件直接跳过。若最早 10 条持续被引用，位于其后的过期文件就一直排不上。内存 SQL 实验中，两轮均选中同一批，第 11 条过期上传始终未入选。建议在释放最后一个有效引用时再标记，归并资料、设计记录和搭配各自的引用检查，并让清理器能越过受阻记录。需覆盖已有误标数据和删除前的锁内复核。[清理查询](../../apps/server/src/main/java/cc/riskswap/lookmate/dao/mapper/FileMapper.java#L41) · [清理执行](../../apps/server/src/main/java/cc/riskswap/lookmate/service/FileService.java#L201) · [日历约定](../02-需求文档/2026-10-28-工作台穿搭日历/03-正式实施计划.md#L10)

### R2 · P2 · Web 结束会话时用了不同的清理清单

普通退出在刷新 CSRF 凭证前后各执行一遍相同的本地清理，会话过期另有一份。改密成功结束当前会话时，页面只清查询缓存及 `hadSession`，同一页签里按账号保存的原提交键和输入仍在。同一账号重新登录并进入相应设计页面后，会查询上次待确认的提交。该恢复路径只发起查询。建议共用会话结束时的清理函数，保留各入口的跳转提示，用退出期间有迟到响应的用例核对清理时序。[普通退出](../../apps/web/src/pages/WorkspacePage.tsx#L49) · [改密成功](../../apps/web/src/features/profile/ChangePasswordForm.tsx#L72) · [重新进入设计页](../../apps/web/src/features/generation/NewDesignPage.tsx#L129) · [退出清理约定](../02-需求文档/2026-10-20-首版个人形象设计/03-生成技术契约.md#L134)

### R3 · P2 · 小程序常用搭配会拼接两种筛选条件的结果

离线运行页面，先加载全部搭配第 1 页，再输入“旅行”，尚未点击“筛选”就滚动到底。第 2 页的请求立即携带“旅行”，页面把结果追加在全部搭配第 1 页后面，同时采用旅行查询的总数。请求确实经过服务端分页，错在输入框和分页共用一个场景值。建议区分输入值与已应用条件，切换条件时从第一页开始，失败重试沿用对应的条件与页码。[页面取数](../../apps/miniapp/src/pages/outfits/index.ts#L21) · [筛选事件](../../apps/miniapp/src/pages/outfits/index.ts#L57) · [分页追加](../../apps/miniapp/src/lib/pagination.ts#L13)

### R4 · P2 · 小程序首页一张日历封面失败会中断整次刷新

用微信接口替身返回 1 条日历安排、1 套常用搭配和 1 个活动任务，仅让安排封面的授权请求返回 503。首次刷新后，三块业务数据都没有显示，也没有安排下一次任务轮询。首页的常用搭配已按图处理失败，日历卡片却走遇错即抛出的默认封面逻辑。建议让这两处复用逐图容错，保留账号切换保护，安排和任务可以先显示。[首页刷新](../../apps/miniapp/src/pages/home/index.ts#L60) · [封面解析](../../apps/miniapp/src/features/outfits.ts#L9) · [页面缺图约定](../02-需求文档/2026-11-13-小程序视觉优化/01-需求说明.md#L36)

### R5 · P2 · Web 日历传入的场景会被自由搭配草稿盖掉

先在同一页签保存“通勤”的普通自由搭配草稿，再从日历点击“为旅行设计”。链接带入了“旅行”，编辑器却恢复整份“通勤”草稿，用户看不到提示。用实际草稿初始化函数离线验证，无草稿时场景为“旅行”，有旧草稿时为“通勤”。建议保留其他草稿字段，明确处理两个场景冲突时的选择。尚待确认的提交继续按原输入找回。[日历入口](../../apps/web/src/features/planner/PlannerDashboard.tsx#L82) · [编辑器初值](../../apps/web/src/features/generation/NewDesignPage.tsx#L65) · [草稿优先级](../../apps/web/src/features/outfitInspirations/drafts.ts#L28) · [日历需求](../02-需求文档/2026-10-28-工作台穿搭日历/01-需求说明.md#L25)

### R6 · P2 · 正常生成的结果仍在模型线程中保存

效果图已可靠暂存、任务写入 `SAVING` 后，执行器在原线程直接校验图片并写七牛。独立保存池能处理延后重试和恢复的任务，但正常成功路径没有移交。对象存储变慢时，模型线程会等待存储完成。建议在暂存完成后把保存工作交给保存池，处理好租约交接，并保留任务终结前对活动名额的占用。[正常执行](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationExecutor.java#L268) · [调度分流](../../apps/server/src/main/java/cc/riskswap/lookmate/scheduler/GenerationScheduler.java#L34) · [执行隔离约定](../01-项目总览/03-架构设计.md#L264)

## 讨论补充 · 方法复用、MVC 分层和查询效率

服务端 Controller 已通过 Service 访问业务 Mapper。建议维持现有分层。Controller 接收请求和返回响应，公共请求解析处理协议限制，Service 负责业务规则与事务，Mapper 负责查询和写入。Web 和小程序各自复用适合本端生命周期的状态与展示方法。

- **文件引用。** 资料、设计记录和清理器各自检查直接引用及衣物识别快照，日历移除安排时却漏掉了这套判断。优先在文件生命周期服务中共用“文件是否仍有有效引用”的方法。释放引用和后台删除分别在各自事务中调用，最终删除前在锁内重新核对。这一处复用直接解决 R1 的规则分歧。[资料删除照片](../../apps/server/src/main/java/cc/riskswap/lookmate/service/ProfileService.java#L430) · [设计记录清理](../../apps/server/src/main/java/cc/riskswap/lookmate/service/DesignLifecycleService.java#L93)
- **请求解析与登录。** 两个搭配 AI Controller 直接调用另一个 Controller 的静态方法解析请求，每个请求还会新建 JSON 解析器。可以把已有方法移到请求解析组件，共用预先配置的解析器，保留 32 KiB 上限、重复字段和尾随内容检查。密码登录和扫码登录也可以复用已有的 Web 会话建立服务；密码入口传入“记住登录”选项，扫码入口先验证一次性票据。[解析实现](../../apps/server/src/main/java/cc/riskswap/lookmate/controller/DesignController.java#L101) · [跨 Controller 调用](../../apps/server/src/main/java/cc/riskswap/lookmate/controller/OutfitAiController.java#L33) · [密码登录](../../apps/server/src/main/java/cc/riskswap/lookmate/controller/AuthController.java#L74) · [Web 会话服务](../../apps/server/src/main/java/cc/riskswap/lookmate/service/WebLoginService.java#L25)
- **客户端复用。** Web 的退出、过期和改密可复用同一套本地会话清理，各入口保留自己的凭证处理和跳转。小程序现有 `outfitCards` 已接受封面解析方法，`fileImageUrl` 已按账号与图片规格做缓存和请求去重。首页、衣橱和搭配列表可以据此共用单图失败处理，保留账号变化时中断旧请求的行为。[Web 清理](../../apps/web/src/pages/WorkspacePage.tsx#L25) · [封面解析入口](../../apps/miniapp/src/features/outfits.ts#L9) · [图片缓存](../../apps/miniapp/src/lib/files.ts#L58)

## 讨论补充 · 前端 MVVM

2026-11-24 确认 Web 和小程序都遵循 MVVM。以下是基于当前调用路径的调整建议。两端职责以[项目架构](../01-项目总览/03-架构设计.md#前端-mvvm-职责)为准。

- **Web。** 个人资料页已将草稿、保存和冲突处理交给 `useProfileSession`，可供设计页参考。设计编辑器同时负责入口场景、草稿选择、预览、提交找回及渲染，建议将草稿优先级和提交状态集中在编辑 ViewModel，复用现有预览 hook 与提交 API。可用 R5 的日历入口验证草稿选择，并核对修改输入后旧预览失效、待确认提交只按原键查询。[资料页](../../apps/web/src/features/profile/ProfilePage.tsx#L29) · [设计编辑器](../../apps/web/src/features/generation/NewDesignPage.tsx#L63) · [预览状态](../../apps/web/src/features/generation/useDesignPreview.ts#L15)
- **小程序。** 首页有活动任务且页面可见时，每轮刷新成功 5 秒后再次读取当天安排、常用搭配和工作台。建议将整页刷新、切换日期、任务轮询定义为不同操作，分别读取全部首页数据、所选日期安排、工作台活动任务。页面隐藏或卸载时停止轮询，单张封面失败仍可显示其他数据。可在接口替身中检查连续两轮任务查询期间，安排和搭配列表均无额外请求。搭配详情页已有独立的轮询操作可参考。[首页读取与调度](../../apps/miniapp/src/pages/home/index.ts#L55) · [搭配详情轮询](../../apps/miniapp/src/pages/outfit-detail/index.ts#L502)

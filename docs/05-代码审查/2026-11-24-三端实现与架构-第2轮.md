### R8 · P1 · 小程序保留一张原图就无法保存衣物编辑

已有图片展示时需要 `id` 和 `fileId`，保存时小程序把两者一起组装成 `{imageId, fileId}`。衣橱 PATCH 规定保留图片只传 `imageId`，新增图片只传 `fileId`。因此只改名称、调封面或保留旧图再加一张都会在服务端返回 400，整次编辑失败。小程序页面替身捕获了这份请求，实际 Java Service 配合 Mapper 替身也返回了 `400 VALIDATION_ERROR`。建议在小程序 Model 集中构造图片变更，图片和顺序未动时省略 `images`。Web 已有这两条规则，可直接用作契约用例。[小程序保存](../../apps/miniapp/src/pages/dress-edit/index.ts#L146) · [服务端校验](../../apps/server/src/main/java/cc/riskswap/lookmate/service/WardrobeService.java#L228) · [衣橱契约](../02-需求文档/2026-10-20-我的衣橱/01-需求说明.md#L21) · [Web 对照](../../apps/web/src/features/wardrobe/DressEditor.tsx#L24)

### R9 · P2 · 小程序找回旧设计后会删除用户刚编辑的新草稿

创建请求结果未知时，用户还能修改同一账号、同一设计模式的表单。按原键找到已接受的旧任务后，客户端按模式删除当前草稿。离线页面实验中，提交「第一版」后改写并保存「第二版」，找回成功后本地草稿为空，期间只发出一次创建请求。建议按提交时的草稿版本或快照清理，让用户继续编辑的内容得以保留。[编辑与持久化](../../apps/miniapp/src/pages/design-create/index.ts#L154) · [成功后的清理](../../apps/miniapp/src/features/design.ts#L15) · [设计草稿约定](../02-需求文档/2026-10-30-微信小程序/01-需求说明.md#L303)

### R10 · P2 · Web 保存搭配期间继续输入，成功响应会丢掉这次输入

点保存后，名称、穿法和单品选择仍可编辑。组件收到先前请求的成功响应，就清除未保存标记并跳转。离线操作时先提交第一次改名，等待中第二次改名已在表单可见，返回详情后只保存了第一次。可在请求期间禁用编辑控件，或让编辑器记录本地修订号，仅在响应对应当前修订时清草稿和跳转。[保存与离开保护](../../apps/web/src/features/outfits/OutfitEditor.tsx#L23) · [编辑控件](../../apps/web/src/features/outfits/OutfitEditor.tsx#L31)

### R11 · P2 · 下调结果大小上限后，已落盘的任务会反复停在 SAVING

任务快照保留了提交时的 `maxResponseBytes`，保存恢复却用进程当前上限检查已落盘文件。若重启时把上限调到低于原文件大小，保存代码在上传前抛错，执行器按暂时性失败重新排队。有效 PNG 的离线实验中，两次领取均延后保存，均未释放账号名额。原文件与较低配置持续存在时，同账号无法新增设计，返回 409。建议用任务快照核验当时已接受的结果，保留对象存储暂时失败的延后重试。[写入配置快照](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationService.java#L141) · [恢复时检查上限](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationExecutor.java#L497) · [失败后重新排队](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationExecutor.java#L294) · [账号占位查询](../../apps/server/src/main/java/cc/riskswap/lookmate/dao/mapper/GenerationMapper.java#L23)

### R12 · P2 · 暂存磁盘已经不足，新生图任务仍会被接受

提交服务在建任务前检查账号名额和全局队列，磁盘水位检查在执行器准备生图时才发生。当请求到达时磁盘已经低于下限，本应拒绝新增并返回 503，当前路径仍可返回 202，随后可能完成一次付费规划，再将任务记为生图失败。独立静态复核覆盖普通设计、搭配效果图和生图重试。纯文字评价可直接保存文字，无需占用图片暂存空间。建议在原键重放之后、接受新增生图工作之前检查水位，保留执行前的第二次检查以应对排队期间空间变化。[准入要求](../01-项目总览/03-架构设计.md#L266) · [提交检查](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationService.java#L378) · [执行时检查](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationExecutor.java#L242)

### R13 · P2 · 搭配 AI 已接受重试，删除来源后同键重发却返回 404

失败任务 A 重试生成 B 后，用户可删除 A。用原键和相同参数再次提交重试时，搭配服务先查询 A 的关联记录，此时直接返回 404。B 仍存续，用同一键 GET 仍可查到 B。普通设计服务已经按“先匹配账号、键和请求摘要，再查来源”的顺序处理。建议搭配入口复用这一顺序，在确实要创建子任务的分支内校验并复制来源，保留同键异参冲突检查。[搭配入口](../../apps/server/src/main/java/cc/riskswap/lookmate/service/OutfitAiService.java#L234) · [普通设计重放](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationService.java#L436) · [来源清理](../../apps/server/src/main/java/cc/riskswap/lookmate/service/DesignLifecycleService.java#L86) · [重试契约](../02-需求文档/2026-10-20-首版个人形象设计/03-生成技术契约.md#L196)

### R14 · P2 · Web 普通设计的「查看原提交」会指向已删除的来源

普通设计重试响应丢失，随后来源被删除。离线渲染普通、发型和穿搭三个创建入口，它们都指向来源详情；该详情的 404 页只提供返回工作台，原提交键仍保留。这条正常找回入口因此断开。用户若另有可打开的普通设计详情，仍有机会从那里手动查询；若已受理的新任务能在记录中找到，也可直接进入。建议抽出按当前账号和原提交键找回的操作，创建入口和详情共用。[创建页入口判断](../../apps/web/src/features/generation/NewDesignPage.tsx#L44) · [详情 404](../../apps/web/src/features/workspace/DesignDetailPage.tsx#L84) · [已有找回操作](../../apps/web/src/features/generation/RetryActions.tsx#L29)

### R15 · P2 · 搭配只改名称，两端仍触发衣物、分组和图片引用重写

### R16 · P2 · Web 搭配历史抽屉关闭时仍取历史页并轮询

### R17 · P2 · Web 新建空收藏夹也会重读同屏的全部收藏

收藏夹写入与设计记录操作共用一个成功回调，每次都使当前账号的八类查询缓存失效。使用仓内真实 TanStack Query 和已挂载的收藏、收藏夹查询，实测新建或改名后分别发起一次收藏页 GET 和一次收藏夹页 GET。两种操作都未改动收藏成员。未挂载的查询仅标记过期，不能计为八次请求。建议保留通用写请求，把受影响的查询键交给具体操作声明；增删收藏成员时仍需刷新对应收藏页。[写入入口](../../apps/web/src/features/designs/CollectionManager.tsx#L28) · [缓存失效](../../apps/web/src/features/designs/queries.ts#L29) · [服务端写入范围](../../apps/server/src/main/java/cc/riskswap/lookmate/service/RecordsService.java#L143)

### R18 · P2 · 小程序参考图库缩图渲染失败，重试仍取同一条坏路径

发型或穿搭灵感列表的缩图已经下载并缓存，随后原生图片组件触发加载错误。页面清空封面，却保留 Model 中的临时路径。离线触发「重试图片」前后，授权和下载次数各为一次，返回同一路径。首次下载失败没有写缓存，走的是另一条路径。建议复用私有衣物图片已有的失效规则，只有缓存仍指向本次失败的路径时才删除，然后按原图片规格重新获取。[列表错误处理](../../apps/miniapp/src/pages/design/index.ts#L159) · [缓存与已有失效方法](../../apps/miniapp/src/lib/files.ts#L80) · [图库验收约定](../02-需求文档/2026-11-14-小程序图库缩图与七牛接入/01-需求说明.md#L30)

### R19 · P2 · 生图结果恢复成功后，模型调用记录可能仍停在 SENT

模型已返回、图片已可靠落盘，但更新调用状态的事务尚未提交时进程退出。重启后，执行器发现文件，只把任务排入保存队列。接着保存图片并将任务置为成功，却没有结束对应模型调用。任务完成后也不会再次被过期租约查询选中。结果图可用；调用记录在存续期间仍显示已发送、无完成时间，影响后续对账。建议恢复时在校验任务归属、调用阶段及暂存文件后，用同一事务补记对应调用的完成状态。[落盘和调用完成之间的窗口](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationExecutor.java#L261) · [重启恢复](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationExecutor.java#L638) · [保存完成](../../apps/server/src/main/java/cc/riskswap/lookmate/service/GenerationExecutor.java#L531)

## 架构与复用

20 个 Controller 均未直接导入业务 Mapper。19 个在类上声明资源路径，另一个只有单一工作台 GET。抽查的 Web 分页仍使用 Ant Design 与服务端返回的总数。建议保留现有 Controller → Service → Mapper，把本轮改动集中在跨端请求字段、Service 的写入条件和 ViewModel 对异步结果的归属判断。原生页面或 React 组件的文件数量本身不构成 MVVM 违规。[服务端分层](../../AGENTS.md#L33) · [Web 与小程序 MVVM](../../AGENTS.md#L59)

数据库还有一处可复用现有结果。当前搭配详情分别查询评价、效果图和最新任务；同一笔成功的生图可能同时满足三个条件，随后同一个请求会三次组装同一任务详情。可先取得三个任务 ID，在当前请求内按去重后的 ID 读取详情，仍按原有三个字段返回。适合作为 R16 的后续优化，收益应结合实际 SQL 次数核对。[当前结果组装](../../apps/server/src/main/java/cc/riskswap/lookmate/service/OutfitAiService.java#L209)

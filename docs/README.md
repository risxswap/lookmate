## 维护规则

采用 development-workflow 的编号和中文命名。长期设计在项目总览固定位置更新；需求与缺陷按各次工作记录范围、方案和结果。本文仅导航，不复制完整业务定义或字段设计。

- 新需求使用 `02-需求文档/YYYY-MM-DD-中文主题/01-需求说明.md`；同一需求跨天更新原文件，正文更新日期。日期采用创建当天的用户当地日期。
- 缺陷有实际记录时创建 `03-BUG修复/YYYY-MM-DD-中文主题/01-问题说明.md`，包含问题、方案和验证。仅在有实际内容时创建。
- 需求及缺陷默认一份文档容纳说明、方案与验证；复杂时再拆出 `02-实施计划.md` 和 `03-验证记录.md` 并链接。仅整理需求不自动生成计划或验证结果。
- 重要技术决定使用 `04-技术决策/YYYY-MM-DD-中文主题.md`。改变原决定时保留历史与替代链接；普通命名和业务规则归入数据库、领域或需求文档。
- 代码审查有实际产出时使用 `05-代码审查/YYYY-MM-DD-中文主题-第N轮.md`，当前不预建目录。
- 业务定义由领域模型维护，需求引用并描述本次预期行为，数据库和接口负责实现设计。草案不得覆盖已确认规则。
- 实施后更新功能总览、受影响的长期设计及需求中的验证证据。未执行的检查明确标为未验证。

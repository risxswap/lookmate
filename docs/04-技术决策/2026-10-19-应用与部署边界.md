# 应用与部署边界

## 背景

项目包含个人发型与穿搭设计以及运营管理。运营管理与用户设计业务职责不同，用户明确要求两个后端直接操作数据库，各自部署和维护配置。

## 决策

- 长期采用 server（用户后端）、web（用户前端）、console（运营后端）、admin（运营前端）四个应用，位于 apps/。首版只实施 server、web，面向桌面浏览器。
- 两个后端不互相调用接口，不抽取共享业务模块，数据库迁移统一由 ops/ 管理。
- server 为一个 Maven 工程和 Spring Boot 进程，采用 Controller → Service → Mapper 分层，service 包不再细分领域子包。
- 每个应用及基础设施拥有独立 docker-compose.yml、配置和运行目录。统一部署脚本只调用各项目入口，不合并 Compose，也不集中存放所有项目的实际配置。
- 使用已有运行时镜像挂载程序产物，首版单实例，允许短暂停机升级。数据库迁移前停止相关应用写入，运行中的模型任务默认等待结束。
- 仅入口 Nginx 对外提供 HTTP/HTTPS，其他服务通过内部网络通信。

## 取舍

不采用先前讨论的共享业务模块、后端间管理接口或集中部署目录。独立应用和直接数据库访问减少首版服务通信，但要求双方及维护工具一致遵守数据规则、并发协议和结构版本约定。

首版不引入微服务、独立任务服务或滚动发布。版本、实际域名和部署资源仍待确定，见 [当前架构](../01-项目总览/03-架构设计.md)。

## 决定与理由

用户明确“前期放到 server 里面，直接调用比较好”。采用 Java + ONNX Runtime 在现有 server 内运行分割模型，替代 [独立图片服务方案](2026-10-23-独立图片处理服务.md)。不创建 apps/image，不引入 Python、FastAPI 和内部 HTTP 链路，减少前期部署与维护成本。

后台执行线程直接调用推理组件，用户侧继续异步等待；本次不改变去背景范围、原图保留、失败保留衣服及权限边界。有效设计见 [架构设计](../01-项目总览/03-架构设计.md#server-内置衣物抠图2026-10-23已确认待实现)，未决行为见 [需求说明](../02-需求文档/2026-10-23-衣物自动抠图/01-需求说明.md)。

## 影响与验证缺口

采用有界执行资源，初期处理并发 1；模型版本固定并复用加载实例。线程池不提供进程级内存和故障隔离，模型原生内存与 CPU 开销由 server 承担。实施前需验证模型加载、前后处理、输出质量、峰值内存、线程数及超时行为。后续是否拆服务依据实际负载决定，不预建远程调用层。

RMBG-1.4 官方提供 ONNX 文件，ONNX Runtime 提供 Java API；这仅支持技术方向可行，不代表本项目已通过兼容性或性能测试。模型尚未选定，授权要求不因换用 Java 而改变。

参考：[RMBG-1.4 ONNX 文件](https://huggingface.co/briaai/RMBG-1.4/tree/main/onnx)、[ONNX Runtime Java 文档](https://onnxruntime.ai/docs/get-started/with-java.html)。资料已在本轮讨论查阅，具体版本在实施前核对。

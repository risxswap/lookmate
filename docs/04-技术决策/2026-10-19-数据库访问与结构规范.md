# 数据库访问与结构规范

日期：2026-10-19。状态：已确认；17 张表职责拆分及事务、清理原则已确认，字段、状态编码及索引基线已确认，未实施。

## 背景

用户后端和未来运营后端共享 MySQL，需要统一迁移来源及数据规范。用户明确要求不使用数据库外键，所有表具有主键、创建时间和更新时间，并采用 MyBatis-Plus。

## 决策

- 数据访问采用 MyBatis-Plus；复杂查询和条件更新可以使用专用 SQL。
- 业务表不创建数据库外键，关联存在性、归属和删除处理由代码在事务中维护，并处理并发创建和删除的竞争。
- 每张业务表具备主键、created_at 和 updated_at，包括历史记录与关联表。统一 id 使用自增 BIGINT，接口以字符串传递；具体字段见数据库设计。
- 保留业务唯一索引和查询索引；取消外键不等于取消唯一性约束。
- 使用 Flyway，由 ops/ 的一次性 Compose 服务显式执行版本化 SQL。应用启动只检查兼容性，不自动迁移。已执行脚本不改写。
- Flyway 内部历史表保留工具原生结构，作为上述业务表字段规范的明确例外。

2026-10-20 补充确认：沿用数据库设计中的 17 张表职责拆分；同账号关联写入采用先锁 user 的短事务及统一锁顺序，外部调用和图片处理不进入事务；历史设计与重试保留独立快照及图片引用；文件核查全部引用并标记待删除后再清理对象，失败重试。任务物理删除后不再保留幂等占位，首版不新增独立幂等记录表。

## 取舍

替代先前提出的数据库实际外键方案。关联完整性由所有写入入口共同负责，数据检查需覆盖孤立引用和跨账号关联。

2026-10-20 已确认当前 SQL 字段类型、可空性、默认值、状态编码及索引作为首版基线；具体实现和数据库验证尚未完成，不新增实施授权。详见 [数据库设计](../01-项目总览/04-数据库设计.md)。

# 用例评审：范围名称

> 模板说明：保存真实返回及复核证据。人工补位记录实际身份和反馈来源；占位符不代表完成评审。

## 评审范围

- 任务与来源版本：实际范围、允许来源和版本。
- 任务阶段：本轮生成评审／修订复核／仅审批既有用例；混合任务注明各自范围。
- 覆盖设计与用例指纹：实际文件位置与内容指纹。
- UI 依据（适用时）：已确认设计／交互说明的版本，原始页面证据及应用版本、角色与环境；区分设计预期和观察事实，列出尚未核实的关键路径。
- 评审方式：独立子 Agent／人工独立补位。
- 评审者与独立性：实际标识或身份，是否参与被评内容编写。
- 补位原因或限制：不适用时写明；缺少评审时列受影响草拟用例。

## 评审分工

本轮生成评审按公共规则由不同评审者承担三个分工，记录实际返回；缺失分工留空并说明原因。混合范围可增加专业评审者。同一人承担多个视角不算多个独立评审者。仅审批既有用例时按当前来源、断言和未解决问题核查，可引用仍适用的历史记录，以下生成评审表不适用时注明，不追补历史分工或清单。

| 分工 | 实际评审者与独立性 | 来源清单证据 | 用例对照证据 | 当前结论或缺失范围 |
| --- | --- | --- | --- | --- |
| 业务覆盖评审 | 实际标识／身份及是否参与编写 | 首次清单位置 | 实际返回位置 | 实际结论 |
| 专业交互评审 | 实际标识／身份及是否参与编写 | 首次清单位置 | 实际返回位置 | 实际结论 |
| 断言与可执行性评审 | 实际标识／身份及是否参与编写 | 首次清单位置 | 实际返回位置 | 实际结论 |

## 来源独立清单

每个评审者先按分工从原始来源列出必测规则和条件，主 Agent 收到并保留清单后再提供覆盖树和用例。保留各自首次清单、来源版本和两次交付记录，不事后改成已有用例列表；对照后新增条件另记。

## 准入建议

逐条列出可执行与仍为草拟的用例及原因；本轮生成范围核对三个分工、五个视角、关键发现及修订复核是否齐备，既有用例审批记录当前核查结果。独立结论、主 Agent 语义核查和执行授权分别记录；风险接受引用真实决定，不等同于通过。待澄清、阻塞与排除项不计作已覆盖。

# 正式计划与执行

只在正式回归、模块验收或正式缺陷复验时读取。临时验证使用入口中的最小记录，不为调用报告工具补造正式身份。

## 选择范围与冻结计划

从目标、变更影响和历史风险选择可执行用例，覆盖直接规则、相邻状态、共享数据／权限及关键链路。优先级表示风险，不自动等于必测性。执行前为每条用例明确 `required_for_conclusion`，排除项记录依据与未验证影响；缺失场景先按覆盖设计补齐，不把现有用例列表当成全部需求。

使用 [计划模板](../assets/templates/execution-plan.md)，保存为 `docs/plan/YYYY-MM-DD-<topic>.md`，PlanId 保留为内容身份。引用已存在的需求、开发 spec/plan，不再复制一份产品设计。计划记录来源修订、实际目标版本、环境与身份、数据准备／清理、地图和目录哈希、执行顺序、必测性、执行器及版本、超时和停止条件。缺陷复验另列原 BUG、原运行、修复版本和验证分组。

先按 [用例格式](test-case-format.md) 校验并生成 Schema v5 目录。冻结选中 CaseId、CaseRevision、来源行号、分类和专业执行器；`module` 取分类中的业务功能节点，跨模块场景仍保留主归属。修改执行语义后重建受影响计划；目录哈希与单例语义指纹分开记录。只有草拟或已废弃用例时交付待补条件，不创建空正式运行。

## 计划思维导图

用 [范围图模板](../assets/templates/execution-plan-map.md) 生成同目录 `YYYY-MM-DD-<topic>-map.md`，按冻结分类组织，根为 `<PlanId> 执行范围`。每条计划任务对应唯一编号块和一个图叶子，叶子末尾 CaseId 链接到本计划任务，任务另链正式用例编号块。任务序号、状态与标题须对应。

图是本轮范围导航，不是新的全局分类事实源。路径按显式资产根计算；资产根不含计划文件时使用普通相对 Markdown 链接，并说明仅提供 Markdown 导航。默认推荐项目根或 `docs/` 作为共同根。未在 Obsidian 操作时只报告静态链接校验。

## 执行前核实

确认选中用例已准入，来源和内容指纹未漂移；目标版本与环境符合计划；账号权限、登录态和数据满足具体场景；执行器实际可用；副作用与清理在已有授权内。UI 按专业技能复用已有自动化，只有已授权长期自动化建设才添加相应框架或配置。

这些是质量与前置条件核实，不是每轮人工批准表。用户已授权本轮测试时直接执行；仅授权生成计划时到此交付。发现凭据缺失、范围扩大或新的未授权副作用，说明受影响事项并继续独立工作；不足以开始任何场景时不建立空 RunId。部分场景具备条件可以启动运行，同时为缺条件场景保留真实阻塞原因。

## 专业执行与逐次记录

API 执行遵循 [api-testing](../../api-testing/SKILL.md)，正式执行器为 `http`，实际版本填 `curl <实际版本>`。UI 遵循 [ui-testing](../../ui-testing/SKILL.md)，逐场景使用 `agent-browser` 或 `playwright`。已选执行器属于冻结身份，另一工具诊断不能替代原结果；需要正式换工具时生成派生计划和新 RunId。

开始时创建 `docs/testing/04-runs/RUN-YYYYMMDD-NNN/`，保存 manifest、results 和证据，字段见 [运行契约](run-data-contract.md)。每个计划场景至少有一条记录；状态含义如下：

| 状态 | 使用条件 |
| --- | --- |
| Passed | 计划内全部步骤与断言实际满足，证据达到要求 |
| Failed | 实际观察与明确检查不符，保留失败分类及证据；不自动断定产品缺陷 |
| Blocked | 环境、数据、权限、依赖或动作歧义导致无法完成验证 |
| Skipped | 依据已授权计划或明确决定跳过，记录理由 |
| NotExecuted | 本轮结束前未开始，记录原因 |

每次操作后验证本步检查，再继续依赖步骤。不能以操作完成、工具退出码成功或截图存在代替业务判断。执行中受阻时保存已观察事实；缺证据或关键预期仍不确定时不能通过。证据与日志先脱敏，再持久化。

只有应用版本、环境、配置、契约、用例指纹、关键数据语义和执行器及版本均未改变，且目的仅为确认瞬时波动时，才在原 RunId 追加连续 Attempt。业务修复、环境恢复后验证、契约或执行器更换创建派生计划和新 RunId，引用原运行。任何重试都保留首次失败与证据。

## 收尾与交付

运行结束时把未开始场景如实记为 NotExecuted，已开始但无法完成的记为 Blocked；不能为补齐结果而猜测发生过的行为。记录实际清理结果和仍存的数据或资源，只清理本轮可识别且获准清理的内容。

按 [报告与 BUG](reporting-and-bugs.md) 生成 HTML 和 Markdown，检查文件可读、全部计划场景和尝试均保留、缺口和整体结论一致。报告输入缺失时先从真实日志核实，无法恢复就明确交付不完整事实；工具报错时保留输入，修复生成问题后重跑，不手改报告统计。

交付区分已完成执行、测试结论和报告交付状态。测试失败不妨碍如实完成本轮执行交付，报告生成成功也不代表测试通过。未验证项和未授权动作分别列明，Agent 不替用户接受发布风险。

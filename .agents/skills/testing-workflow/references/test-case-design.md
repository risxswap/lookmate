# 覆盖设计与用例准入

设计新用例、扩充覆盖或评审现有场景时读取。公共流程确定范围和可观察目标，具体动作与断言形式交给专业技能。

## 来源与覆盖分配

列出本轮来源及版本、目标角色、业务动作、规则、状态与预期结果。接口预期只来自用户指定或项目明确约定的在线／本地契约与接口说明；页面预期来自需求和验收标准及其已确认设计、交互说明。已有测试、历史 BUG 和实际响应提供风险线索，不能替代权威预期。UI 测试脚本、配置和定位信息只用于执行适配，实页观察用于核实操作路径，不能把当前表现当作正确预期。具体来源边界见 [API 技能](../../api-testing/SKILL.md) 和 [UI 技能](../../ui-testing/SKILL.md)。

先按已确认业务职责分领域和功能，再展开测试条件。接口路径、正常／异常、角色或优先级不直接作为业务领域。跨模块用例由主要验证规则确定主归属，其他模块作为依赖记录。命名可以沿用项目约定；语义有冲突时只暂停受影响分类并说明冲突。

用 [覆盖设计模板](../assets/templates/test-case-design.md) 在 `docs/testing/00-data/02-analysis/` 记录来源到场景的映射。每个规则说明适合在哪一层观察：接口验证协议、权限及外部业务结果，UI 验证用户操作、页面状态和完整链路。同一规则可能两层都需要，避免用页面提示代替接口持久化断言，或用接口成功代替页面操作。

## 覆盖方法

根据实际来源判断下列维度是否相关，不生成机械笛卡尔积。关联的高风险条件要有场景或明确的缺口处置；不相关项简述依据。

| 维度 | 关注条件 |
| --- | --- |
| 业务结果 | 主路径、替代、拒绝、取消、恢复，以及禁止发生的副作用 |
| 输入和边界 | 缺失、null、空串、空白、格式、枚举、编码、重复、跨字段约束；已声明上下限前／时／后 |
| 集合和关系 | 0、1、多项、容量边界、分页、重复、顺序、已删除关联、所有权和租户 |
| 身份与权限 | 未登录、失效凭据、相关角色、资源所属方、权限变化与隔离 |
| 状态和时间 | 允许／禁止转换、终态、逆序、重复操作、截止点、时区和明确的一致性窗口 |
| 依赖与并发 | 超时、部分成功、重试、恢复、重复提交、并发更新、乱序及约定的幂等规则 |
| 页面状态 | 初始、加载、空、成功、校验错误、服务错误、禁用、刷新、返回及相关输入方式 |
| 数据与副作用 | 可观察的新增／变更／删除、事件、通知和审计；失败时状态保持和清理 |

独立输入用等价类和边界值选代表；多个条件共同决定结果时用决策表；生命周期用状态转换表；高风险相互作用按具体失败机制组合。来源未声明的上限、时限、错误语义及内部数据结构进入待澄清项，不编造约束。

在覆盖设计中逐项记录维度的适用性、来源和对应覆盖节点；同一条件可关联多个维度，无需复制用例。关键状态转换和高风险组合须能定位到具体 CaseId 与检查，未形成用例的条件保留缺口处置。UI 范围另按 [UI 覆盖展开](../../ui-testing/references/ui-case-design.md) 逐功能细化；公共维度和 UI 维度可以在同一台账关联，避免重复维护。

每条重要规则推演至少一个可能逃逸的最小错误，再定位能识别它的具体检查。例如来源要求取消后释放占用，可分别检查状态改变和后续可用性；若只断言取消请求成功，就记录弱断言缺口。这类反例是设计假设，不是已发现产品 BUG，也不授权故障注入。

## 草拟与准入

归属明确的场景直接写入正式用例目录，初始状态为草拟，不另存候选用例副本。每条用例应有可追溯来源、独立执行的前提和数据、唯一动作顺序、具体可观察的预期、必要等待和清理。凭据只用引用；用例中的数据表不隐含参数化循环。

生成阶段按 [独立挑战评审](coverage-challenge-review.md) 处理，已有用例的审批或纯格式维护不因此重启生成评审。逐条满足以下条件才可标可执行：

- 预期与来源相符，无影响结论的歧义，独立执行者不需要猜测。
- 步骤、观察方式、前置数据和清理可落实，环境条件可在执行前核实。UI 关键路径按专业规则有适用版本的实页观察依据；已发现产品差异与尚未核实的操作路径分别记录，路径核实不要求业务预期已通过。
- 重要反例有可靠断言，关键发现已处置；本次生成范围按独立评审规则完成三个分工、五个视角及必要修订复核。
- [格式校验](test-case-format.md) 通过，地图和正文一致。格式通过本身不证明前三项成立。

准入由 Agent 在授权内完成。审批既有用例核对当前来源、明确断言和未解决问题，可引用仍适用的评审记录；不因缺少历史独立评审记录追补生成审查，也不补造历史记录。用例获准不代表用户已授权执行。

## 未决项与结束条件

已知事实直接采用，可在允许来源中核实的内容自行核实。需要业务决定的问题附具体冲突、受影响场景和建议，一次只处理当前依赖已满足的问题；继续无依赖分支。已有会话答案直接引用。

覆盖叶节点只取已映射、已排除、待澄清、阻塞之一。已映射引用 CaseId；排除写依据与影响；待澄清和阻塞写解除条件。风险接受引用真实责任人决定，不等同于已覆盖，也不能让预期不明确的用例变成可执行。地图仅包含已有正文用例，分析中未形成用例的风险不建占位叶子。

结束时列出已完成范围、仍为草拟的用例和原因、缺口及排除项。只有本轮相关规则、适用维度、关键状态转换和高风险组合有明确处置，关键歧义已解决、生成范围完成独立评审时，才表述对应范围设计完成。待澄清、阻塞、排除和风险接受分别列出，不计作已覆盖；不承诺覆盖未知规则或所有理论输入。

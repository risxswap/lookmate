# 独立覆盖挑战评审

用于新建、补充生成、重新生成正式用例及该轮修订复核。审批已有用例、纯格式修正、地图维护、回归选择或重生成报告本身不触发新一轮生成评审。需求变化确实需要生成场景时，仅对受影响范围启动。

## 独立性与补位

评审者不得参与被评覆盖树或用例的编写、修订。正式用例生成默认由三个不同的独立子 Agent 承担下表分工，API、UI 和混合范围均适用。主 Agent 负责生成、汇总和修订，自查只能作准备，不能替代独立结论。

| 分工 | 独立检查范围 | 必须返回 |
| --- | --- | --- |
| 业务覆盖评审 | 来源规则、角色目标、主路径、替代与拒绝路径、跨模块业务结果 | 来源必测清单、规则与用例映射、遗漏或排除依据 |
| 专业交互评审 | UI 检查设计依据、实页路径证据、输入、页面状态、导航、异步及恢复；API 检查契约边界、鉴权、状态转换、并发及幂等；混合范围检查两层分配和衔接 | 边界与状态转换、高风险操作组合、缺失场景及来源、UI 未核实路径 |
| 断言与可执行性评审 | 最小错误能否逃逸，前提、数据、动作、观察、等待、持久化、禁止副作用和清理能否落实 | 反例与具体检查位置、弱断言、不可执行步骤及准入建议 |

分工由不同评审者承担；同一评审者可连续检查本分工的多个视角并复核修订，不计为其他分工的独立返回。并发额度不足时分批启动不同子 Agent。无子 Agent 能力或调用失败时，允许未参与编写的人员按缺失分工独立补位，记录实际身份、分工与限制，沿用相同来源边界和证据要求；不能把一个评审者改名记录成多人。混合范围需要更多专业评审者时可增补，汇总时仍核对三个分工和下表五个视角。

派发采用两个阶段，工具支持时使用最小上下文：

1. 只提供任务目标、评审分工、技能路径、允许的原始来源及版本、风险范围和交付要求。每个评审者先按自己的分工从原始来源列出必测条件及待澄清项，保存首次清单及来源；此阶段不提供也不自行读取生成者的覆盖树、用例或预设结论。
2. 收到并保留该评审者首次清单后，再提供同一待评版本的覆盖设计、用例、地图及内容指纹。评审者对照清单返回遗漏、冲突、重复、反例和准入建议，首次清单保持原样，新增条件另记。不同评审者对同一规则产生不同预期时，回到原始来源核实，不能按多数票决定业务规则。

UI 第一阶段同时提供已确认设计、交互说明、原始实页证据及必要版本和环境信息，区分预期来源与观察事实，不夹带生成者的覆盖结论。第二阶段核对用例引用的页面观察记录及适用性。证据不足时由专业交互评审定位待核实路径，授权内可补查；缺少实页证据不能只靠多名评审者同意就判为可执行。

评审者只读被评资产；主 Agent 合并同源发现，保留发现者和受影响范围，再修订用例。原独立评审者核对实际修订后关闭发现。修订影响其他分工时，同时交对应评审者复核；未受影响的返回可沿用并说明依据。评审者一旦参与编写，后续复核换人，无需为正常修订每轮重新创建三个子 Agent。

缺少任一分工的独立评审结果时，记录缺失分工、原因和待评范围，受影响用例保持草拟，可使用 `处理提示：待独立评审` 并定位记录。其他已经准入的场景继续推进。此时尚未发生业务运行，不补造 Blocked 运行结果；也不把正式任务改成临时验证绕过准入。

## 检查范围

| 视角 | 要回答的问题 | 保留的证据 |
| --- | --- | --- |
| 业务完整性 | 每种角色的目标与来源规则是否有覆盖或排除依据？ | 原始来源条款与覆盖节点对照 |
| 规则与边界 | 条件取反、边界前后、所有权变化、重复或逆序是否遗漏？ | 等价类、决策表或状态转换及来源 |
| 交互与故障 | 关键组合、超时、部分成功和恢复会产生什么可观察影响？ | 高风险操作序列、最终结果与禁止副作用 |
| 反例与断言 | 一个最小错误能否逃过现有断言？ | 规则→假设错误→CaseId 及具体检查位置 |
| 独立找漏 | 先从来源列出的条件与现有用例有哪些差异？ | 对照前的清单、遗漏、冲突与重复 |

三个分工合计覆盖五个视角，每个评审者都要完成自己分工的独立找漏。普通功能可以合并本分工的检查轮次，涉及 P0/P1、权限、跨模块状态或历史高影响缺陷时逐视角记录；合并轮次不合并评审者。五个视角是检查范围，不是凑满固定轮数。资料没有定义的故障语义留作澄清，不以反例推演虚构产品要求。

接口评审只使用文档和外部证据；UI 预期来自需求、验收标准及其已确认设计与交互说明，实页证据核实操作路径，测试代码只用于执行适配。主 Agent 不能让评审者读取禁用来源后转述。

## 发现、复核与准入

使用 [评审模板](../assets/templates/test-case-review.md)，保存到 `docs/testing/00-data/02-analysis/`。每轮记录真实评审者标识／身份、独立性、输入版本与指纹、检查范围、发现、返回证据和复核结果。人工评审保留其实际反馈来源，不把未回复记作通过。无发现也要给出检查过的条款或反例。

发现用稳定编号，写清来源、受影响规则和 CaseId、可能逃逸的错误、影响、修订与复核证据。区分待修订、待澄清、已修订待复核、已关闭；真实风险决定单独引用。主 Agent 不能只凭自己写了修订说明就关闭独立发现。

复用历史评审时核对来源、范围、用例语义和独立性仍适用，并引用真实记录。审批已有用例不因审批动作重新发起独立评审，也不因历史缺少独立记录追补生成审查；主 Agent 核对当前可定位来源、明确断言和实际未解决问题。该边界不适用于本轮新生成或实质新增的场景，不能把待独立评审的新用例转称已有用例来绕过准入。

本轮相关规则、适用维度、关键状态转换和高风险组合均有场景或有据处置，三个分工及五个视角有独立返回证据，修订完成必要复核、关键发现已解决，且 [用例准入](test-case-design.md#草拟与准入) 满足后，Agent 可将对应场景标为可执行。待澄清、阻塞和风险接受单列，均不计为已覆盖。缺口只阻止依赖它的用例。时间预算耗尽或资料没有更新时，交付真实的草拟范围与解除条件，停止重复空转，不降低准入要求。

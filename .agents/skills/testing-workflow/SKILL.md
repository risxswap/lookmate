# 测试工作流

负责测试范围、公共覆盖方法、用例质量和结果汇总。具体接口动作由 [api-testing](../api-testing/SKILL.md) 处理，页面动作由 [ui-testing](../ui-testing/SKILL.md) 处理。专业技能直接进入时，读取本入口的模式与授权规则后继续原任务，不再次路由自己或重启流程。

本流程只组织通过公开接口或运行中的页面观察行为的黑盒测试，预期来自需求、验收标准和接口契约。函数、类、内部模块及隔离组件的测试交由开发流程处理，其通过结果不能计作接口或 UI 黑盒覆盖。技能附带脚本的开发自测只验证工具本身，也不属于业务测试结果。

## 先确定交付范围

沿用用户指定项目、已有资产和本次授权，核对目标、预期来源、版本、环境及可用身份。测试资产可在业务仓库内，也可在独立测试仓库；获准访问的自动化资源可以另设路径。仓库布局不改变专业技能的来源边界。

| 模式 | 适用条件 | 最小交付 |
| --- | --- | --- |
| 临时验证 | 单个接口或页面的局部核实，不形成正式验收或回归结论 | 保存来源、环境、实际操作、预期、实际、证据和限制 |
| 正式测试 | 模块验收、正式回归、按正式流程组织的缺陷复验 | 可执行用例、相应类型地图、计划与范围图、运行快照、逐次结果及 HTML/Markdown 报告 |

模式由任务目标决定，直接调用专业技能也可以执行正式测试。临时记录不进入正式覆盖统计；需要纳入回归时，再生成、评审正式用例。正式任务缺少独立评审时保留草拟状态，不能改称临时验证绕过准入。

用户只要求用例、计划或评审时，交付到对应阶段。已有测试执行授权且前置条件齐备时，直接推进到结果和报告，不逐次索取用例或计划批准。业务预期冲突、范围扩大、未授权副作用只暂停受影响操作并说明所缺决定，继续无依赖工作；既有授权不重复确认。凭据仅使用安全引用，持久化记录先脱敏。

## 临时验证

使用 [临时记录模板](assets/templates/temporary-check.md)，保存为 `docs/testing/02-checks/YYYY-MM-DD-<topic>.md`，证据放同名目录。无需初始化完整资产、生成正式 CaseId/PlanId、地图或 HTML 报告。记录每次真实尝试，预期不明确时说明资料缺口，不以当前响应或实现填补答案。专业技能完成操作后，交付可观察结论和未验证项。

## 正式测试

1. **范围与覆盖**：读取 [覆盖设计](references/test-case-design.md)，引用已有需求、接口文档及验收标准，区分必测和补充范围，给接口与 UI 分配可观察的断言。无需复制开发 spec 或开发 plan。按 [用例格式](references/test-case-format.md) 使用中文用例和相应类型地图。
2. **生成与准入**：新建、补充生成或重新生成用例时，按 [独立挑战评审](references/coverage-challenge-review.md) 默认组织三个不同子 Agent，分别检查业务覆盖、专业交互、断言与可执行性，并完成修订复核。各评审者先从原始来源形成清单，再对照用例。子 Agent 不可用时按缺失分工安排独立人工补位；缺少独立结论的用例保持草拟。已有用例审批不重复触发或追补历史生成评审；核对当前来源、断言和未解决问题，不补造历史记录。完成评审、解决关键缺口后，Agent 可将符合条件的用例标为可执行。
3. **计划与执行**：读取 [计划与执行](references/planning-and-execution.md)，校验资产、冻结用例及来源，逐项明确必测性、执行器、依赖和停止条件。新计划为 `docs/plan/YYYY-MM-DD-<topic>.md`，范围图为同目录的 `YYYY-MM-DD-<topic>-map.md`。在授权范围内组织专业技能执行。
4. **结果与收尾**：读取 [运行契约](references/run-data-contract.md) 保存每条场景和每次尝试，按 [报告与 BUG](references/reporting-and-bugs.md) 生成同源报告，处理缺陷与复验。确认产品失败优先判整体失败；无产品失败但必测项无法完成为阻塞；只有非必测缺口才可给出带风险通过。未分析失败不能计作通过。

## 交付边界

用例生命周期与运行结果分开，重试、新版本复验和更换执行器均保留原事实。报告生成成功、测试通过和发布风险接受分别判断。正式执行交付报告入口、实际覆盖与缺口、BUG 和解除条件；未执行的阶段如实标明。

需要修复应用代码时，测试侧提供缺陷记录和复现证据，交由项目采用的开发流程处理。若已安装同级 `development-workflow`，可在获准开展修复任务时读取其 `SKILL.md`；它是可选衔接，缺失不阻塞测试、报告或缺陷交付。收到修复版本后安排原问题复验及影响回归。发送消息、发布或生产操作须已有对应授权。

编写测试文档时，若已安装 `humanizer-zh`，使用它校订本轮文字；未安装时按本技能的模板与报告规则完成文档。校订须保护契约字段、编号、路径和命令。下面的参考与模板仅在相应分支读取，不要求简单验证加载全部资源。

# 实施计划与子 agent 执行

## 触发与分工

任务有对应 Spec，且用户已授权实施时，必须先保存独立 Plan，再由子 agent 按计划实现。Spec 包括已有需求规格，以及本轮按需求流程保存的需求说明；小需求也适用，计划可以只有一个任务。主 agent 负责调查、拆分计划、协调依赖、审查和验证，不直接编写实现代码；实现及审查后的代码修复交给子 agent。

仅讨论或整理 Spec 时，完成规格产出即可，不自行创建实施计划或开始编码。无对应 Spec、范围明确的局部修改保持轻量流程，无需为套用此流程补建规格。已被主 agent 按 Plan 派发的子 agent 执行分配任务，读取本流程或专项技能时沿用当前阶段，不重新规划整个需求或递归派发。

本流程参考 superpowers 的 `writing-plans` 和 `subagent-driven-development`：将规格转成具体、可验证的小任务，逐任务交给新的实现 agent，并分别检查规格符合性和代码质量。规则已在本文中整理完整，不依赖安装 superpowers；执行模式、审批、提交和目录采用当前用户授权及项目约定，不照搬来源技能的固定流程。

## 保存可执行的 Plan

先读 Spec、相关代码、项目约定和已有验证入口，按 [行为切片](behavior-slices.md) 拆分任务。沿用项目已有计划路径；没有约定时，保存到对应 Spec 所在目录的 `02-实施计划.md`，并在 Spec 中链接。多份 Spec 共用目录时，用需求主题区分计划文件名。已有计划继续更新，Spec 内只保留引用，避免重复维护。

计划包含以下内容，篇幅与任务规模相称：

- **目标与依据**：引用 Spec 及验收条件，概括实现目标、相关架构和技术栈，列出全局约束、范围与未决项。已有设计以链接引用，拟议选择与已确认决定分开记录。
- **覆盖映射**：将 Spec 的预期行为、失败与权限条件、验收要求映射到任务及验证方式，确保每项有归属。
- **任务顺序**：为任务分配稳定编号，记录依赖、负责的具体文件及职责；新增、修改和测试文件分别列明。说明输入输出、共享类型、接口契约与前置条件，使下一位 agent 无需猜测边界。
- **可执行步骤**：每项任务用复选步骤说明要修改的具体位置和行为、检查方法及必要的文档同步。验证写明实际命令、运行目录和预期结果；界面或人工检查写明操作与可观察结果，不能仅写“完成测试”。
- **验收与状态**：列出任务完成条件，记录待实施、实施中、待验证、验证失败或已完成，以及执行 agent、证据和缺口；计划中的预期不能写成已经通过。

有可观察行为变化或缺陷回归时，优先安排有意义的失败检查、最小实现、通过检查及必要整理；用户明确要求 TDD 时遵循该要求。纯文案、低影响配置或其他不适合自动测试的变更使用相称的检查，不为符合步骤添加无意义测试。计划应具体到能执行，但无需预写全部生产代码。

派发前自查：Spec 是否全部覆盖，文件与职责是否明确，依赖是否可执行，任务间接口是否一致，验证是否能证明验收条件。缺失的业务决定按需求澄清边界处理，独立任务可以先计划。保存并核对文件后，已有实施授权即进入子 agent 执行，无需再次让用户选择执行模式或批准同一范围。

## 按任务调度与检查

1. 每项任务交给新的实现子 agent。提供该任务完整步骤、Spec 引用、全局约束、相关代码上下文、依赖结果和验收方式，明确允许修改的文件、共享工作区的已有改动，以及需要返回的实际验证证据。
2. 按依赖顺序推进；前置结果通过必要验证后，才作为下游的成立条件。只有文件互不重叠、契约已确定且无依赖的任务可以并行；共享文件或相互依赖的任务顺序执行。
3. 子 agent 实现、自查并运行任务检查。主 agent 先核对 Spec 符合性，包括遗漏、额外行为和验收证据，再检查代码质量、项目规范与跨任务接口。需要独立审查时交给审查子 agent；实现者自查不能替代主 agent 的审查责任。
4. 发现问题后交回负责实现的子 agent 修复并重新检查。子 agent 不可继续时，将上下文交接给新的实现子 agent；主 agent 不直接代写修复。审查通过且验证证据满足验收条件后，才将任务标为已完成。
5. 所有任务完成后，按 [验证与交付](verification-and-delivery.md) 检查整体行为、跨任务集成及文档一致性，报告实际结果和剩余缺口。测试未运行或失败时如实记录，不用子 agent 的完成声明替代证据。

新增或调整 Spec 时，先同步覆盖映射、任务和依赖，再派发受影响任务；实现中发现接口冲突时同样先修订计划。实质扩大范围或改变已授权行为时澄清对应部分，其余独立工作继续。

子 agent 工具不可用、派发失败或并发额度暂不可用时，说明实际阻塞，保留已保存的计划和任务状态；可以继续调查、审查或验证，待能力恢复后继续派发。不得静默退回主 agent 直接实现。

# 前后端契约协作

接口改动前对照现有 Controller、客户端、OpenAPI 或接口说明确定事实。沿用已有协议与错误结构；新接口约定在实现前形成最小可核对的契约，不强制统一响应包装或代码生成。

契约应明确：方法与路径、身份和资源权限、字段类型与必填/可空/缺省含义、成功和错误响应、分页与排序、日期时区、金额单位、ID 表示，以及重复写操作的处理。更新时区分字段缺失、null 和清空，避免无意覆盖。

后端负责传输类型和接口说明，前端核对解析与展示。超出 JavaScript 安全整数范围的 ID 使用字符串，两端避免 Number/parseInt 转换；金额按契约使用最小单位整数或十进制字符串并保留精度；日期区分日期值与时刻，明确时区转换位置。

跨层完成条件：至少用一组实际响应验证两端字段与错误路径；对变更相关的边界值、空值和失败条件提供证据。已有消费者的破坏性变更需纳入明确范围，不为了页面方便静默改变全局序列化策略。

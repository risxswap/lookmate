## 公共准备

- 本文为合成示例；进入可执行状态前，核实目标需求 REQ-BOOK-001 的字段、提示、查询能力和清理方式。未匹配目标契约时保持草拟，记录缺口。
- 本文中的弹窗、按钮、文案及路径均为示例，不代表已看过目标页面。替换为项目事实时，在公共准备或各用例准备中引用覆盖设计内的页面观察记录，定位适用应用版本、角色、相关环境和关键路径证据；只有设计稿或文字说明时保持草拟并标记待实页核实。
- 员工 alice 的隔离测试会话已经登录，账号通过安全引用提供。
- 会议室编号：由执行计划准备并通过 listRooms 核实的本次专用会议室 id，测试期间不供其他任务使用。
- 预约日期：本次尝试开始时 Asia/Shanghai 时区的明天，确定后不再重算。
- 运行标识：本次尝试开始时生成并固定的 UUID。
- 会议室已启用，在预约日期 10:00—11:00 无预约，容量至少为 2。
- 示例契约：createBooking 为创建预约，listBookings 为按主题或会议室及时段查询预约，cancelBooking 为取消预约；成功创建返回 201。
- 只使用隔离数据；执行计划须明确允许创建、查询和取消本次预约，清理不影响其他任务数据。

## 用例

### UI-BOOK-001｜员工成功预约后刷新仍能查看

用例编号：UI-BOOK-001 ^case-ui-book-001

优先级：P1
状态：草拟
关联需求：REQ-BOOK-001

#### 准备

- 满足“公共准备”。
- 通过 listBookings 按本用例的会议主题查询，确认匹配记录为 0 条。

#### 数据

- 会议主题：字符串 meeting- 后拼接「运行标识」。
- 参会人数：2。

#### 步骤

1. 填写预约
   操作：在页面打开「会议室编号」对应的预约弹窗，填写日期「预约日期」、时段 10:00—11:00、主题「会议主题」和人数「参会人数」。
   检查：弹窗中的日期、时段、主题和人数与输入逐项相同。

2. 提交预约
   操作：在弹窗中点击“提交预约”。
   观察：从点击提交前开始保留该页面的网络记录，直到 createBooking 响应和页面成功反馈均出现。
   等待：最多等待执行计划声明的页面完成预算；终点为创建响应和成功提示均出现，超时保留证据并按计划归因。
   检查：createBooking 响应状态码为 201，响应 id 是非空预约编号。
   检查：页面显示“预约成功”，弹窗关闭。
   保存为：预约编号 ← 本步 createBooking 响应的 id 字段

3. 刷新并查看
   操作：打开页面的“我的预约”，刷新页面并找到「预约编号」。
   检查：仅显示一条对应记录，主题、会议室、日期、10:00—11:00 时段及人数与本次输入一致。

#### 最终检查

- 通过 listBookings 按「会议主题」查询，仅返回 1 条记录，其 id 等于「预约编号」，创建人为 alice，会议室、日期、起止时间和人数与输入一致。
- 保存创建响应、刷新后页面和查询结果作为同次尝试的脱敏证据，不能用提交前的界面状态证明持久化。

#### 清理

- 若已保存「预约编号」，通过 cancelBooking 取消该编号对应的本次预约；若创建请求已发送但未取得编号，先按「会议主题」精确查询并核实创建者后再取消本次记录。
- 通过 listBookings 确认本次主题的有效预约为 0 条，记录取消或清理失败，不删除其他主题的数据。

### UI-BOOK-002｜员工未填写主题时不能提交预约

用例编号：UI-BOOK-002 ^case-ui-book-002

优先级：P1
状态：草拟
关联需求：REQ-BOOK-001

#### 准备

- 满足“公共准备”。
- alice 在专用会议室的预约日期 10:00—11:00 没有预约；通过 listBookings 核实匹配记录为 0 条。
- 页面网络记录能够完整观察 createBooking 调用，已排除采集过滤和丢失。

#### 数据

- 会议主题：空字符串；不得替换为空白、JSON null 或不发送字段。
- 参会人数：2。

#### 步骤

1. 填写空主题
   操作：在页面打开「会议室编号」对应的预约弹窗，填写「预约日期」、10:00—11:00 及人数「参会人数」，清空主题至「会议主题」。
   检查：主题输入框内容为空，其他输入与填写值一致。

2. 尝试提交
   操作：在弹窗中点击“提交预约”。
   观察：从点击前开始记录网络直到主题错误提示出现且本次页面校验结束；网络采集无法覆盖这个窗口时记录阻塞原因。
   等待：页面校验结束的等待预算及终点观察方式由执行计划给定，不自行延长重试取得通过。
   检查：主题输入框显示“请输入会议主题”。
   检查：弹窗保持打开，日期、时段和人数与提交前一致。

#### 最终检查

- 观察窗口内 createBooking 请求数量为 0。
- 通过 listBookings 查询 alice 在「会议室编号」的「预约日期」10:00—11:00 的预约，匹配记录仍为 0 条。
- 保存提交前后页面、覆盖完整观察窗口的网络记录及查询响应；若发生意外写入，保留失败证据。

#### 清理

- 关闭预约弹窗；若失败导致意外记录，先保存证据，再核实创建者、专用会议室和时段，通过 cancelBooking 取消本次意外记录并记录结果。

# UI 测试

按需求和验收标准细化用户操作，检查真实页面状态及可观察业务结果。支持直接页面验证、工作流分配的场景和页面探索。

通过浏览器操作运行中的应用页面开展黑盒测试。资产格式中的“UI 集成测试”指页面及业务链路的黑盒验证，不指组件挂载测试、DOM 模拟或内部函数测试；复用 Playwright 时也按这个范围选择场景。

## 进入任务

直接收到 UI 测试请求时，先读取同级 [testing-workflow](../testing-workflow/SKILL.md)，确定临时验证或正式测试、任务阶段和资产位置，再继续本技能。由工作流转入时沿用已确定的模式、范围、来源、授权和计划，只补齐页面执行条件，不重新分流或循环调用入口。配套工作流缺失时先说明依赖缺口，不自行复制公共流程。

业务预期来自需求和验收标准，交互与视觉预期可引用其中已确认的设计稿、交互说明或项目标准，记录版本和确认依据。项目使用 spec 时读取其 UI 设计与交互条目；没有 spec 时沿用其他可靠需求，不要求补建开发文档。允许读取已有测试代码、配置、夹具与定位信息来适配执行，已有断言仍须核对业务依据；当前页面和脚本输出只说明实际行为。应用源码的根因定位交给开发流程，测试侧保存页面和外部证据。

先从需求提取测试条件，再勘察实际页面以细化操作。正式 UI 用例进入可执行状态前，关键路径须有适用版本的实页观察依据；只有需求或设计稿时按 [UI 覆盖展开](references/ui-case-design.md) 保留条件或草稿，不猜测按钮、弹窗和跳转。

## 按任务读取

- 细化交互、运行已有 Playwright、真实浏览器检查、页面探索或分析失败时，读取 [页面方法与执行](references/ui-execution.md)。
- 生成、补充或修订正式用例时，读取公共 [覆盖设计](../testing-workflow/references/test-case-design.md)、[UI 覆盖展开](references/ui-case-design.md) 和 [格式契约](../testing-workflow/references/test-case-format.md)，采用 [UI 用例模板](assets/templates/ui-integration-test-case.md)。模板是合成示例，替换为已核实项目事实后再使用；正文文件名须与一级标题一致，地图入口按实际资产根重算。
- 生成正式用例的挑战评审，按公共 [独立评审](../testing-workflow/references/coverage-challenge-review.md) 组织三个独立分工，使用 UI 覆盖展开表检查角色与入口、页面状态与转换、操作序列、等待和否定观察窗口、刷新后持久化及跨页面数据一致性；准入由工作流维护。
- 正式执行时读取公共 [计划与执行](../testing-workflow/references/planning-and-execution.md)、[结果契约](../testing-workflow/references/run-data-contract.md)；失败归因、BUG 或修复复验按 [报告与 BUG](../testing-workflow/references/reporting-and-bugs.md) 处理。

## 完成与交接

按当前模式交付场景、实际执行器与结果、关键截图及相关证据、未验证项和清理结果。临时记录与正式报告使用公共工作流指定位置和格式；向工作流返回真实场景结果，由其汇总跨类型结论。浏览器验证通过不等于已有 Playwright 自动化，脚本存在也不等于本次已执行。

默认完成本次验证并复用已有自动化。用户要求持续回归、CI 或可重复执行脚本时，才建设相应长期自动化；沿用指定测试仓库和既有工具链授权，不自动为一次页面检查引入新框架。

# 页面方法与执行

## 场景与执行器

从需求和验收标准确定角色、入口、前置状态、操作、逐项页面检查及最终业务结果。按范围覆盖加载、空数据、错误、禁用、成功、返回或刷新后的状态；只在任务需要时展开视口、键盘、布局或视觉检查。视觉预期使用已明确设计或项目标准，截图差异本身不证明业务缺陷。

生成正式场景时先按 [UI 覆盖展开](ui-case-design.md) 从需求提取条件，勘察相关页面或复核已有实页证据，再细化操作并建立用例映射。关键路径未经实页核实的用例保持草拟；已有自动化数量和当前页面可见控件不能定义覆盖范围。

稳定回归场景已有可运行的 Playwright 测试时优先复用。新页面、探索或缺少既有自动化时使用能观察真实渲染页面的 Agent 浏览器。按所用环境的浏览器工具说明操作；静态 HTML、源码或脱离真实浏览器的 DOM 模拟不能替代页面观察。

正式执行器在计划中确定；临时验证也记录实际工具与版本。同一正式运行中不因失败静默替换执行器。需要换工具诊断时保留原结果，补充验证按公共计划与结果契约建立追溯，不能拿 Agent 浏览器成功覆盖 Playwright 失败。

## 环境与数据

核实地址、应用版本、角色和登录态、功能开关、必要数据及其清理方式。记录本场景相关的浏览器名称与版本、视口或设备、语言和时区。缺少必须由用户提供的条件时说明具体缺口，继续不依赖它的工作；前置条件和授权以公共工作流为准。

优先沿用测试会话与隔离夹具，保存登录态时避免将 Cookie、令牌或个人数据写入仓库和证据。仅在需要时使用项目既有命令启动本地服务，记录本次启动的资源，收尾只释放本次资源。

需要接口协助准备、查询或清理数据时，读取同级 [接口执行方法](../../api-testing/references/api-execution.md)，按明确接口文档通过 curl 完成。页面触发的网络请求仍作为 UI 执行证据；接口辅助通过不能代替页面断言。沿用用户指定仓库和可访问资源，不为使用自动化强制另建测试仓库。

## 真实浏览器执行

1. 打开目标页面，观察当前渲染状态、可访问结构和场景相关控制台、网络信息，确认已经到达所需入口。
2. 用已观察到的角色、可访问名称、标签或稳定测试标识定位；每次页面状态变化后重新核对目标。定位不明确时澄清步骤或收集页面证据，避免猜测可能改变业务语义的操作。
3. 逐步执行并核对本步检查。等待使用可观察终点和有限预算；否定断言覆盖明确窗口。例如“未提交请求”需要从触发前开始完整采集，不能仅检查最后一刻的网络列表。
4. 验证持久化或跨页面链路时，按用例刷新、重新进入或查询目标记录，并核对本次标识与字段。只看成功提示、URL 或元素存在不能替代要求的业务结果。
5. 失败时保留 URL、具体步骤、关键截图及相关控制台和网络证据，脱敏后落盘。停止依赖失败输出的步骤，继续安全取证和适用清理。

动作完成不代表断言通过。必要网络、控制台或页面状态无法观察时，明确是哪项断言未验证，而不是用工具执行成功推定业务通过。

## 已有 Playwright 执行

核对项目命令、配置、夹具、浏览器依赖和报告约定，仅选择本轮范围。测试代码可用于确定运行方式、定位和适配；若断言与需求冲突，记录用例或脚本问题，不把脚本当作业务裁决依据。

正式用例与所选自动化通过稳定 CaseId 唯一关联；缺失、重复或指向废弃用例时，先修正映射再执行受影响范围。临时运行已有脚本不为此补造正式身份。

保留退出码、实际测试数量、选中场景和项目产生的输出、Trace、截图、视频或报告。核对选中场景确实运行，空选择或全跳过不代表通过。读取项目重试设置，按公共契约保留各次尝试，不能只保存重试后的绿色汇总。

失败后区分产品、用例、自动化脚本、环境或数据问题。定位调整须保持原业务操作与断言；改动后重跑受影响场景，原失败与新结果分别保留。无法确定原因时保留待分析状态，不放宽断言以取得通过。

新建长期自动化按用户已授权的持续回归、CI 或脚本范围实施，复用现有工程约定。缺少所选工具能力时先说明具体限制；一次性测试优先采用现有可用执行器。工具链建设的已有授权无需重复确认，新增范围仍按公共工作流处理。

## 页面探索

先记录目标区域、角色、风险假设、时间或范围限制、数据边界和观察方式。临时探索写入公共临时记录；正式探索写入本轮计划，运行记录遵守正式契约。开放式观察不能为了生成报告虚构预先存在的正式用例，计划外发现作为证据和候选场景记录。

保留真实访问路径、输入、尝试、截图及观察。明确偏离已确认预期的可复现行为进入失败分析；预期未明确时记录需求问题；偶发且无法复现时保留不确定性。值得长期回归的稳定场景转为正式用例草稿，关联探索来源，由工作流组织生成评审与准入。临时探索结果不自动计入正式覆盖。

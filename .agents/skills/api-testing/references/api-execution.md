# 接口方法与执行

## 将契约变成可检查的场景

从明确接口文档提取方法、路径、operationId、认证和角色、请求参数、响应状态与字段、业务状态及副作用。记录所用版本或内容指纹、具体章节和未说明部分；operationId 缺失时记录该缺口，正式身份按公共格式处理，不把猜测值当作文档事实。

按当前范围细化正常路径、必填和空值差异、边界与格式、角色及资源归属、重复提交、状态转换和依赖结果。幂等、并发、时间窗口等只在相应契约和风险涉及它们时展开。每项检查写清输入、独立预期、观察途径和结束条件；“HTTP 200”“非空”“符合预期”不能代替已声明业务规则。

数据准备、登录、被测操作、结果查询和清理都使用文档明确的接口。若副作用只能通过缺少契约的查询确认，记录验证缺口，不通过数据库、内部配置或源码补出答案。需要修复或源码诊断时，将复现事实交回开发流程。

## 契约缺口与用例映射

针对本轮接口和场景核对文档，不要求补齐无关接口。解析 OpenAPI 时先识别声明版本，展开被引用的参数、请求体、响应及 Schema，并计入适用的全局认证与接口覆盖；其他接口说明提供相同业务信息即可。字段省略的标准语义可以按声明版本解释，但规范默认值不能补出业务规则。文档完整性检查属于测试准备，不需要安装开发技能或读取应用源码。

| 文档依据 | 用例及断言落点 | 信息不足时记录的缺口 |
| --- | --- | --- |
| 方法、路径、标识、参数位置、媒体类型、认证及权限 | 可重建的请求，未登录、无权限和资源归属场景 | 无法确定请求地址、凭据传法、角色或预期拒绝结果 |
| 必填、可空、空字符串／空白／空集合、缺省及更新语义 | 分别设计省略、null、空值和有效值场景；检查更新后的字段 | 必填是否排除空白、不传是否保留原值、默认值何时生效 |
| 类型、格式、范围、长度、枚举及跨字段条件 | 从已声明约束选等价类、边界和必要组合，并定位每类失败的响应依据 | 上限、长度计算方式、规范化顺序或组合失败语义未说明 |
| 响应状态、必要头、业务码与触发条件 | 逐场景检查 HTTP 和业务结果；同一 HTTP 状态下分别判断业务分支 | 只有通用成功 Schema、错误码无触发条件或失败数据行为不明 |
| 输出字段名、类型、必需／可空、嵌套结构及枚举 | 检查实际传输类型、字段存在条件、集合元素及业务值 | Data 只写 object、字段是否必定返回或空结果形态未定 |
| 前置状态、唯一性、分页、幂等及副作用 | 状态转换、重复和权限隔离；通过已声明查询验证结果，按约定窗口观察异步完成 | 查询、清理、完成条件或失败时禁止副作用缺少契约 |

每个场景保留“来源文档及版本／指纹 → operationId 或已记录的标识缺口 → 字段路径或规则条款 → 输入／前置条件 → 预期响应和业务结果 → 观察方式”的映射。正式测试写入已有覆盖设计和用例来源；临时验证写入本轮记录，不另建一套台账。类型正确或 HTTP 200 只证明对应层次，不能替代业务码和状态变化断言。

示例用于构造数据和理解场景，不能从单个示例推断长度上限、必填字段、固定列表数量或错误文案。`default`、`format` 等注解是否对应服务端处理，按明确的接口说明判断；只将有依据的值或消息片段设为固定断言。请求与输出分别解释，同名字段不自动具有相同的类型、必填或空值语义。

发现文档缺失、Schema 与说明／示例冲突、引用无法解析或业务规则不明时，记录接口、字段／条件、来源位置、受影响断言和补齐条件；只让依赖该信息的场景保持待澄清或草拟，继续有可靠依据的独立部分。正式准入和整体结论沿用公共规则。未知预期不能记为产品缺陷或已覆盖，不从当前响应、测试源码或应用实现补出答案，也不因缺口主动运行探索性写请求。

## 构造与发送请求

核实实际 curl 版本和场景所需能力。正式结果的执行器类别为 `http`，版本填写 `curl <实际版本>`。curl 不可用或无法满足必要能力时说明限制；不静默换成另一 HTTP 客户端。

- 将 `--disable` 放在 curl 的第一个参数，避免用户默认配置改变请求。显式提供方法、URL、头、请求体、连接超时和总超时；超时值来自已明确的执行预算。
- 使用 `--silent --show-error`，分别捕获响应体、响应头、HTTP 状态和 curl 退出码。预期错误响应也要读取和检查，不能因 `--fail` 或 shell 提前退出丢失响应与收尾记录。
- 默认不自动跟随重定向或重试。场景要求重定向时核对目标及凭据转发范围；要求重试时按公共规则保留每次尝试。
- shell 可编排 curl，Python 或现有 JSON 工具可解析已获取响应、判断断言、写运行结果；辅助代码不代发 HTTP 请求。
- 请求链中的资源 ID 来自本次响应，校验后存入本次尝试上下文。上游失败时停止依赖该输出的业务步骤，继续安全取证与适用清理。

## 凭据、隔离与副作用

从环境变量名、安全存储引用或已授权会话取得身份信息，验证角色和资源归属。避免凭据进入命令行参数、回显、verbose/trace、仓库和持久化证据；含密钥的 curl 配置、Cookie jar 和原始响应只在权限受限的临时位置使用，按任务需要安全清理。先脱敏再展示或保存证据，保留解释失败所需的字段结构与关联关系。

每个身份、并发参与者使用独立会话，数据带本次可识别标记。只清理已核实属于本次任务的数据。开始可能写入的请求前确认隔离方式、查询与清理能力；授权和前置条件按公共工作流处理。

超时或连接中断后不能推定服务端未提交。先用文档明确的查询核实副作用，再决定是否允许重试、复用幂等键或清理。无查询能力或幂等保证时保留不确定性，停止可能重复写入的后续请求。

并发场景用独立 curl 进程等待同一同步点，记录各参与者就绪、释放和起止时间，汇合后判断结果及最终状态。仅在后台启动多个进程不能证明满足调度要求；不能达到约定并发条件时记录限制。

## 判断与取证

分别判断三个层次，并保存同一次尝试的证据：

| 层次 | 判断内容 |
| --- | --- |
| 传输 | curl 退出码、错误、是否收到完整响应；退出码为零不等于测试通过 |
| HTTP 契约 | 明确的状态码、必要响应头、字段类型和结构；预期 4xx/5xx 可以是正确行为 |
| 业务 | 字段值、权限隔离、状态变化、幂等或唯一性、文档允许观察的副作用；写入后按场景查询最终状态 |

失败证据包含脱敏请求与响应、时间、目标环境和版本、身份角色、实际操作、具体断言及清理结果。对“没有发生”的断言记录观察窗口、查询范围与结束条件；一次空响应不足以证明整个窗口没有副作用。

区分明确违背契约的产品失败、契约或用例缺口、脚本、环境和数据问题；无法归因时如实保留待分析失败。状态、重试身份、记录位置及报告生成沿用公共契约，不因某次重试通过覆盖前一次失败。

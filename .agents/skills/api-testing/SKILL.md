# 接口测试

依据明确的接口契约细化场景，通过 curl 向运行中的服务发送 HTTP 请求，检查响应和可观察业务结果。这里的接口指服务对外提供的 API；直接调用内部函数或以 Mock 替代被测服务的单元测试不属于本技能。支持直接请求和测试工作流分配的任务。

## 进入任务

直接收到接口测试请求时，先读取同级 [testing-workflow](../testing-workflow/SKILL.md)，确定临时验证或正式测试、任务阶段和资产位置，再继续本技能。由工作流转入时沿用已确定的模式、范围、来源、授权和计划，只补齐接口所需信息，不重新分流或循环调用入口。配套工作流缺失时先说明依赖缺口，不自行复制公共流程。

接口行为的预期来自用户指定或项目明确约定的在线文档、本地 OpenAPI／Swagger 或接口说明。记录来源和版本；本地契约足够时无需额外提供网址。文档缺失或冲突时指出受影响断言并请求补充，继续有可靠依据的独立部分。应用源码、测试源码、代码 diff 和当前响应不作为接口预期或根因定位依据；实际响应只记录观察事实。

## 按任务读取

- 生成或细化场景时，先按[契约缺口与用例映射](references/api-execution.md#契约缺口与用例映射)核对本轮文档是否足以构造请求和确定预期；执行请求或分析失败时继续读取该文件的对应方法。
- 生成或修订正式用例时，读取公共 [覆盖设计](../testing-workflow/references/test-case-design.md) 和 [格式契约](../testing-workflow/references/test-case-format.md)，采用 [接口用例模板](assets/templates/api-test-case.md)。模板是合成示例，替换为已核实项目事实后再使用；正文文件名须与一级标题一致，地图入口按实际资产根重算。
- 生成正式用例的挑战评审，按公共 [独立评审](../testing-workflow/references/coverage-challenge-review.md) 组织三个独立分工，专业交互评审重点检查鉴权、输入边界、状态转换、并发与幂等，断言评审核实副作用及可执行性；准入由工作流维护。
- 正式执行时读取公共 [计划与执行](../testing-workflow/references/planning-and-execution.md)、[结果契约](../testing-workflow/references/run-data-contract.md)；失败归因、BUG 或修复复验按 [报告与 BUG](../testing-workflow/references/reporting-and-bugs.md) 处理。

## 完成与交接

按当前模式交付接口场景、实际执行范围、逐项预期与结果、脱敏证据及未验证项。临时记录与正式报告使用公共工作流指定位置和格式；只有编写用例的任务交付到用例阶段，不把脚本存在称为已执行。向工作流返回场景结果与证据，由其汇总跨类型结论。

默认完成本次验证，按需编写数据处理和断言辅助脚本。用户要求持续回归、CI 或可重复执行脚本时，才建设相应长期自动化；已有授权和测试仓库选择直接沿用。

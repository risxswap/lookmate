# 预约管理

[[docs/testing/01-cases/01-api/00-接口测试用例|返回接口测试用例]]

## 用例

### API-BOOK-010｜两名员工争抢同一时段仅一人预约成功

用例编号：API-BOOK-010 ^case-api-book-010

优先级：P0
状态：草拟
关联需求：REQ-BOOK-002
关联接口：createBooking

#### 准备

- 本文为合成示例；进入可执行状态前，核实目标需求 REQ-BOOK-002、主 operationId、请求字段、冲突响应和查询契约。未匹配目标事实时保持草拟并记录缺口。
- 员工 alice 和 bob 各有独立认证会话，凭据通过安全引用提供；二者均有预约权限。
- 执行计划已准备本次专用、启用、容量至少为 2 的会议室，并允许创建、查询和取消本次隔离预约。
- 通过 listBookings 确认专用会议室在预约日期 10:00—11:00 的预约为 0 条，测试期间不供其他任务使用。
- 示例契约：createBooking 输入 roomId、date、startTime、endTime、topic 和 attendees；成功返回 201 及 id，时段冲突返回 409 及 code=BOOKING_CONFLICT；listBookings 可按会议室和时段查询；cancelBooking 可取消本次创建的预约。
- 执行器支持两个独立客户端等待同一释放屏障，保留调度及请求起止时间；不能满足时不以顺序提交代替本用例。

#### 数据

- 会议室编号：执行计划创建并核实的专用会议室 id。
- 预约日期：本次尝试开始时 Asia/Shanghai 时区的明天，确定后固定。
- 运行标识：本次尝试开始时生成并固定的 UUID。
- alice 主题：字符串 alice- 后拼接「运行标识」。
- bob 主题：字符串 bob- 后拼接「运行标识」。

#### 步骤

1. 竞争同一时段
   操作：alice 与 bob 各自通过 createBooking 提交一个请求，roomId=「会议室编号」、date=「预约日期」、startTime=10:00、endTime=11:00、attendees=2；topic 分别为「alice 主题」与「bob 主题」。
   并发：两个独立客户端在请求发送前就绪于同一屏障，同时释放；各发送一次且禁用客户端自动重试，汇合两个响应后继续。按计划中明确的最大调度偏差核实并保留记录；无法证明满足并发条件时记录阻塞。
   等待：两个请求均结束后汇合，最长时限采用计划中声明的请求超时；超时不得按冲突响应处理。
   检查：两个响应中恰有一个为 201，另一个为 409；不得预先指定 alice 或 bob 获胜。
   检查：201 响应包含非空 id；409 响应 code 等于 BOOKING_CONFLICT。
   保存为：成功预约编号 ← 本步唯一 201 响应的 id 字段
   保存为：成功员工 ← 本步唯一 201 响应对应请求的员工身份

2. 核实最终唯一性
   操作：通过 listBookings 查询「会议室编号」在「预约日期」10:00—11:00 的有效预约。
   检查：仅返回 1 条预约，id 等于「成功预约编号」，创建者等于「成功员工」，时段和人数与输入一致。
   检查：另一员工未在同一时段生成第二条预约。

#### 最终检查

- 保存屏障就绪与释放记录、两个脱敏请求和响应、起止时间及最终查询结果；仅有一成一败响应不能代替最终唯一性查询。
- 不确定胜者或响应未满足预期时，保留原始证据并停止依赖成功员工或成功预约编号的步骤，继续安全的只读核查与清理。

#### 清理

- 按「alice 主题」和「bob 主题」查询本次记录，核实创建者和专用会议室后通过 cancelBooking 取消，包含失败时意外创建的两条记录；不取消其他运行的记录。
- 再次查询专用会议室的本次时段，确认本次主题的有效预约为 0 条，记录清理失败。

# 后端验证

从项目 wrapper、构建配置和 CI 读取实际命令，使用项目的 Maven/Gradle 与测试设施；不默认安装另一工具链。新增检查器前验证 JDK/语法兼容性，P3C 仅覆盖部分规则。

| 变更 | 最小有意义证据 |
| --- | --- |
| Java 排版或格式工具配置 | 格式检查通过；新增检查需证明压缩注解与方法体的样例会失败、格式化后通过，并完成编译与已有测试 |
| 业务计算、空值、状态转换 | 成功和相关失败/边界的单元测试 |
| 查询、ORM、约束、分页 | 兼容真实数据库语义的集成测试与返回结果 |
| 多步写入 | 成功状态与中间失败后的独立数据库读取 |
| 竞争更新 | 多请求竞争后业务不变量、冲突结果 |
| API、认证与授权 | 请求/响应、非法输入、他人资源访问被拒绝 |
| 启动、配置或依赖 | 项目构建及隔离环境启动证据 |

mock 测试不能证明 SQL、事务代理或真实权限过滤器有效；替代数据库的语义差异需说明。修改测试前确认它断言业务结果而非复制实现，修复类任务尽量证明同一回归检查能捕获原故障。

最终沿用公共 [验证与交付](../../development-workflow/references/verification-and-delivery.md)，明确测试环境和未验证范围。

## 格式交付检查

有 Java 修改时，交付前必须运行项目的格式检查命令，记录命令、范围和结果；不能用编译成功或编辑器缩进设置代替。先按项目配置修正本轮涉及文件，再执行检查并审阅 diff。既有格式问题单独报告，不通过跳过检查或扩大自动格式化范围掩盖。

项目缺少可执行格式检查时，明确报告缺口；任务包含工具配置时，选用兼容实际 JDK 的格式器，锁定插件和引擎版本，覆盖生产与测试源码，并把只读检查接入常规构建或 CI。自动修复使用独立命令，检查失败不得自动改写源码。验证失败样例确实被拦截，再验证修复后的检查与既有测试。未获工具配置授权或工具不可用时如实标记格式检查未完成，仍需人工核对排版。

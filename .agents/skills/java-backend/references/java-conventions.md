# Java 规约

阿里来源与等级以 [规则映射](alibaba-rule-mapping.md) 为准；本页是执行摘要，超出映射的建议属于本套补充。

- A01–A03：按角色命名类、成员和常量；布尔 POJO 属性避免 is 前缀。修改已有 JSON 字段或 ORM 映射前检查消费者，不只重命名 Java 字段。
- A04–A05：语义常量集中在所属模块，避免万能常量类。新增 Java 代码默认四空格，具体排版与检查要求见下文。
- A06：保持 equals/hashCode 契约；进入哈希集合后的键避免改变参与相等判断的字段。按值语义审查自定义键。
- A07–A09：精确十进制从字符串或准确来源构造；数值等价用 compareTo，金额明确单位、scale 和舍入。存储策略见映射中的适配说明，禁止先经浮点运算再试图恢复精度。
- A10：POJO 可空性与数据库、接口契约一致；包装类型拆箱前处理 null，局部计算优先适当的基本类型。
- A14：捕获异常必须有恢复、转换或传播语义，保留原因，不用空 catch 或假成功掩盖失败。

本套补充：资源使用 try-with-resources；集合转换考虑重复键、null 和不可变集合的修改行为；区分空集合、未找到和访问失败。时间值明确日期/时刻及业务时区，测试时注入可控时钟。日志记录必要业务标识与原因，敏感值脱敏；toString 不自动输出凭据、个人数据或递归关联。

选择新语法、record、虚拟线程或新 API 前核对实际 JDK 与依赖支持。静态检查器只作为证据之一，不假定支持全部现代语法，也不把扫描通过当全部规则合规。

## 排版与可读性（本套补充）

- 类、方法和字段的声明注解各占一行，声明另起一行；参数和类型使用注解随对应类型排版。
- 非空方法和构造器的语句从下一行开始，结束大括号独占一行；即使只有一条 return 或委托调用也展开。空方法体按项目格式器处理。
- 每行放一条语句，字段逐项声明；控制流按层级换行缩进，长参数列表和调用链由项目格式器断行。成员方法之间留空行，方法内部按逻辑步骤分段。
- 使用项目锁定版本的格式器和配置，覆盖生产代码与测试代码；局部任务只格式化涉及文件，统一格式迁移单独明确范围，不夹带业务修改。
- Java 变更交付前必须执行格式检查，并阅读最终 diff，核对注解、方法体、控制流和逻辑分段的可读性。格式器通过不能替代这一步人工核对；检查命令、缺失工具的处理见 [后端验证](backend-verification.md)。

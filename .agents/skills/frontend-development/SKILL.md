# 前端开发

读取项目 `AGENTS.md`、README、构建配置、依赖与锁文件、同类界面及验证入口，分别确认产品场景、运行平台和技术实现。管理后台或消费者产品可以运行在 Web、小程序或客户端上，不能仅凭框架推断产品形态。缺少这些定义或与实现冲突时，按 [项目约定](../development-workflow/references/project-conventions.md) 先分析现状，再与用户确认并记录；不为局部修改替换工具链。

直接承担设计或开发任务时读取 [开发流程](../development-workflow/SKILL.md)，沿用已有阶段。被开发、诊断、审查或建模技能作为参考读取时，只提供当前所需规则，不重新启动流程。沿用已有词汇表、Issue / Spec 和 ADR，无对应 Spec 且规则明确的局部任务直接推进；有对应 Spec 的实施遵循公共 [实施计划与子 agent 执行](../development-workflow/references/implementation-planning.md) 规则。

## 按范围组织设计与实施

| 任务 | 工作范围 |
| --- | --- |
| 新产品界面或整体改版 | 明确用户任务与内容层级，确定视觉方向，形成全局规范，再按授权实施 |
| 现有产品新增页面 | 继承已有组件与设计规范，补充页面结构、关键状态和必要差异 |
| 局部样式、交互或功能修改 | 只读取相关页面、组件及规则，保留未涉及的设计与工具链 |
| 设计讨论或界面审查 | 提供方案、取舍或有依据的问题；记录沿用公共流程，不自动修改业务代码 |

涉及页面结构、视觉方向、改版或设计审查时读取 [界面设计](references/interface-design.md)。设计结论明确且实现已获授权时继续实施和验证，不逐阶段重复确认。用户只要求设计时，以可实施的方案及未决问题交付；未运行页面时不声称完成视觉验收。

## 围绕用户任务实施

先确认用户要完成的操作、涉及的页面与状态、成功和失败反馈，再选择本次相关的关注点；以下场景可组合，不是四套必走流程：

| 场景或平台 | 当前任务涉及时关注 |
| --- | --- |
| 管理后台 | 表单与数据表格、筛选和批量操作、权限展示、误操作恢复 |
| 面向消费者 | 核心操作路径、内容呈现、加载体验和操作反馈 |
| 小程序 | 具体平台及版本、页面与应用生命周期、授权能力、包体与发布限制 |
| 桌面或移动客户端 | 导航与窗口、设备能力、离线行为、平台交互及安装运行环境 |

平台 API、权限或发布要求不明确时查对应版本的官方资料；已有 Web/Vue 示例不能代替平台规则。不预建无实际用途的场景文档，专项内容出现独立流程后再考虑拆分。

## 按任务读取

- 组件边界、状态归属与生命周期：读 [组件与状态](references/components-and-state.md)。
- 字段、错误、认证或请求竞态：读 [API 与认证](references/api-and-auth.md)。
- 页面、表单、导航及辅助操作：读 [交互与可访问性](references/interaction-and-accessibility.md)。
- 项目使用 Vue，且任务涉及其组件、响应式或副作用机制：读 [Vue 实现参考](references/vue.md)。其他技术沿用项目规范和对应官方资料。
- 验收和交付：读 [前端验证](references/frontend-verification.md)，根据目标平台选择浏览器、开发者工具、模拟器或真机。

按用户行为完成加载、成功和相关失败路径，再验证实际结果；只加载本次所需参考。用户决定和项目约定优先于通用建议，未在目标平台验证的行为明确列为缺口。

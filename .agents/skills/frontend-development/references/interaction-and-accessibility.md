# 交互与可访问性

先确定任务所需的用户操作、反馈与业务结果，复用已有组件、设计 token 和页面布局。视觉改动按用户范围实施，不借机整体换肤或替换组件库。

列表区分初次加载、刷新、空结果和失败；表单区分输入错误、服务端拒绝、提交中与完成。失败后保留合理输入，危险操作提供与风险相称的确认；取消不能产生隐含提交。

导航检查返回、重入和平台支持的深链接是否保留需求规定的状态。Web 界面中，模态框打开后焦点可进入、键盘可关闭、关闭后焦点回到触发位置；按钮和输入使用语义元素及可访问名称，错误与字段关联，状态不只依赖颜色。

按目标平台检查适用窗口尺寸、屏幕方向或视口，长文本与空值不破坏布局。用户内容默认以文本渲染；确需富文本时使用项目可信的净化流程，不能直接将不可信内容送入 HTML 或平台富文本渲染接口。

非 Web 界面沿用平台的可访问名称、焦点和辅助操作机制，在支持的键盘、触控或辅助技术下验证相关路径。

完成标准是用户能完成目标操作并理解失败原因，不仅是截图看起来正确。

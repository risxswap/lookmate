# 组件与状态

沿用项目组件或界面单元的输入、事件和输出契约，明确谁拥有数据、谁可以修改。列表中的有状态条目使用稳定业务身份，避免位置变化导致状态错配。

区分服务端数据、派生值、页面临时输入与跨页面共享状态。派生值按所用框架的机制计算；共享状态需有明确作用域和生命周期，不因多个页面存在相似字段就建立全局存储。

监听器、订阅、定时器和请求在失效或生命周期结束时清理。平台后台切换、页面复用与销毁可能不同，依据实际生命周期处理。跨筛选和导航的数据竞争按 [API 与认证](api-and-auth.md) 处理。

保持既有组件与状态管理方式，只在真实复用或职责需要时提取公共逻辑。框架专属实现读取对应参考，业务概念不自动对应组件或全局状态。

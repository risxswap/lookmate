# 设计规范维护

用于新建或调整跨页面设计约定。先定位项目已有设计文档、组件库、主题和 token 定义，沿用现有位置与组织方式；局部改动不要求新建全局设计系统。

## 全局约定与页面差异

全局规范记录产品共用的视觉与交互决策；页面说明引用全局规范，只记录特殊布局、组件状态或平台差异。页面差异写明适用范围和理由，不能默默改变全局行为。多处反复出现的差异再评估是否提升为共用约定。

按实际需要记录：

- 语义颜色与主题用途，例如主要操作、警告、错误和背景层级。
- 字体层级、中文与字体回退策略、内容密度、间距和容器布局。
- 共用组件的使用场景、视觉层级及交互状态。
- 适用尺寸或平台下的布局变化、动效用途及减少动效时的表现。

这些是记录范围，不是每次必须填完的模板。代码中的 token、主题和组件定义作为实际实现值的来源；文档说明用途、取舍并链接对应代码，避免复制整份数值表。方案值尚未实现时标为提案，实施后更新引用与状态。

## 保存与变更

沿用目标项目文档约定。没有约定且确需独立全局规范时，可使用 `docs/01-项目总览/05-界面设计规范.md`；页面设计放在相应需求说明中，引用全局规范。只有实际内容才创建文件，不预建页面目录或空模板。

读取现有规范后增量更新，保留未涉及的决定。用户已确认的设计与新建议分别标注；记录方案不代表用户确认，也不代表已实施或已验证。明确要求不写文件时，在回复中提供方案。

变更共用 token 或组件时核对受影响页面，验证范围随影响扩大。交付前检查需求中的设计约定、文档引用与实现是否一致，说明尚未应用的页面或未验证的状态。

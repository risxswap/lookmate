# API、认证与异步状态

沿用项目网络访问方式、客户端和错误处理；响应类型依据真实契约，不编造字段或把网络错误伪装成空列表。接口变化读取公共 [契约协作](../../development-workflow/references/api-contract-collaboration.md)，核对 ID、金额、时间和空值；字符串大整数不能先转 number 再转回字符串。

区分传输失败、业务失败、取消和未登录。保留表单输入，提供与实际结果一致的反馈；只有服务端确认后才显示成功。重复提交按业务要求禁用或去重，但服务端仍负责写入一致性。

快速筛选、翻页和路由切换时，取消失效请求或使用递增请求标识，成功、错误和 finally 的状态更新都需属于当前请求。界面销毁或请求所属生命周期结束后不继续写入失效状态。测试刻意让旧请求晚于新请求返回。

权限展示与路由守卫用于交互，服务端才决定访问权限。Token/Cookie 策略沿用项目约定，不能把环境变量当秘密存储，不为联调改动后端认证协议。登录过期避免多个请求反复跳转或刷新死循环，按实际项目策略验证。

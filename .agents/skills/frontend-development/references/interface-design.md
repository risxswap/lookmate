# 界面设计

按任务范围完成以下相关环节。已有明确设计稿或局部调整直接进入适用环节，沿用技能入口与公共流程的授权和记录方式。

## 用户任务与内容

从需求确定目标用户、使用场景、主操作、信息优先级和成功条件，再组织页面区域、导航和操作顺序。管理后台关注扫描、比较和重复操作效率；面向消费者的页面结合内容阅读、发现或转化任务设计，具体取舍以当前需求为准。

使用用户提供的内容或有代表性的样本检验布局，包括长标题、中文、数值、空值及实际列表密度；样本标明用途，不把虚构指标、评价或品牌背书作为真实内容。状态和操作反馈沿用 [交互与可访问性](interaction-and-accessibility.md)。

本环节完成时，应能说明主操作在哪里、信息为何按此顺序呈现，以及本次涉及的关键状态。影响业务行为的未知项按公共需求流程处理，不用视觉选择替代业务决定。

## 视觉依据与方向

先检查项目现有页面、组件、设计 token、品牌资源及用户提供的参考。区分已确认约定、实际实现和待讨论建议；现有实现可说明现状，不能自动证明设计正确。参考页面或图片只有实际查看后才能描述其特征，无法访问时说明缺口。

方向明确时沿用；存在影响整体效果的选择时，比较少量候选，具体说明布局、信息密度、字体层级、配色、图片与动效的差异，以及它们如何服务用户任务。参考资料记录来源和采用的具体特征，不把参考网站的品牌、文案或素材默认为可直接复用。

用可观察的设计约定解释风格词：例如“紧凑”要落实为表格行高、信息分组和操作间距，“安静”要落实为强调色使用范围和动效用途。密度、视觉变化程度与动效强度可以分别调整，不因某个行业标签固定选择配色或布局。

本环节完成时，所选方向有明确依据，并有页面结构、参考图或可查看的关键区域草稿支撑。按需要选择线框、代码预览或图像工具；用户指定工具时遵循其要求，否则不强制生成概念图、联网找图或安装新工具。

## 全局规范与页面差异

跨页面共用的设计决策按 [设计规范维护](design-system.md) 记录。局部调整只补充现有需求或组件约定；已有全局规范时优先继承，页面说明只记录必要差异及理由。

进入实现前，明确受影响区域、复用组件、内容层级、适用窗口尺寸下的布局变化及关键状态。字体、间距、颜色、边框和动效的细节应足够让实现者作出一致选择；已由组件或 token 定义的值引用其来源。

## 实现后的设计检查

按 [前端验证](frontend-verification.md) 在目标平台检查受影响页面；Web 使用真实浏览器。先检查用户能否发现并完成主操作，再检查信息层级、对齐、留白、文字换行、内容密度和组件一致性。按本次范围检查窄屏、宽屏、长内容，以及涉及的主题和交互状态。

可访问性、平台限制和需求验收条件作为约束；视觉风格、阴影、圆角或动效强弱属于情境选择。检查可读性、焦点、状态辨识和减少动效偏好时，采用适用标准及平台依据，不把审美偏好包装成通用硬规则。

对照需求、已确认设计或项目规范记录具体问题，指出受影响页面或状态和修改理由；已获修复授权时修改并复查对应问题。截图用于核对呈现，操作结果用于核对行为，两者不能互相替代。缺少运行环境时可做静态审查，并明确视觉与交互仍未验证。
